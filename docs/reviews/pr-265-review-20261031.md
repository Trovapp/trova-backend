# PR #265 리뷰 (2026-10-31)

리뷰 시작 기준은 37da9ab이다. 정상 출력 수집, 인터럽트/시간초과/콜백 실패, 부모 선행 종료, 프로세스 탐색/종료 실패, 파일 보존과 제한 시간의 의미를 점검했다.

## 수정 사항

### 프로세스 탐색·종료 예외가 나머지 정리를 중단함

기존 종료 helper는 전체 로직을 하나의 try로 감싸 탐색 예외가 나면 부모 종료조차 시도하지 않았고, 한 자식의 종료 예외 뒤에는 다른 관찰 자식도 시도하지 않았다.

탐색·부모 종료·개별 하위 트리 탐색·개별 자식 종료를 나눠 실패를 기록하되 나머지 종료는 계속 시도하도록 수정했다. 실패가 하나라도 있으면 종료 확인 결과를 false로 유지해 작업/출력 파일 삭제나 정상 반환으로 넘어가지 않는다. 종료 요청을 보냈다는 사실만으로 성공으로 판단하지 않고 기존 제한 시간 내 종료 대기도 유지한다.

SecurityException을 주입한 테스트에서 탐색 거부 후 부모 종료 시도, 한 자식의 종료 거부 후 다른 자식 종료 시도를 확인했다. 이전 helper를 사용한 negative control에서는 두 검사 모두 실패했다. 실제 OS의 권한을 변경하거나 신호 거부 상태의 프로세스를 만든 것은 아니다.

### 보존 파일을 찾을 수 있도록 로그 보강

종료 미확인 로그에 workDir와 stdout/stderr의 경로를 함께 남긴다. 파일 내용이나 환경 변수의 키 값은 출력하지 않는다.

## 검증한 계약

- 정상/오류 시 소유 프로세스 종료 확인 → 출력 수집 → 임시 파일 정리 순서.
- 전체 종료 대기 예산 5초를 부모/관찰 자식이 공유. 탐색/종료 OS 호출 자체의 실행 시간을 하드 실시간으로 제한하는 보장은 아니다.
- 인터럽트 상태를 잠시 해제해 정리하고 원래/정리 중 인터럽트 플래그를 복원.
- stdout 파일 전환으로 EOF 대기 reader 스레드 제거. 큰 한국어 JSON과 기존 진행 이벤트 검증 유지.
- 종료 미확인 시 파일 보존. 실제 Python 정상/인터럽트/시간초과/콜백 실패 검사는 기존 테스트를 다시 실행한다.

## 보장하지 않는 범위

관찰 전에 분리된 프로세스·새 fork 레이스·JVM SIGKILL은 여전히 Java cleanup만으로 해결하지 않는다. 원자적 OS 프로세스 그룹 종료, 다른 Python runner들의 일괄 정리, 실제 OS 권한 오류·종료 거부 상태 주입은 수행하지 않았다. 종료 미확인 파일 삭제 억제는 helper의 실패 반환 검사 및 코드 검토 범위이며, OS가 종료를 거부하는 end-to-end 시나리오를 실행한 것은 아니다.
