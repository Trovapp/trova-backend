# #264 실제 프로세스 정리 검증

PipelineRunner의 부모 Python과 하위 Python을 실제로 띄워 인터럽트·시간초과·진행 콜백 실패 후 둘 다 종료되고 작업 폴더가 삭제되는지 검사했다. 인터럽트 플래그 보존과 예외 종류/원인도 확인한다.

추가로 부모가 먼저 정상 종료하고 관찰된 자식이 남아 stdout을 상속하는 경우, 자식을 정리한 뒤 JSON을 읽는 것을 확인한다. 131,072자 한국어 stdout도 파이프 막힘 없이 정상 수집한다. 기존 정상·실패·진행 이벤트 테스트도 유지한다.

프로세스 종료를 임시로 생략한 negative control에서 인터럽트 테스트의 실제 소유 프로세스 생존 검사가 실패했다. 테스트가 소유한 fixture는 테스트 finally에서 정리하며, 정상 구현을 복구한 뒤 통과했다. 외부 API·운영/8080 서버·Supabase는 사용하지 않았다.

관찰 전 분리된 프로세스까지 OS 프로세스 그룹처럼 원자적으로 관리하는 보장은 아니다. 강제 종료 후 5초 안에 소유한 프로세스 종료가 확인되지 않으면 파일을 보존하고 로그로 알린다. 실제 종료를 거부하는 프로세스/OS 권한 오류는 주입하지 않았으며 해당 보존 경로는 코드 검토 범위다. JVM 자체의 SIGKILL은 Java 정리 코드로 처리할 수 없다.

이 변경은 PipelineRunner에만 적용한다. 다른 Python runner들의 취소 수명주기는 추가 점검 대상이며, 기존 UTF-8 진행 로그 분할 디코딩 문제도 이번에 수정하지 않는다. 전체 Kafka/JVM 복구 검증(PR #263)은 별도 변경이다.

최종 검증: 이번 브랜치(main 005ac63 기반)의 ./gradlew build 935 tests 통과, 실패/오류/skip 0. PipelineRunner 기본 3개와 신규 프로세스 정리 5개 테스트를 포함한다. 다른 열린 PR의 전용 테스트까지 병합해 실행한 수치는 아니다. diff 검사 통과.
