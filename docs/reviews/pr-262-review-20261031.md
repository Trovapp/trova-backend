## 발견·수정

### 기존 통과 기준을 바꾸던 엄격 assertion

별도 strict assertion 때문에 기존 사례의 전체 통과 여부/종합 점수까지 달라졌다. 기존 두 assertion의 pass/score를 유지하고 strict는 결과 namedScores에만 추가하도록 분리했다. 이 promptfoo 버전은 weight=0이면 namedScores까지 0으로 만들어 단순 weight=0 처리는 사용하지 않는다.

동일 10개 출력을 echo provider로 재생해 모든 사례의 기존 success/score/recall/precision이 원본과 같음을 확인했다. 전체 3 passed·7 failed·실행 오류 0이며 strict metric도 정확하게 집계된다. 이때 CLI 종료 코드 100은 예상한 채점 실패 7건이다.

### 형식이 나쁜 사례가 오프라인 재채점 전체를 중단함

사례별 오류를 분리하고 totalCases/cases/unscorableCases와 complete/partial/no_valid_cases 상태를 명시했다. 유효 사례가 없으면 평균 null 및 종료 코드 2로 보고한다. assertion 실패(r.error)가 있더라도 유효한 예측 출력은 제외하지 않는다. Unicode 정규화가 같은 이름을 별칭 후보로 잘못 제시하지 않도록 공통 정규화를 사용한다. 기존 유효 10건의 strict 평균은 그대로 유지됐다.

### 정상 비장소 판정을 실행 오류로 처리

provider가 NOT_PLACE_CONTENT만 빈 예측으로 변환한다. 장소가 있는 정답에 빈 예측이면 recall로 감점한다. 401·속도 제한·소스/미디어 오류는 예외로 유지하고 빈 결과로 숨기지 않는다. 정답 CSV는 변경하지 않았다.
