# 보조 Python 실행기 수명주기 수정 (#284)

리뷰 요약·태깅·후보 선택·검증·일정 생성의 기존 구현은 인터럽트 시 부모/자식을 종료하지 않고 입력을 삭제했다. stdout reader도 부모 종료 이후 따로 살아 있을 수 있었다. 실제 Python 부모/자식을 띄운 기존 코드 검사 5개가 모두 실패했다.

공통 `JsonPythonProcessRunner`로 입력 작성·파일 출력·종료 확인을 묶었다. 기존 주 파이프라인의 검증된 종료 helper를 `OwnedProcessTerminator`로 추출해 함께 쓴다. 정상/오류/시간초과/인터럽트 모두 부모와 관찰 자식 종료를 확인한 뒤 파일을 읽고 소유 폴더를 정리한다. 인터럽트 플래그는 보존한다. 새로 만든 폴더만 소유하며 기존 폴더/파일은 덮거나 삭제하지 않는다. 종료 미확인이면 입력과 출력을 보존한다. 기본 2분/주 파이프라인 5분, 종료 예산 5초 및 기존 입력·파서·API 기록/재시도 정책은 유지했다.

## 검증

- `./gradlew build -q` 종료0: 1,010개 중1,007통과·실패/오류0·기존 opt-in3skip.
- 새 검사25개: 실행기별 인터럽트5/시간초과5/정상 입력·출력5/오류 종료5, 큰 한글·이모지 출력, 부모 조기 종료 후 자식, 종료 미확인 보존, 기존 폴더/파일 보존, API 기록 예외 경계. 큰 출력 검사는 정상 검사에 포함된다.
- 기존 주 파이프라인까지 포함한 집중 검사35개 통과.
- 내장 Kafka + 별도 Spring JVM + 파일 H2 + Python fixture 강제 종료/재수신 opt-in1개 추가 통과. 공통 helper 추출 후 기존 복구 경계를 재확인했다. 기존 원본은 유지하고 [이번 결과](../bench/results/auxiliary-process-recovery-20261101.json)를 별도 보관했다.
- [기존 코드 재현](auxiliary-process-negative-20261101.json), [검증 집계](auxiliary-process-validation-20261101.json), [운영 관찰](production-observation-284-20261101.md).
- 실제 외부 API 호출/운영 변경 없이 로컬 fixture로 검증했다. 종료 미확인 보존은 terminator false 주입이며 OS의 실제 신호 거부를 재현하지 않았다.

프로세스 그룹 원자성·관찰 전 분리/재부모화·JVM SIGKILL까지 보장하지 않는다(ADR0028). 이번 변경은 PR 준비 상태이며 운영에 배포하지 않았다. 큐 전달 성능과 REST/Spring AI/async/Kafka 비교의 새 측정으로 합산하지 않는다.
