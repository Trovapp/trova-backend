# 새 장소 대안 측정 진행 기록

사용자가 지금 진행하도록 지시한 뒤 매니저가 같은 JAR로 운영 서버를 재시작했다. 매니저 통보 기준 재시작18:09 KST, UP18:12, Prometheus30초 수집18:15~20:15. 메모리 기반 일일 장소 한도와 Prometheus 누계가 초기화됐으므로 앞선 공동 편집 구간과 카운터를 직접 이어 붙이지 않는다. Windows 작업자는 재시작·설정 변경을 하지 않았다.

18:15에 두 기기 화면을 확인했다. 실제 요청은 Google 계정5586 한 기기에서 순차 수행한다. 새 시험 여행 `V11-FRESH-533`에 장소를 검색해 하나만 추가하고, 조건 필터 없음으로 대안 찾기를 한 번 누른다. 결과 캡처 뒤 시험 여행의 장소만 제거해 다음 지역·분류를 준비한다. 기존 저장 목록·기존 여행은 수정하지 않는다.

장소 검색·추가는 측정 준비이며 대안 API 응답 시간에 포함하지 않는다. 새 원래 장소를 검색해 추가하는 과정에서 해당 원래 장소 자체는 카탈로그에 저장될 수 있다. 비교의 핵심인 대안 후보 저장·임베딩의 신규성은 매니저의 서버 로그로 따로 대조한다. 따라서 원래 장소명이 새롭다는 이유만으로 모든 후보가 미저장이라고 단정하지 않는다.

번호별 `fresh/NN/before.png`, `result.png`, `frame-*.png`, `timing.json`을 보관한다. 05번부터는 검색/결과 OCR도 보관한다. 같은 번호 폴더가 있으면 도구가 실행을 거절하며 자동 재시도하지 않는다. `followup_fresh_next.py`는 한 장소만 진행하고 OCR 상태·대상 이름·결과를 검증한다. 예상과 다른 화면에서는 중단한다.

화면 관측 시간은 호스트 입력부터 검색 버튼이 준비 상태로 돌아온 캡처까지다. ADB·화면 캡처 지연이 포함돼 HTTP 응답 시간과 다르다. 첫 대안 요청 시작은18:18:54.631 KST다. 실제 응답 평균·p95·SQL과 외부 호출 수는 측정 종료 후 재시작 이후 서버 구간으로 계산한다.

금지한 영상 분석 요청은 하지 않는다. 한도 오류가 보이면 경로를 멈추고, 외부 Google Places 전체2000회 상한 내에서 진행한다. 한 번에 한 요청, 각 장소별 한 번씩 총30건이 목표다.

25건 완료 뒤 26번 준비 검색(18:50:55 KST)에서 Google 테스트 계정의 일일 장소 호출 한도가 표시돼 중단했다. 매니저에게 물었고, 두 계정 모두 측정용 계정이므로 Kakao 5584로 남은 5건을 채우라는 명시적 승인을 받은 뒤 재개했다. Google 25건·Kakao 5건으로 계정이 나뉘며 개인화 조건이 완전히 동일하지 않다. Kakao용 별도 테스트 여행은 V11-FRESH-KAKAO-533이다. 한도 화면은 fresh-limit/daily-quota-26-preparation.png에 보관했다. 대안 요청을 실패 후 반복한 것은 없으며, 한도에 막힌 26번 장소 검색은 준비 단계였다.
