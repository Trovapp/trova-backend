## 무엇을 알게 됐나

이번 실행에서 가장 큰 구간은 초기 추출로 실행 시간의 약 67.4%다.
그 내부의 Gemini 수집·필터링 호출 기록은 4.397초 + 5.001초, Python 단계 로그는 약 9.4초다.
Java 추출 전체 11.25초와의 차이는 제목 조회·프로세스·진행/결과 DB 갱신 등도 포함하는 범위 차이로,
차이를 전부 DB나 네트워크 하나의 문제로 단정하지 않는다.

후보 선택+검증+저장은 약 3.360초다. 이전 job 125에서 보였던 11.844초의 후반 구간은
이번 입력에서는 비슷한 크기로 나타나지 않았다. 입력·장소 수·배포 후 첫 분석 조건이 다르므로
속도가 개선됐다는 전후 비교나 이전 원인의 확정 근거로 쓰지 않는다.

영상에 연결된 Gemini 호출 4건은 모두 성공, attempts=1, waited_ms=0.
지도 검색 호출 기록 8건도 성공이다. 병렬 검색이므로 호출 시간을 더해 단계 경과 시간으로 쓰지 않는다.
일정 초안 AI 기록 1건은 job_id가 없으므로 해당 시간대 관찰로만 남겼다.

WARN 1건은 지역 기반 추정 좌표가 같은 영상의 다른 장소 좌표와 겹쳐 폐기된 기록이다.
ERROR는 관찰 구간 0건이다. 이는 잘못된 좌표를 그대로 채택하지 않은 동작이지만,
최종 좌표 미확정 2곳의 정확도 문제는 성능 지연과 별도로 검토해야 한다.
