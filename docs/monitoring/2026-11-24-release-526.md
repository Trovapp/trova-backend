# 2026-11-24 JSON 오류 추적 헤더 운영 배포 (#526)

[서버 #526](https://github.com/Trovapp/trova-backend/pull/526)을 트레일러 없이 squash 머지한 `ce95a4ec258d9685e04b3e076a53e942c1afcf66`에서 JAR만 배포했다. 운영 Python 두 파일, Caddy, 기존 API 주소, 환경 설정은 변경하지 않았다. DB 확인은 읽기 전용 트랜잭션으로 실행하고 ROLLBACK했다.

## 머지 전 검증

최신 main `968e84e`에 #526의 세 파일만 합쳐 `./gradlew build --no-daemon --rerun-tasks --console=plain`을 실행했다. 전체 1,489건 중 1,482건 통과, 6건 건너뜀, 기존 실패 1건이었다. `ApiErrorContractTest` 16건은 모두 통과했으며 409의 `VERSION_CONFLICT`, `latest`, 헤더 한 개와 본문 `traceId` 일치를 포함한다. 운영에서는 쓰기로 409를 만들지 않았다.

기존 실패 1건(pgvector, SQL 기대 `[9,9,9]`·실제 `[7,7,7]`)은 #526 이전 main 원본에서도 별도 `--no-daemon` 실행으로 재현했다(4건 중 1건 실패). #525 배포 기록에도 같은 실패가 있다. 코디네이터가 기존 실패 예외 처리를 명시적으로 승인했으며 테스트 수정이나 제외는 하지 않았다. 따라서 전체 build 종료값은 1이고, 전체 통과로 기록하지 않는다.

첫 샌드박스 실행의 프로세스 관련 34건 실패는 권한 제한 없는 새 데몬에서 모두 해소됐다. 해당 5개 클래스 전체 38건(Interrupt 5, Lifecycle 20, LaunchPolicy 5, ProcessCleanup 5, PipelineRunner 3)이 실패 없이 통과했다. 샌드박스에서 시작된 데몬을 재사용하면 권한 문제가 남아 `--no-daemon`으로 분리했다. 머지 뒤 동일한 소스에서 `bootJar --no-daemon` 빌드는 성공했다.
