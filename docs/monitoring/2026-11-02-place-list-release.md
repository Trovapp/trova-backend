## 기능 검증

기존 테스트 계정으로 배포 전후 장소 목록을 각각 1회 조회했다. HTTP 200, 장소 42개,
전체 JSON 및 응답 SHA-256이 동일했다. 임시 토큰은 비공개 파일로 전달 후 삭제했고 실제 응답은 커밋하지 않았다.
[응답 비교 증거](2026-11-02-place-list-postflight.json)

iPhone 17 Pro / iOS 26.5 시뮬레이터의 기존 로그인 상태에서 앱을 재실행하고
홈 → 영상 기록 → 원주 영상의 장소·지도 → 준비된 일정 초안을 직접 열어 정상 표시를 확인했다.
계정·장소·영상·일정을 생성/삭제하지 않았다. 스크린샷은 계정 정보가 있어 로컬 임시 폴더에만 남겼다.

관찰 구간의 서버 전체 API 증가분은 16건(200 15건, 404 1건), 5xx 0건이었다.
404는 저장한 여행이 없는 기존 정상 분기였다. 클라이언트별 추적이 없어 전체 증가분을 시뮬레이터 단독 요청이라고
확정하지 않는다. Prometheus `up{job="trova-prod"}=1`, 배포 시작 이후 journal WARN/ERROR 0줄을 확인했다.
journal 시간은 서버 UTC 기준이며 배포 시작 epoch로 조회했다.
[시뮬레이터 계측 증거](2026-11-02-place-list-simulator-postflight.json)

마지막 확인에서도 진행 작업 0, 마지막 분석 job 127, 최근 1시간 Gemini 호출 0이었다.
테스트 전용 PostgreSQL 컨테이너와 볼륨은 제거했다. 운영 파일 백업은 보존한다.

## 운영 성능 개선율로 해석하지 않는 이유

테스트 계정 단일 HTTP 전체 시간은 배포 전 399.74ms → 재시작 후 1,202.72ms로 증가했다.
시뮬레이터 구간 장소 목록 4회 서버 처리 평균도 539.69ms로, 이전 관찰의 약 334ms보다 높았다.
느린 표본을 삭제하지 않았다. 재시작 직후·표본 수 부족·동일한 워밍업 조건 아님·다른 동시 요청 때문에
이번 운영 수치로 성능 향상이나 지속적인 성능 회귀를 확정할 수 없다. 원인을 재시작만으로 단정하지도 않는다.

이번에 확인한 것은 운영 **응답 동등성·화면 동작·오류 여부**다.
성능 개선 근거는 격리 PostgreSQL의 동일 조건 교대 비교(중앙값 49~52%, p95 34~47% 감소)로 한정한다.
인터넷·원격 DB를 포함한 운영의 장기 지연 변화는 별도 관찰이 필요하다.
