# Rust 부분 비교 구현 순서 (#309)

상태: **1~5단계 로컬 구현·검사 완료(#312, [로컬 결과](../../bench/rust-parts-pilot-local-20261104.md)), 6단계 이후 운영 실행 미착수**. 설계: [부분 비교 설계](../specs/2026-11-04-rust-pipeline-pilot.md).

1. 새 구현 작업/이슈/워크트리를 만들고 기준 `build_parts` 소스·운영 아키텍처/런타임을 고정한다. 제안의 코드 구현이 선택된 뒤 진행한다. 이번 분석은 과거12건 재계산과 설계만 완료했다.
2. 고정 입력24개와 누락/초과/형식 실패 입력을 만든다. 원본 파일과 골든 출력 해시, 후보/미디어 순서를 기록한다. 개인 자료·실제 키·DB·URL 다운로드는 쓰지 않는다.
3. Python 제어 CLI를 기존 함수에 연결한다. 네트워크/키 로드 경로에 들어가지 않는지 검사하고 실제 골든과 일치시킨다. 제어군 단독 A/A 측정기로 warmup/순서/캐시/프로세스 비용을 기록할 수 있게 만든다.
4. Rust release CLI를 같은 계약으로 구현한다. parts의 의미/순서/텍스트/base64/실패 처리를 비교한다. 이 단계에는 서버/대기열 어댑터를 붙이지 않는다.
5. 로컬24개 출력 호환성 검사와 스크립트 테스트를 통과시킨다. 예외·부분 출력·큰 입력·한글 경로·취소 시 자식 종료를 검사한다. 시간 결과는 운영 성능으로 표시하지 않는다.
6. 구체적 산출물/명령/운영 자원 사용 시간/제거 범위를 검토할 수 있게 준비한다. 사용자가 운영 실험을 선택한 뒤 유휴 서버의 별도 폴더/프로세스에서288개 관측을 직렬 실행한다. JAR/설정/운영 큐·실제 사용자 작업은 그대로 둔다. 무한 예약/자동 재실행을 만들지 않는다.
7. 모든 표본과 정확성 결과·평균/중앙값/짝 차이·wrapper와 process-tree 메모리를 기록한다. 기준 CLI와 실제 Python→Rust 보조 통합 비용을 구분한다. 좋은 결과만 고르거나 서로 다른 영상/대기열 경로를 언어 대조군으로 섞지 않는다.
8. 이익과 유지보수/빌드 비용을 사용자가 검토한다. 실제 채택/프로덕션 변경이 선택되면 기존 ADR 충돌 여부를 먼저 확인하고 새 결정/구현/평가·배포 계획을 별도 작성한다.

현재 전후 표: [비교 틀](../../bench/results/rust-pilot-comparison-template.json). Python/Rust 비교 준비 함수 시간과 Rust 결과는 아직 **null**이다. 역사적 전체 분석 시간을 새 준비 함수 실험의 전(before) 수치로 복사하지 않는다.

역사 자료의 JAR/Python 해시는 당시 기록 설명용이다. 미래 운영 실험에서는 최신 활성 상태·산출물·진행 작업을 읽어 새 기준을 고정하며, 과거 해시를 현재 운영의 기대값으로 재사용하거나 이전 예약 실험을 자동 재실행하지 않는다.
