# 격리 동시 조회 부하 측정 (#307)

운영 데이터/설정 없이 internal Docker network에 PostgreSQL, 실제 애플리케이션 JAR,
Prometheus를 실행한다. 앱 1 CPU/768 MiB, DB 1 CPU/512 MiB로 제한한다.
합성 사용자 160명에 각 장소 1,000개를 저장하고 GET /api/places를 호출한다.
IP 요청 제한은 테스트에서만 해제한다. 인증과 응답 내용 검사는 유지한다.

k6 VU 1→5→10→20→40→80→160, 각 45초(앞 15초 워밍업 제외), 요청 후 1초 대기.
실험 기준 p95 < 1초, 오류 < 1%. 최초 초과 지점을 확인하고 경계 두 단계를 반복,
마지막 1 VU 회복 확인. 오류율 5%/p95 5초 이상이면 추가 상승 중단.
Prometheus 2초 간격 원본, 컨테이너 cgroup CPU throttling, k6 요약을 보존한다.
운영 최대 사용자 수, 장시간 안정성, AI 분석 처리량으로 일반화하지 않는다.

## 후속: 인덱스 개선 A/B 검증

같은 JAR·데이터·컨테이너를 유지하고 인덱스 없음(A) → 있음(B) → 있음(B) → 없음(A)
순으로 20/40 VU를 반복한다. 각 단계 45초/15초 예열 제외 및 1초 think time을 유지한다.
시간 경과/JVM 예열 영향을 줄이기 위해 순서를 뒤집어 확인한다. 전후 실제 응답 본문도 비교한다.
Prometheus 연속 수집과 Grafana 별도 대시보드·캡처를 남긴다. 운영에는 아직 적용하지 않는다.
