# 재구성 접수 한도·동시 중복 방지 (#270)

- 기존 사용자별 장소 API 요청 한도를 새 재구성 생성 시도에도 적용한다. 기존 활성 작업 재사용, 소유권 없는 요청, 조건 오류는 차감하지 않는다.
- 기존 장소 API와 같이 요청 시도 단위 1회이며, 생성/큐 접수 실패도 환급하지 않는다. 실제 외부 요청 수의 전역 예산은 별도 문제다.
- 같은 여행의 활성 작업 조회→한도 확인→저장→비동기 접수를 고정 256개 잠금으로 직렬화한다. 다른 여행의 버킷 충돌은 가능하며 단일 JVM 보장이다.
- 한도 초과는 기존 429 예외 매핑을 사용한다. 큐 거절은 기존 행 삭제/503 처리 유지. 저장 실패는 작업자 호출 없이 전파하며 잠금 해제.
- 단위 동시성 검사, 컨트롤러 HTTP 429/재사용 검사, 전체 build 순으로 확인한다. 외부 API는 호출하지 않는다.
