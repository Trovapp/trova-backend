# PWA(설치형 웹앱) 배포 설계

- 날짜: 2026-10-12 · 이슈: 백엔드 #165, 앱 Trovapp/trova-app#7 · 결정 기록: [ADR 0013](../../adr/0013-pwa-before-app-store.md)
- 범위: 앱(Trovapp/trova-app, Expo) 웹 버전 + 백엔드(이 레포). 기존 웹 앱(trova-frontend)은 바꾸지 않는다.

## 왜
- 아이폰 앱 배포는 어떤 방식이든(TestFlight·App Store) 애플 개발자 계정(연 $99)이 필요하다. 비용 0원 원칙([ADR 0002](../../adr/0002-cost-zero-free-tiers.md))에서 지금 단계의 사용자 확보 경로가 막혀 있다.
- 아이폰은 웹에서 받은 앱 파일을 설치할 수 없고, 웹으로 할 수 있는 건 PWA("공유 → 홈 화면에 추가")뿐이다.
- 사용자 결정(2026-10-12): PWA로 먼저 출시, 바탕은 지금 앱(Expo)의 웹 버전, 아이폰 링크 넣기는 단축어 + 복사한 링크 감지, 처음엔 소개 → 설치 안내로 유도(유니플 방식, uniple.app).

## 전체 흐름
```
브라우저로 접속 ─► 소개 화면 ─► "시작하기" ─► 설치 안내(아이폰/안드로이드 탭, 그림)
                                                │
                     홈 화면 아이콘으로 실행(standalone) ◄─┘
                                │
                         로그인(구글·카카오) ─► 앱 화면(지금 앱과 같음)
```
- 아이폰 PWA는 Safari와 저장소가 따로라, 로그인은 설치한 뒤(홈 화면 앱 안에서) 한다. 설치 안내에도 "설치한 앱에서 다시 로그인"을 적는다.
- 컴퓨터 브라우저는 설치 없이 "웹에서 바로 쓰기"로 들어갈 수 있다.

## 1. 앱(Expo) 웹 버전
- `npx expo export --platform web`(output: single) → `dist/`. 2026-10-12 시험 빌드: 번들 3.1MB, 화면은 뜨고 첫 오류는 보안 저장소(웹에 없음) 하나.
- 웹에서 안 되는 부분은 같은 이름의 `.web.ts(x)` 파일로 바꾼다(앱 코드는 그대로).

| 부분 | 앱 | 웹 |
|---|---|---|
| 토큰 저장 | expo-secure-store | localStorage(+ CSP로 외부 스크립트 차단) |
| 로그인 | expo-web-browser + `mobile=true` 딥링크 | 같은 창 이동 `?client=web` → `/auth/callback/?code=` → 교환 |
| 공유 받기 | expo-share-intent | 안드로이드: `/share/?url=&text=`(Web Share Target), 공통: 복사한 링크 감지 |
| 지도 | WebView + 카카오맵 HTML | iframe(srcdoc)으로 같은 HTML. 카카오 개발자 콘솔에 웹 도메인 등록 필요 |
| 날짜 선택·햅틱 등 | 네이티브 | 웹 대체(input date, 진동 없음) — 구현 중 확인 |

## 2. PWA 껍데기 (앱처럼 보이게)
- `public/index.html`(expo customize)에 manifest, `apple-mobile-web-app-capable`, `apple-touch-icon`, `theme-color`, `viewport-fit=cover`.
- `manifest.json`: `display: standalone`(주소창 없는 전체 화면), 아이콘 192·512(앱 아이콘에서 생성), `share_target`(안드로이드 공유 목록).
- 서비스 워커: 설치 조건만 맞추고 캐시하지 않는다(네트워크 그대로) — 캐시가 업데이트를 막는 문제(Expo 문서 경고)를 피한다. 오프라인 지원은 하지 않는다.
- 화면 전환: 웹은 기본 전환 애니메이션이 없어 스택 화면에 짧은 밀기·페이드 전환을 넣는다(동작 줄이기 설정이면 끔).
- 설치 유도: 안드로이드 Chrome은 `beforeinstallprompt`로 "설치" 버튼, 아이폰은 그림 안내.

## 3. 소개·설치 안내 화면 (웹 전용, 브라우저로 열었을 때만)
- 소개: 한 줄 소개("릴스 하나 공유하면 여행 일정이 생겨요") → 실제 앱 화면 캡처 카드(앱 레포 `docs/screenshots`) → 사용 흐름 3단계 → "시작하기".
- 설치 안내: 아이폰/안드로이드 탭(기기 자동 선택), 단계마다 그림.
  - 아이폰: ① Safari로 열기 ② 아래 공유 버튼 ③ "홈 화면에 추가" ④ 추가한 아이콘으로 열고 로그인
  - 안드로이드: "설치" 버튼(가능하면) 또는 ⋮ → "홈 화면에 추가"
  - 인앱 브라우저(인스타·카카오톡·유튜브 등) 감지: "Safari(Chrome)에서 열어 주세요" + 주소 복사 버튼. 인앱 브라우저에서는 홈 화면 추가가 안 된다.
- 링크 넣는 방법 안내(그림): 안드로이드 공유 → Trova, 아이폰 단축어 설치 → 공유 → "Trova에 저장", 복사한 링크 붙여넣기.
- 그림은 실제 OS 화면이 아니라 단순화한 SVG 그림(OS 버전마다 화면이 달라 캡처는 금방 낡는다).

## 4. 링크 넣기
### 안드로이드 — 공유 목록
- manifest `share_target`(GET `/share/?url=&text=`). 받은 주소에서 인스타·유튜브 링크를 골라 지금 앱의 공유 처리(`POST /api/shares`)로 보낸다. 로그인 전이면 로그인 뒤 이어서.

### 아이폰 — 단축어 "Trova에 저장" + 공유 전용 키
- 단축어: 공유 목록에 표시, 입력은 URL·텍스트 → 백엔드 `POST /api/shares` (헤더 `X-Trova-Share-Key`) → "Trova에 보냈어요" 알림. PWA를 열 필요가 없다.
- 공유 전용 키(백엔드):
  - 사용자당 1개, `trv_sk_` + 무작위 32바이트. DB에는 SHA-256 해시만 저장, 원문은 발급 때 한 번만 보여준다.
  - 이 키로는 `POST /api/shares`만 된다(다른 API는 401). 재발급하면 이전 키는 바로 무효, 폐기 가능.
  - 키당 분당 10회(감으로 정함, 실측 아님) + 기존 하루 공유 한도(`QUOTA_SHARES_PER_DAY`)가 그대로 적용.
  - 마지막 사용 시각을 남겨 화면에 보여준다(이상한 사용을 사용자가 알아채게).
  - `GET /api/share-key`(있는지·발급·마지막 사용 시각), `POST /api/share-key`(발급·재발급, 원문 응답), `DELETE /api/share-key`.
- 단축어 배포: 단축어는 아이폰에서 만들어 iCloud 링크로 공유한다(서명된 파일이 필요해 서버에서 만들지 않는다). 설치할 때 "가져오기 질문"으로 키를 붙여 넣게 한다. 만드는 법은 앱 레포 문서에.

### 공통 — 복사한 링크 감지
- 웹에서 앱을 열거나 다시 볼 때 "복사한 링크 붙여넣기" 버튼을 보인다. 누르면 클립보드를 읽어(아이폰은 "붙여넣기" 확인이 뜬다) 인스타·유튜브 링크면 바로 저장. 자동으로 읽지 않는다(브라우저가 사용자 동작 없이는 막고, 몰래 읽지 않는 게 맞다).

## 5. 백엔드 — 웹 로그인
- PR②(#163)의 관리자 웹 로그인과 같은 방식: `/oauth2/authorization/{provider}?client=web` → 로그인 성공 → 1회용 코드(60초, 1회) → `<APP_WEB_APP_URL>/auth/callback/?code=` → `POST /api/auth/web-exchange` → 앱 토큰(앱과 같은 90일).
- 관리자 웹 코드와 섞이지 않게 코드에 용도(관리자 웹/웹앱)를 같이 저장하고, 교환 API가 용도를 확인한다.
- 로그인 뒤 서버 세션은 지운다(관리자 웹과 같음).
- CORS: 웹앱 주소는 쿠키 없이 `/api/**`에 연다. 쿠키를 싣는 기존 웹(frontendUrl) 설정과 출처별로 나눈다.
- 교환 IP당 분당 10회(관리자 교환과 같은 카운터 규칙).

## 6. 보안
- CSP: 관리자 웹처럼 빌드 뒤 인라인 스크립트 해시로 `_headers` 생성. 카카오맵 SDK(`dapi.kakao.com`·`t1.daumcdn.net`)는 지도 iframe 안에서만 쓰므로 iframe 쪽 출처만 연다(구현 중 확정).
- 토큰은 localStorage(앱 토큰 90일) — 외부 스크립트를 막는 CSP가 전제. 로그아웃하면 지운다.
- 공유 전용 키는 범위를 공유 저장 하나로 좁혀, 단축어에서 새도 피해가 "링크 저장"에 그친다.

## 하지 않는 것(이번)
- 웹 푸시 알림("일정 완성"): iOS 16.4+ 홈 화면 앱에서 되지만 구독 관리·발송 서버가 커서 다음 단계.
- 오프라인 사용, 기존 웹 앱(trova-frontend) 정리.

## 테스트
- 백엔드: 공유 키 발급·재발급(이전 키 무효)·폐기, 키로 `POST /api/shares`만 되고 다른 API 401, 해시만 저장, 키 횟수 제한 429, 마지막 사용 시각, 웹 교환(관리자 코드로는 실패·반대도), 웹앱 CORS(쿠키 없음).
- 앱: 웹 빌드·실행(헤드리스 Chrome, 휴대폰 폭), 브라우저/설치 모드 분기, 인앱 브라우저 감지, 공유 목록 주소 처리, 복사 링크 감지, 네이티브 앱 동작은 그대로(타입 검사).
