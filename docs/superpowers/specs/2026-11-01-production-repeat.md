## 사전 계획

- 현재 배포 JAR394ba700.../Python7개와Kafka설정을 고정한다. 예약 실행 중에는 서버 재시작·큐 전환·JAR/환경/스키마 변경을 하지 않는다. 이번 목적은 현재 구성의 반복 시간과 두 작업의 분리이며, 새로운 Kafka 대 async 인과 비교가 아니다.
- 공개 영상C(8vmpPuFwQ94) 하나를 준비1+측정6회, 총7공유한다. 새 표본의 중앙값/범위/각 실행을 함께 제시한다. 한 영상에 한정하며 과거 표본과 합치지 않는다. 한도20중 최소3건 예비를 남길 수 있어야 시작한다.
- 각 실행 뒤 소유 장소/자동초안을0600백업 후 정리하여 같은 영상의 자동초안 중복 생략이 다음 실행에 섞이지 않게 한다. job/API로그는 유지한다. 순차 실행·매 실행 전 유휴 확인, 운영 강제 장애/Google 수동 초안 호출 없음.
- 영상 분석: 접수 응답, 생성→분석 시작(시작 상태검사 포함), 생성→장소 저장, 작업별AI단계/시도/대기, 지오코딩 전체시간/단계시간 로그, 장소 이름과 좌표 수를 기록한다.
- 일정 생성: 분석 완료→초안 생성, 초안 생성→마지막 갱신, 작업 생성→마지막 갱신을 구분한다. 마지막 갱신은 전용 완료시각이 아니므로 READY상태의 대용값으로 표시한다. job연결없는Java로그는 시간대 기록으로만 사용하며 다른 초안이 겹치면 추가 접수를 중단한다. 자동초안은 코드상 영업시간 Google조회를 생략한다.
- 같은영상의 과거job수도 기록한다. AutoDraftService가 TripService.findExistingTripForVideo에서 같은 영상의 과거job마다 장소를 조회하므로 이력이 늘면 확인 비용도 늘 수 있다. 이를 Kafka/SpringAI만의 효과로 귀속하지 않는다. 실제SQL횟수/저장단계시간은 별도미계측이다.
- 무료공급자 실제 잔여량은 미확인. 새실행창 알려진시도+미계측행당3 추정이60이상이면 다음 접수를 중단한다. 서버가 진행 중인 한 작업의 외부 요청을 이 도구가 강제로 제한하는 것은 아니므로 이는 다음 접수 가드이며 wire 요청 상한이라고 부르지 않는다. 실패/관찰된 네트워크재시도/429가 있으면 그 결과를 보존하고 추가접수를 중단한다. API행=wire횟수로 주장하지 않는다.
