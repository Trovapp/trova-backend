# 공유하면 일정 초안 자동 생성 + 준비 알림 설계 (#136, #137)

## 배경과 목표

사용자가 말한 제품 방향(2026-10-07): 여행 릴스·쇼츠를 인스타·유튜브에 저장해 두고 다시 안 보는 데서 출발했다.
"인스타나 유튜브에 저장해 놓는게 아닌 트루바에 공유를 시켜서 트루바 백그라운드에서 자동으로 일정을 짜놓는거지".

지금은 공유 → 분석까지는 자동이지만, 일정 초안은 사용자가 "영상으로 일정 짜기"에서 기간과 영상을 직접 골라야 만들어진다.
이 작업은 **분석이 끝나면 그 영상으로 일정 초안을 자동으로 만들어 두고**, 준비되면 **알림**을 보낸다.

### 사용자 결정 (2026-10-07)
- 자동으로 만드는 것은 **일정 초안**까지. 여행은 사용자가 확인하고 승인해야 만들어진다(원치 않는 여행이 쌓이지 않게).
- 기간은 **영상 기준**: 영상 장소의 일차 구분 → 제목의 "N박 M일" → 당일치기.
- 순서: 1단계(자동 초안 + 홈 카드)를 먼저 배포하고, 2단계(푸시 알림)를 이어서 한다.

### 성공 기준
- 영상을 공유하고 앱을 닫았다가 다시 열면, 홈에 "일정이 준비됐어요" 카드가 있고 눌러서 여행으로 만들 수 있다.
- 같은 영상을 다시 분석해도 자동 초안이 중복으로 생기지 않는다.
- 초안 생성이 실패해도 영상 분석 결과는 그대로 쓸 수 있다.
- (2단계) 초안이 준비되면 알림이 오고, 누르면 그 초안 화면이 열린다.

## 1단계: 자동 초안 (#136)

### 백엔드

**AutoDraftService** (`service/AutoDraftService.java`, 새 클래스)
- `startFor(Long jobId)`: `PlaceExtractionService`가 `markDone(jobId)` 직후 부른다. 예외는 안에서 잡아 로그만 남긴다
  (분석 작업 상태에 영향 없음).
- 만들지 않는 경우(모두 로그 한 줄):
  - 설정 `app.auto-draft.enabled=false`
  - 저장된 장소가 0곳
  - 이 영상으로 이미 만든 여행이 있음(`TripService.findExistingTripForVideo`)
  - 같은 영상(VideoKey 기준)의 자동 초안이 이미 있음(상태 무관, 닫은 것 포함) — 재분석해도 다시 만들지 않는다
- 기간 메시지 만들기(`autoMessage`, 순수 함수로 분리해 테스트):
  1. 장소들의 `day_number` 최댓값이 2 이상이면 그 일수 → `"N-1박 N일"`
  2. 아니면 제목에서 `PlanRequestParser.parseDays`로 읽은 일수
  3. 둘 다 없으면 `"당일치기"`
  → 메시지가 정해진 표현이라 요청 해석은 CODE 경로로 끝난다(Gemini 호출 0).
- `TripDraft`를 `auto=true`로 저장한 뒤 `TripPlannerService.process(draftId)`(기존 비동기)를 부른다.
  실행기가 가득 차 거절되면(`TaskRejectedException`) 초안을 지우고 로그를 남긴다(다음 재분석 때 다시 시도 가능).

**데이터**
- `trip_drafts.auto_created` (boolean, 기본 false) — 자동으로 만든 초안 표시. `ddl-auto update`로 칸 추가.
- 닫기는 `dismissed_at` (timestamp, null 허용) — 닫은 초안은 목록에서 빠지지만 행은 남아 중복 생성 방지에 쓰인다.

**API**
- `GET /api/trip-drafts/auto` → 본인의 자동 초안 중 `dismissed_at`이 없고 상태가 PENDING·PROCESSING·READY인 것,
  최신순 최대 10개. 항목: `draftId, status, jobId, videoTitle, days, createdAt`.
- `POST /api/trip-drafts/{id}/dismiss` → 본인 것이 아니면 404, 성공 204. 승인된 초안은 409.
- 승인(`/approve`), 조건 바꿔 다시 짜기(앱이 새 초안 생성)는 기존 그대로.

**비용·한도**
- 공유 1건당 Gemini 약 1~2회 추가(초안 생성·수정). 무료 티어 안이며 키를 운영·로컬이 같이 쓰므로
  한도가 빠듯하면 `app.auto-draft.enabled=false`로 끈다.
- 여행 패스(BM, 미머지)의 이용 횟수에는 자동 초안을 세지 않는다 — BM 머지 시 이 규칙을 반영한다.

### 앱 (trova-app)
- **홈 맨 위 카드**: `GET /api/trip-drafts/auto` 결과가 있으면 "일정이 준비됐어요 · {영상 제목} {N일}".
  만드는 중이면 "일정을 짜고 있어요". 누르면 기존 `PlanTrip` 화면을 그 초안으로 연다(`draftId` 파라미터). 카드의 닫기는 dismiss.
- **영상 결과 화면(VideoGroupScreen)**: 만든 여행이 없고 그 영상의 자동 초안이 READY면 아래 버튼을 "준비된 일정 보기"로.
- **분석 중 화면**: 아래 안내에 "끝나면 일정도 짜 둘게요" 한 줄.

## 2단계: 준비 알림 (#137)

- 전송: Expo 푸시 서비스(무료, 유료 플랜 불필요) → APNs(무료). 서버는 `https://exp.host/--/api/v2/push/send`에 HTTP 요청.
  실패(네트워크·잘못된 토큰)는 로그만 남기고 초안에는 영향 없음. `DeviceNotRegistered`면 그 토큰을 지운다.
- 토큰: `push_tokens(id, user_id, token unique, platform, created_at)`.
  `POST /api/push-tokens {token, platform}`(같은 토큰이면 사용자만 갱신), `DELETE /api/push-tokens {token}`(로그아웃).
  회원 탈퇴 시 삭제 목록에 추가.
- 보내는 때: 자동 초안이 READY가 될 때 한 번. 제목 "일정이 준비됐어요", 본문 "{영상 제목} {N일} 일정을 확인해 보세요",
  데이터 `{draftId}`. FAILED·수동 초안은 보내지 않는다.
- 앱: `expo-notifications`. 처음 공유로 분석을 시작할 때 "일정이 준비되면 알려드릴까요?"를 보여 주고 허용하면 iOS 권한 요청 →
  토큰 등록. 알림을 누르면 `PlanTrip(draftId)`로 이동(앱이 꺼져 있었어도).
- 사용자 작업(계정·키): `eas init`으로 EAS 프로젝트 연결, 애플 개발자 계정의 APNs 키를 `eas credentials`로 등록.
- 개인정보처리방침: 수집 항목에 "푸시 알림 토큰(알림 허용 시)" 추가.

## 테스트와 확인
- 백엔드 단위: `autoMessage` 3가지 규칙(일차 구분, 제목, 당일).
- 백엔드 통합: 분석 완료 → 자동 초안 생성, 건너뛰기 4가지(설정 끔·장소 0·기존 여행·기존 자동 초안), 초안 생성 예외가
  분석 작업 상태를 바꾸지 않음, 목록·닫기의 본인 확인. 고치기 전 실패 확인.
- 2단계: 전송 클라이언트는 목으로(요청 형식·DeviceNotRegistered 시 토큰 삭제), READY 때만 한 번 보내는지.
- 시뮬레이터(로컬 서버 + 개발 DB): 공유 → 분석 → 홈 카드 → 초안 → 여행 → 장소 메모까지. 알림은 `xcrun simctl push`로
  표시와 눌렀을 때 이동만 확인하고, 실제 전송·도착은 사용자 작업 후 실기기에서 확인한다.

## 범위 밖
- 여러 영상을 묶어 자동으로 한 여행 만들기(지금은 영상 하나당 초안 하나).
- 출발 날짜 자동 추정(초안은 날짜 없이 만들고, 승인·여행 화면에서 정한다).
- 안드로이드 알림(FCM) — iOS 먼저.
