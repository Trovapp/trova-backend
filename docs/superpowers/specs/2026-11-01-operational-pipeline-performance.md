# 운영 기준 분석 경로 개선 (#296)

사용자가 쉬운 설명과 운영 기준 검증을 요청했다. 좋은 결과만 선택하지 않고 기존 측정에서Kafka가느린것과SpringAI속도우위미입증을명시한다.

- Kafka리스너의사전상태조회는서비스의잠금내시작상태검사와중복이다. 시작상태검사를한곳으로모아같은동기처리/ACK경계를유지한다.
- 시작트랜잭션이이미읽은createdAt을URL과함께전달해큐계측의재조회도없앤다. 구String메서드는호환용으로남긴다. 날짜정의/경로별계측/완료건skip정책은유지한다.
- 단위검사로이미있는시각의계측은DB조회0을확인하고, 실제Kafka/JVM검사로완료중복/재수신/offset을재확인한다.
- 운영에서동일영상수정전후각1회기능/시간확인(현재공유3건중2건). n1씩을속도개선입증으로부르지않는다. 강제운영장애/브로커전원중단은하지않는다.
- 관련네보완을검토·합쳐검증후운영확인한다. 저장/완료원자화(#292)와함께DB왕복감소가목표이나AI시간변동으로전체가느려질수도있다. 측정결과를그대로보고한다.
