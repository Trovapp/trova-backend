# 관리자 DB 조치와 감사 기록 원자성 (#271)

- 확인 토큰/사유 검사는 트랜잭션 밖에서 하고 별도 실행 서비스에서 핸들러의 DB 변경과 감사 기록을 REQUIRED 트랜잭션으로 묶는다.
- 조회/로그인용 기존 REQUIRES_NEW 감사 기록은 유지하고, 실행 감사는 MANDATORY 메서드를 따로 둔다.
- 재실행 작업 생성과 생성 감사는 함께 커밋한 뒤 ShareJobQueue.enqueue를 호출한다. 롤백이면 큐를 부르지 않는다.
- 커밋 후 큐 거절은 별도 새 트랜잭션에서 새 작업 삭제와 거절 감사 기록을 함께 남긴 뒤 기존 409를 반환한다. 원래 생성 기록은 남는다. DB-브로커 분산 원자성/프로세스 강제 종료 틈은 보장하지 않는다.
- 정지 목록 add/remove는 DB+감사 커밋 이후 적용한다. 감사 실패 시 DB/키/메모리 상태가 원래대로 남는지 검사한다.
- 실제 JPA/H2로 숨김/삭제/정지/정지풀기/재실행의 실패와 정상 커밋, 별도 스레드 큐에서 새 작업 가시성, 큐 거절 후 정리를 검증하고 전체 build한다.
