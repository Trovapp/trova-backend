# #261 같은 영상 작업의 동시 실행 방지

## 문제

Kafka ACK 대기 시간초과는 실제 전송 취소를 보장하지 않는다. async 폴백과 늦게 도착한 Kafka 메시지가 같은 작업을 실행할 수 있다. 단순 PROCESSING 제외는 재시작 복구를 막고, 현재 실행 중이라는 이유로 Kafka를 즉시 반환하면 선행 async가 끝나기 전에 오프셋이 확정될 수 있다.

## 현재 범위

단일 JVM의 PlaceExtractionService 진입에서 작업별로 기다린다. 고정 256개 잠금으로 보관량을 제한한다. 같은 버킷인 다른 작업도 직렬화될 수 있다. 작업 완료/실패/삭제를 DB에서 다시 확인한 뒤 실제 분석 여부를 정한다. PROCESSING이지만 분석 결과가 없는 작업은 새 프로세스에서 다시 처리할 수 있다.

영상 분석 전용 startAnalysis를 두고, 일정 생성에서 재사용하는 markProcessing은 바꾸지 않는다. 분석이 이미 끝난 뒤 일정 생성 중인 PROCESSING 작업도 다시 추출하지 않는다. 관리자의 재시도는 새 job을 생성하므로 새 작업은 허용된다.

## 검증

- async가 먼저인 경우와 Kafka가 먼저인 경우 모두 실제 리스너/서비스 진입을 사용해 한 번만 파이프라인·저장·자동 초안을 호출하는지 확인한다.
- 늦은 경로는 선행 실행이 끝나기 전에 반환하지 않아야 한다.
- 다른 작업은 독립 버킷에서 동시 처리한다.
- DB 통합 테스트로 중단된 PROCESSING 재시작, 완료/실패/삭제 건너뛰기, 일정 생성과의 호환성을 확인한다.

## 범위 밖

다중 JVM 간 분산 실행 차단, exactly-once 외부 API, 프로세스 중단 전 부분 저장의 중복 제거는 보장하지 않는다. 기존 Kafka 재전달은 at-least-once다. 운영 배포와 실제 프로세스 강제 종료 시험은 이번 단계에서 실행하지 않는다.
