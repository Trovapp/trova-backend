# 관리자 운영 대시보드 설계

- 날짜: 2026-10-11 · 이슈: #157 · 결정 기록: [ADR 0012](../../adr/0012-admin-dashboard-web.md)
- 범위: 백엔드(이 레포) + 웹(Trovapp/trova-frontend). 앱(trova-app)은 바꾸지 않는다.

## 왜
- 운영 상태를 보려면 지금은 운영 DB를 직접 조회하거나 devflow `ops-check`를 돌려야 한다. Gemini 무료 한도(하루 1,000회)를 로컬·운영이 함께 써서 2026-10-04에 운영까지 막힌 적이 있다.
- 사용자 요청(여행 삭제, 탈퇴 대신 처리, 실패한 분석 재실행)을 처리할 화면이 없다. 지금은 DB를 직접 고쳐야 한다.
- 사용자 결정(2026-10-10~11): 운영용, 지표 4종 전부, 웹 관리자 페이지(이용자가 늘면 앱보다 웹이 낫다), 계정 삭제 포함, AI 보조 포함.

## 단계
| 단계 | 내용 | 위험도 |
|---|---|---|
| 1 | 조회 대시보드 — 지표 4종, 웹 로그인, 서버 상태 기록, 배포 | 낮음(읽기만) |
| 2 | 관리자 조치 — 미리보기·사유·재확인·감사 기록 | 중간(DB 변경) |
| 3 | AI 보조 — 실패 원인 요약·하루 요약, opsflow 플러그인 연결 | 중간(무료 한도 사용) |

단계마다 구현 계획 → PR → 로컬 확인 → 운영 배포·확인을 따로 거친다. 1단계는 PR 3개(백엔드 집계, 백엔드 웹 로그인, 웹 화면)로 나눈다.

## 1단계 — 조회 대시보드

### 화면 (trova-frontend `/admin`)
- 맨 위 "지금 확인할 것" 카드 4개: 오늘 Gemini 사용량(1,000회 중), 최근 24시간 분석 실패 수, 5분 넘게 멈춘 작업 수, 최근 1시간 응답 시간 p90. 기준을 넘으면 빨간색(기준은 백엔드 설정, 처음 값은 감으로 정함: Gemini 800회, 실패 5건, 멈춤 1건, p90 1,000ms).
- 탭 4개, 기간 7/14/30일. 휴대폰 브라우저 폭에서도 보이게.

| 탭 | 그래프 | 출처 |
|---|---|---|
| AI 한도·호출 | 일별 호출 수(성공·실패), 토큰 합, 작업(영상) 1개당 호출 수, 기능(operation)별 호출 수 | `api_call_logs` |
| 분석 파이프라인 | 일별 요청 수·성공률, 처리 시간 중앙값·p90(분석이 처음 끝난 시각 `analysisFinishedAt` − createdAt — 분석 뒤 일정 생성이 같은 작업의 status·updatedAt을 다시 바꾸므로. 이 열이 생기기 전 작업은 updatedAt), 실패 이유별 건수, 지금 멈춘 작업 목록(최대 20개) | `processing_jobs`, 일정 초안 `trip_drafts`(기간 안 만든 수·실패 수·멈춘 초안 — PR③ 화면과 함께 추가, 요약 카드 "멈춘 작업"에도 합침) |
| 서버 상태 | 5분 단위 응답 시간 p50·p90, 요청 수, 5xx 수, 힙 사용량, DB 커넥션 사용 수 | `server_metric_snapshots`(새로) |
| 사용 데이터 | 일별 가입자·저장 장소·여행·자동 초안 수, 누적 사용자 수 | `users`, `saved_places`, `trips`, `trip_drafts` |

### 백엔드 API
- `GET /api/admin/dashboard/summary` — 위 카드 4개.
- `GET /api/admin/dashboard/{ai|pipeline|server|usage}?days=7|14|30` — 탭별. 탭을 나눈 이유: 한 탭 집계가 실패해도 나머지는 보이게.
- 권한: 기존 `AdminAccessService`(설정 `ADMIN_USERS`) — 관리자가 아니면 403. 로그인 안 했으면 401.
- 집계는 DB에서 날짜별 `group by`로 하고 일별 숫자만 응답한다(사용자가 늘어도 응답 크기 일정). 날짜는 서버 기본 시간대 기준 — 엔티티가 `LocalDateTime.now()`(서버 기본 시간대)로 저장하므로 같은 기준으로 묶는다. 운영은 `TZ=Asia/Seoul`이라 한국 시간과 같다(TZ가 빠지면 UTC로 9시간 밀림 — 배포 확인 항목).
- 실패 이유 분류: `errorMessage`에 이미 쓰는 코드(`SOURCE_RATE_LIMITED`, `GEMINI_DAILY_QUOTA_EXCEEDED` 등)로 묶고, 없으면 "기타". 분류 규칙은 한 클래스(`FailureReason`)에 모은다.
- 새 코드는 `admin` 기능 패키지(`controller`·`service`는 기존 규칙대로, 집계는 `admin` 패키지 안 Service로 분리 — 외부 연동 없음).

### 서버 상태 기록 (새 테이블)
- `server_metric_snapshots`: 5분마다 한 줄 — 측정 시각, 요청 수, 응답 시간 p50·p90(ms), 5xx 수, 힙 사용(MB), DB 커넥션 사용 수.
- 값은 이미 있는 Micrometer 지표(`http.server.requests`, `jvm.memory.used`, `hikaricp.connections.active`)에서 5분 사이 증가분으로 계산한다. Prometheus·Grafana는 운영 서버에 띄우지 않는다(E2.1.Micro 남은 메모리 약 300MB).
- 저장이 실패한 구간의 표본은 버리지 않고 다음 줄에 합친다 — 그래프에서 빈 칸 바로 뒤 줄은 두 구간 값이라 요청 수·5xx가 평소보다 크게 보인다.
- 30일 지난 줄은 하루 한 번 지운다. 하루 288줄이라 Supabase 무료 용량(500MB)에 부담 없음.
- 로컬 서버와 운영 서버가 같은 DB를 쓰는 환경이 있으므로 `source`(설정 `app.instance-name`, 예: prod/local) 칸을 두고 대시보드는 prod만 보여준다.

### 웹 로그인 (1회용 교환 코드)
- 지금 로그인 성공 처리(`OAuth2LoginSuccessHandler`)는 앱(`MobileLoginFlagFilter`가 세션에 남기는 `MOBILE_LOGIN`)에만 토큰을 주고, 그 밖에는 `app.frontend-url`로 토큰 없이 보낸다. 웹용 `WEB_LOGIN` 표시를 같은 필터 방식으로 추가한다.
- 흐름: 웹 → `/oauth2/authorization/{provider}?client=web` → 로그인 성공 → `https://<관리자 웹>/auth/callback?code=<1회용 코드>`로 이동 → 웹이 `POST /api/auth/exchange {code}` → JWT.
- 코드: 무작위 32바이트, 60초, 한 번만 쓸 수 있음. 교환 결과는 관리자 웹 전용 1시간 토큰(아래 "보안")(서버 메모리 저장 — 서버 1대라 충분, 재시작하면 사라져 다시 로그인하면 됨). 토큰을 주소창에 넣지 않아 브라우저 기록·서버 로그에 남지 않는다.
- 돌아갈 주소는 설정 `app.admin-web-url` 하나만 허용한다. CORS도 그 주소만 열고, 이미 열린 주소는 그대로 둔다.
- 웹은 JWT를 메모리(+ 탭을 닫으면 사라지는 sessionStorage)에만 둔다. 관리자 아니면 화면 대신 "권한 없음".

### 보안 (#159 보강)
데이터는 서버가 지킨다 — 웹 파일은 공개돼도 데이터가 없고, 모든 데이터는 `/api/admin/*`에서 요청마다 관리자 명단을 확인한 뒤에만 나간다. 그 위에 아래를 더한다.

| 항목 | 내용 | 단계 |
|---|---|---|
| 관리자 웹 전용 토큰 | 교환 코드로 받는 JWT는 유효 **1시간**, 클레임 `aud=admin-web`. 앱 토큰(`JwtService` 기본 90일)과 섞이지 않게, `/api/admin/*`는 `aud=admin-web` 토큰만 받는다(앱 토큰으로는 403). 만료되면 다시 로그인 | 1(PR②) |
| 위험 조치 재인증 | 삭제·재실행 등 2단계 조치는 토큰 발급(로그인) 후 10분 안일 때만 실행. 지나면 다시 로그인 안내 | 2 |
| Cloudflare Access | 관리자 웹(`*.pages.dev`) 앞에 이메일 1회용 코드 문을 둔다(무료 플랜 50명까지, 약관 확인 후). 서버 확인과 합쳐 두 겹 | 1(PR③) |
| 요청 횟수 제한 | `POST /api/auth/exchange` IP당 분당 10회, `/api/admin/*` 관리자당 분당 120회(감으로 정함, 실측 아님). 넘으면 429. 서버 1대라 메모리 카운터로 충분 | 1(PR②) |
| 관리자 로그인 기록 | 관리자 웹 로그인 성공·실패(관리자 아님)를 감사 기록에 남김 — 내부 번호만, 개인정보 없음 | 1(PR②) |
| 전수 권한 테스트 | 등록된 모든 `/api/admin/**` 매핑을 찾아, 비로그인 401·관리자 아님 403·앱 토큰 403인지 테스트가 자동으로 확인. 새 관리자 API가 권한 확인을 빠뜨리면 테스트가 실패 | 1(PR①부터, PR②에서 앱 토큰 항목 추가) |
| 웹 보안 헤더 | 외부 스크립트 없음, CSP `script-src 'self'`, `frame-ancestors 'none'`, Referrer-Policy `no-referrer` (Cloudflare Pages `_headers`) | 1(PR③) |

### 배포
- 웹: Next.js 정적 내보내기(`output: "export"`) → Cloudflare Pages(무료, `*.pages.dev`, 무료 플랜 빌드 월 500회 — [공식 한도](https://developers.cloudflare.com/pages/platform/limits/)). 상업적 사용을 막는 조항은 2026-10-11 검색에서 찾지 못했다 — 3번째 PR(배포) 전에 약관을 다시 확인한다. Vercel 무료(Hobby) 플랜은 개인·비상업 용도만 허용이라 쓰지 않는다(여행 패스 수익 모델이 있음, [Vercel 문서](https://vercel.com/docs/plans/hobby)).
- 그래프: recharts(MIT) 버전 고정.
- 운영 설정: `ADMIN_USERS`에 운영 관리자 계정(카카오), `APP_ADMIN_WEB_URL`, `APP_INSTANCE_NAME=prod`.

## 2단계 — 관리자 조치

| 조치 | 방식 | 재사용 |
|---|---|---|
| 여행 삭제 | 사용자 요청 시 그 사용자의 여행 하나를 연결 데이터까지 삭제 | `TripService.deleteTrip` |
| 계정 삭제 | 탈퇴 요청을 대신 처리 — 회원과 참조 데이터 전부 즉시 파기(개인정보처리방침 2항) | `UserAccountService.withdraw` |
| 실패한 분석 다시 실행 | 일시 오류(429 등)로 실패한 작업만, Gemini 오늘 사용량 확인 후 같은 영상 링크로 새 처리 작업을 만든다(기존 작업은 그대로 두고 감사 기록에 연결) | 링크 제출 처리(`SharesController` → 비동기 파이프라인) — 지금은 재시도 API가 없다(`retryCount` 칸만 있음) |
| 멈춘 작업 정리 | 5분 넘게 PROCESSING인 작업을 FAILED로, 이유 기록 | `OrphanedJobRecoveryService`와 같은 규칙 |
| 자동 초안 숨기기 | 잘못 만들어진 초안 하나를 홈에서 숨김 | 초안 닫기(`POST /api/trip-drafts/{id}/dismiss`) — 초안 삭제 API는 없다 |

안전장치(모든 조치 공통):
1. 미리보기 — `POST /api/admin/actions/{조치}/preview`가 영향 범위(예: 여행 1·일차 3·장소 12)를 돌려준다. 실행은 미리보기에서 받은 확인 토큰(5분, 1회)이 있어야 한다.
2. 사유 필수, 삭제는 대상 이름(여행 이름 또는 "계정 삭제")을 다시 입력해야 실행.
3. 감사 기록 `admin_action_logs` — 시각, 관리자(내부 번호), 조치, 대상(내부 번호), 사유, 결과(영향 건수). 앱에서 수정·삭제하는 경로를 만들지 않는다. **개인정보를 남기지 않는다**: 로그인 ID·닉네임·이메일 같은 값은 저장하지 않는다(계정 삭제 후에도 남는 기록이므로).
4. 관리자 계정 자신과 다른 관리자 계정은 이 화면에서 삭제할 수 없다.
5. 같은 확인 토큰으로 두 번 실행되지 않는다.

사용자 찾기: 내부 번호, 또는 사용자가 알려준 영상 링크·여행 이름으로 검색(닉네임 일부 검색은 관리자 화면 안에서만, 결과 최대 20개).

## 3단계 — AI 보조

비용 원칙([ADR 0002](../../adr/0002-cost-zero-free-tiers.md)): 서버에 유료 AI API를 넣지 않는다.

- 서버 안(Gemini 무료 한도):
  - 실패 원인 요약 — 규칙(`FailureReason`)으로 분류되지 않는 실패만 Gemini에 물어 한 줄 요약 + 다시 실행할지 제안. 결과는 작업에 캐시해 같은 실패를 두 번 묻지 않는다.
  - 하루 운영 요약 — 매일 아침 어제 지표를 3줄 요약, 이상한 점 표시(규칙으로 먼저 감지하고 문장만 AI).
  - 관리자 AI 호출에는 하루 상한(설정, 처음 50회)을 따로 두고, 서비스 몫이 줄어들 때(오늘 800회 이상)는 부르지 않는다. 호출은 `api_call_logs`에 `operation=admin-*`로 남는다.
- 로컬(Claude Code, 비용 0원): 새 플러그인 **opsflow**(taeng-marketplace).
  - 관리자 화면의 "Claude Code로 조사" 버튼이 `/opsflow:investigate job <번호>` 같은 명령을 복사해 준다.
  - opsflow는 관리자 API로 작업 정보를 읽기 전용으로 가져와 → 새 워크트리에서 같은 입력으로 재현 → 실패하는 테스트 → 원인·수정 제안(근거 `경로:줄`) → 사용자 승인 후 수정·PR → reviewflow 리뷰.
  - 운영 DB를 직접 읽지 않고 관리자 API만 쓴다(관리자 토큰은 로컬 파일, 레포 밖).
  - 플러그인 설계는 3단계 시작 때 taeng-marketplace에 따로 쓴다.

## 테스트
- 백엔드: 관리자 아님 403·비로그인 401(전수 권한 테스트로 모든 `/api/admin/**`), 앱 토큰으로 관리자 API 403, 관리자 웹 토큰 1시간 만료, 교환·관리자 API 횟수 제한 429, 날짜별 집계 값(한국 시간 경계 포함), 실패 이유 분류, 스냅샷 계산(증가분)·30일 정리, 교환 코드(재사용·만료·잘못된 코드 거부), 허용 안 된 돌아갈 주소 거부, CORS.
- 2단계: 미리보기 없이 실행 거부, 재실행이 새 작업을 만들고 기존 작업은 그대로, 확인 토큰 재사용 거부, 관리자 계정 삭제 거부, 감사 기록에 개인정보 없음, 계정 삭제 후 참조 데이터 0건.
- 웹: 관리자 아님 화면, 탭별 오류가 다른 탭에 번지지 않음.
- 끝나면 로컬(개발 DB)에서 확인 → 운영 배포 → 운영 데이터로 확인(실행 환경을 기록에 구분).

## 하지 않는 것
- 화면에서 SQL을 직접 실행하는 기능.
- 앱 안의 관리자 화면.
- 운영 서버에 Prometheus·Grafana.
- 서버에서 유료 AI API(Claude API 등) 호출.
