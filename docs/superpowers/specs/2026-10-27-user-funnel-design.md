# 관리자 사용자 퍼널·기능 사용 지표 설계

- 날짜: 2026-10-27 · 이슈: #237 · 관련: 관리자 대시보드 설계(`2026-10-11-admin-dashboard-design.md`), ADR 0012
- 범위: 백엔드(이 레포) API 1개 + 관리자 웹(Trovapp/trova-frontend `admin-web/`) 탭 1개. 앱(trova-app)은 바꾸지 않는다.

## 왜
- 사용자: "사용자가 어떤걸 쓰는지 Amplitude 퍼널 이런거 해야하지 않나? 영상을 얼마나 저장하는지 대안추천을 하는지 등등", "1번부터 진행해줘"(2026-10-27).
- 1번 = 분석 도구를 붙이기 전에 운영 DB에 이미 있는 기록으로 퍼널을 먼저 본다. 외부 서비스·앱 새 빌드·개인정보처리방침 변경이 없고(비용 0, ADR 0002), 지금은 테스터가 20명 안팎이라 사람별로 직접 보는 편이 정확하다.
- 지금 관리자 "사용량" 탭은 날짜별 건수(가입·저장 장소·여행·자동 초안)만 있어 "몇 명이 어디까지 갔나", "대안 추천을 누가 쓰나"를 알 수 없다.

## API
`GET /api/admin/dashboard/funnel?days=7|14|30|0` — `0`은 전체 기간. 권한·요청 제한은 기존 `/api/admin/**`와 같다(`AdminGuard`).

### 1. 퍼널 (사람 수)
대상: 기간 안에 가입한 사용자(전체 기간이면 모든 사용자). **관리자 계정(`app.admin` 설정)은 뺀다.** 단계마다 "지금까지 한 번이라도 했나"로 센다.

| 단계 | 기준 |
|---|---|
| 가입 | `users` |
| 영상 공유 | `processing_jobs` 1건 이상 |
| 장소 받음 | `saved_places` 1건 이상(분석이 장소를 하나라도 찾음) |
| 여행 만듦 | `trips` 1건 이상 |
| 여행 다듬음 | `user_preference_signals`의 `ALTERNATIVE_REPLACED`·`GAP_INSERTED`·`CHAT_LIKED` 1건 이상 |

단계마다 사람 수와 앞 단계 대비 비율. 덧붙여 "가입 → 첫 영상 공유" 걸린 시간 중앙값(`Percentiles.of`).

### 2. 기능별 사용 (기간 안, 관리자 제외 전체 사용자)
| 기능 | 출처 | 보여 줄 것 |
|---|---|---|
| 영상 공유 | `processing_jobs` | 쓴 사람 수, 건수, 성공(DONE) 비율 |
| 저장된 장소 | `saved_places` | 사람 수, 건수 |
| 찜 | `bookmarks` | 사람 수, 건수 |
| 일정 초안 | `trip_drafts` | 사람 수, 건수, 승인(APPROVED) 수, 자동 생성/직접 요청 구분 |
| 여행 만들기 | `trips` | 사람 수, 건수 |
| 대안으로 바꾸기 | 신호 `ALTERNATIVE_REPLACED` | 사람 수, 건수 |
| 빈 시간 채우기 | 신호 `GAP_INSERTED` | 사람 수, 건수 |
| 비서 후보 좋아요 | 신호 `CHAT_LIKED` | 사람 수, 건수 |
| 날씨 다시 짜기 | `trip_replan_jobs` | 사람 수, 건수 |

### 3. 사용자별 표 (최대 100명, 마지막 활동 순)
닉네임, 가입일, 마지막 활동(위 표들의 `created_at` 중 가장 최근), 영상 수, 여행 수, 다듬기 수, 도달한 퍼널 단계. 관리자 "사용자" 탭과 같은 사용자 id로 이어 볼 수 있게 id도 준다.

## 구현 메모
- 집계는 `admin` 패키지 `FunnelDashboardService` + 쿼리 한 곳. 사람별 존재 여부는 `select distinct user.id`로 DB에서 묶고, 사용자 수가 적어도 행 수에 비례해 메모리가 늘지 않게 한다.
- `DashboardPeriod`는 7·14·30만 받으므로, 이 API만 `0`(전체)을 따로 처리한다(기존 탭 동작은 그대로).
- 관리자 계정 판별은 기존 관리자 설정 값을 재사용한다(새 설정 없음).

## 화면 (admin-web)
- 새 탭 "사용자 흐름": 위에 퍼널 막대(단계별 사람 수·비율), 가운데 기능별 사용 표, 아래 사용자별 표. 기간 선택은 다른 탭과 같은 자리에 "전체"만 더한다.
- 휴대폰 폭: 기존 탭처럼 표를 감싼 칸에서만 가로로 넘긴다. 열이 많은 사용자별 표는 줄바꿈을 막아 글자가 한 자씩 끊기지 않게 한다(`DataTable nowrap`).

## 이걸로 알 수 없는 것 (다음 단계 후보)
- 화면을 열었지만 쓰지 않고 닫은 경우(대안 시트를 열고 교체 안 함, 온보딩 이탈), 앱을 열기만 한 재방문.
- 필요해지면 PostHog(무료 월 100만 이벤트) 같은 도구로 이벤트 몇 개만 보낸다 — 그때 ADR과 개인정보처리방침 4항을 함께 바꾼다.

## 확인
- 테스트: 퍼널 단계 계산(관리자 제외, 기간 경계), 기능별 집계, 권한(관리자 토큰 아니면 403 — 기존 전수 권한 테스트에 자동 포함).
- 로컬(개발 DB) 값 확인 → 운영 배포 후 운영 값 확인. 기록에 로컬/운영을 나눠 적는다.
