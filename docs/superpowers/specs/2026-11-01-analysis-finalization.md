# 분석 결과 원자 저장 (#292)

현 구조는 savePlace별 트랜잭션과 markAnalysisDone이 분리되어 있어 중간 종료 후 PROCESSING 재수신 시 기존 부분 결과에 추가 저장할 수 있다. 로컬 H2에서 구 방식의 부분 저장 잔류를 재현하고, 분석 결과 교체와 완료 상태를 하나의 트랜잭션으로 묶는다.

- 외부 API·지오코딩은 트랜잭션 밖에서 완료한다.
- PROCESSING이며 analysisStatus가 없는 작업만 완료한다. 완료·실패·일정 작업의 결과는 덮지 않는다.
- 새 결과 전체와 DONE을 함께 커밋한다. 이전 버전의 미완료 부분 결과도 같은 트랜잭션에서 교체한다. 실패하면 기존 부분 결과/작업 상태를 유지한다.
- 단일 JVM 잠금·큐 ACK·재시도/한도 정책은 유지한다. 다중 JVM 선점/외부 호출 exactly-once는 보장하지 않는다.
- H2 실제 트랜잭션 검사: 부분 결과 교체·두 번째 행 실패 롤백·완료 중복 호출·실패 상태 보존·입력 불일치. 기존 실제 Kafka/JVM 복구 검사도 명시 실행한다.
