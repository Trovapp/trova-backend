# 공통 규칙 (모든 Codex 작업)

각 지시문은 이 파일을 먼저 읽으라고 시작한다. 지시문과 이 파일이 다르면 지시문이 우선한다.

## 하지 말 것

- `.env`로 시작하는 파일, `pipeline-test/.env`, 운영 로그·사용자 데이터 파일을 열지 않는다.
- 서버 실행(`bootRun`), 네트워크 호출, Gemini·카카오·Google 등 외부 API 호출, 운영 서버 접속을 하지 않는다.
- `git commit`, `git push`, 브랜치 변경, PR 생성을 하지 않는다. 커밋과 PR은 대장이 한다.
- 지시문의 "건드릴 파일" 밖은 고치지 않는다. 꼭 필요해 보이면 고치지 말고 보고에 적는다.
- 지나가다 본 다른 문제는 고치지 않고 보고의 "따로 볼 것"에 적는다.
- 새 의존성·플러그인을 추가하지 않는다(`build.gradle` 수정 금지).

## 코드 규칙 (CLAUDE.md, ADR 0009)

- 들여쓰기 4칸, 생성자 주입, Lombok 쓰지 않음, 요청·응답은 `record`.
- 새 코드에서 와일드카드 import(`*`)와 `var`를 쓰지 않는다.
- 테스트 이름은 한글 문장(`void 승인하면_...()`).
- 파일 전체를 다시 포맷하지 않는다. 바꾼 줄만 바뀌어야 한다.
- 기존 ADR(`docs/adr/`)과 부딪히는 변경이 필요해 보이면 하지 말고 보고에 적는다.

## 검증

- 코드 작업은 끝에 `./gradlew build`를 돌린다. 샌드박스 때문에 실행이 막히면 우회하지 말고 "빌드를 돌리지 못함"과 오류 첫 줄을 보고한다. 대장이 다시 돌린다.
- 테스트는 테스트 DB(H2, `src/test/resources/application.yml`)만 쓴다.

## 보고 형식 (마지막 메시지, 한국어)

1. 바꾼 파일 목록과 파일마다 한 줄 설명
2. 실행한 명령과 결과(통과·실패 수, 실패하면 오류 원문)
3. 확인하지 못한 것(추정은 "추정"이라고 표시)
4. 따로 볼 것(범위 밖에서 본 문제, 지시문과 다른 코드 상태)

모든 주장에는 `경로:줄번호` 근거를 붙인다.
