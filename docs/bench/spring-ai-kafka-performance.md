# Spring AI 2·Kafka 대기열 도입 성능 기록 (2026-10-29 ~ 2026-10-31)

> 최신 종합: [2026-11-01 비교 정리](system-comparison-summary-20261101.md). 원본 재계산과 후속 중복 억제/복구 검증 상태를 포함합니다. 아래 수치는 당시 기록입니다.

> 2026-10-31 후속 검증: [기존·Spring AI 2·Kafka 비교](system-comparison-20261031.md). 과거 Kafka 87·88은 서로 다른 영상이므로 통제 속도 비교가 아니다. 최신 비교와 한계는 이 후속 문서를 우선한다.

두 도입(PR #245 Spring AI, PR #246 Kafka)이 성능에 무엇을 바꿨는지 실측으로 모은 기록. 출처는 docs/experience-notes.md의 각 작업 항목이다.
**실측**만 숫자로 적고, 재지 않은 것은 "추정"이라고 쓴다. 환경은 매 줄에 로컬/운영을 적는다.

## 한눈에

| 바꾼 것 | 속도(전 → 후) | 비용(전 → 후) | 얻은 것 | 환경 |
|---|---|---|---|---|
| Spring AI 2 (Gemini 텍스트·JSON 호출) | 응답 중앙값 902ms → 892ms(소표본 관측) | JAR 71.2 → 95.9MB(+24.7), RSS +16MB | 초기 SDK의 숨은 재시도 제거(최초 REST도 상한 3회), `gen_ai_*` 지표 자동 | 로컬(Mac) |
| Spring AI 2 운영 | 2026-10-31 첫 호출 6/6 20초 시간 초과(#253) → HTTP/1.1 고정(#254) 뒤 1/1 성공 5.1초 | 운영 RSS 384MB(배포 직후) | — | 운영(Oracle E2.1.Micro) |
| Kafka 대기열 (영상 분석 시작) | 분석 시간 14.5초(kafka)·14.8초(async 폴백), 다른 영상이라 속도 비교 불가 | JAR 71.2 → 83.9MB(+12.8), non-heap +14MB, RSS 비슷 | 프로세스 재시작 후 재수신 관측; Aiven 전원 중단 시 보존 한계 있음, 경로별 대기 지표 | 운영·로컬 |
| Kafka 대기 시간 (공유 → 분석 시작) | async 경로는 재지 않음(추정 수십 ms) → kafka 252ms(로컬 Docker), 1,192ms(운영 Aiven, 연결 뒤), 3,867ms(운영, 재시작 뒤 첫 공유) | 브로커 실패 시 넘김에 +5초 한 번(`max.block.ms`) | — | 로컬·운영 |

결론: 현재 자료로 두 기술의 유의미한 속도 이득을 입증하지 못했다. Spring AI는 호출 경계·지표, Kafka는 전달 경로·재수신의 변화다. 자원 증가와 장애 시 보존 한계도 함께 평가해야 한다.

## Spring AI 2 (PR #245, ADR 0020)

### 로컬 응답 시간 (2026-10-30, Mac, JVM -Xmx384m, 같은 프롬프트를 기존·새 클라이언트로 번갈아 각 4회 × 2회차)

| | 기존 RestClient | Spring AI(google-genai) |
|---|---|---|
| 첫 호출 | 1276 / 1181ms | 1062 / 1349ms |
| 나머지 중앙값 | 902ms(6회) | 892ms(5회) |
| 나머지 평균 | 902ms | 932ms |

- 차이는 측정 흔들림 안. 응답 시간은 거의 Gemini 처리 시간이다.
- Spring AI 1회는 분당 제한 `429`로 2.0초 만에 실패했다(30초 안에 15번 넘게 부름). 운영과 키를 같이 쓰므로 다음 측정은 호출 사이에 간격을 둔다.

### 로컬 자원 (2026-10-29, -Xmx384m, 개발 DB, 기준 main 97fc866과 번갈아 각 2회)

| 항목 | 기준 | Spring AI | 차이 |
|---|---|---|---|
| JAR | 71.2MB | 95.9MB | +24.7MB |
| 시작 시간 | 3.73 / 3.47초 | 3.65 / 4.27초 | 비슷 |
| 시작 20초 뒤 RSS | 374 / 392MB | 399 / 400MB | 평균 +16MB |
| heap / non-heap | 95·78 / 135·138MB | 101·108 / 144·142MB | non-heap +약 7MB |
| 불러온 클래스 | 21,810 | 22,723 / 22,732 | +약 920 |

### 재시도 상한 (실측에서 발견)
- SDK 기본 재시도 5회 × Spring AI 기본 10회 × 우리 코드 3회가 겹쳐 한 요청이 최대 15회까지 Gemini를 부를 수 있었고, 20초 제한인데 한 호출이 41초 걸렸다(로컬).
- 둘을 끄고 우리 코드 3회만 남긴 뒤 모든 호출이 20.1초 안에서 끊겼다.

### 운영 (2026-10-31, Oracle E2.1.Micro, 배포 15c1406)
- 배포 직후 java RSS 384MB, 서버 여유 268MB. 재시작 뒤 UP까지 119초.
- 첫 실사용("영상으로 일정 짜기" 2회): Gemini 호출 6회 전부 20.3초 시간 초과(`gen_ai_client_operation_seconds{error="RuntimeException"}` 6, 합 120.8초). 같은 시각 맥에서 REST 직접 호출은 200·0.2초.
  → 운영 서버 + google-genai(OkHttp, HTTP/2) 조합 문제로 보고 HTTP/1.1로 고정(#254).

### 운영 재측정 — HTTP/1.1 고정 뒤 (2026-10-31 02:24, 배포 2b1b56e)
- 같은 시나리오("영상으로 일정 짜기", 당일·영상 1개·장소 7곳): Gemini 호출 1회 **성공, 5.1초**, 토큰 입력 926·출력 325(`gen_ai_client_token_usage_total`). 앱에 초안(당일·서울 6곳)이 떴다. 재시작 뒤 첫 호출이라 연결을 새로 연 시간이 포함돼 있다.
- 전후 비교(운영, 같은 시나리오): HTTP/2(기본) 6/6 시간 초과 20.3초 → HTTP/1.1 1/1 성공 5.1초. 로컬에서 잰 892ms(짧은 프롬프트)와 달리 초안 생성은 프롬프트가 길어(926 토큰) 5초대다.
- 배포: 해시 일치, 재시작 뒤 UP까지 108초, 확인 3항목 통과, 전체 145초. 백업 `app.jar.bak-20261031-022143`.

## Kafka 대기열 (PR #246·#250, ADR 0021)

### 분석 시간 — 운영 실공유 (2026-10-30, Aiven 무료 Kafka)

| | 작업 | 경로 | 분석 시작 → 끝 |
|---|---|---|---|
| 브로커 켜짐 | 87(강릉 쇼츠) | Kafka 리스너 | 14.5초 |
| 브로커 꺼짐 | 88 | 넘김 → 서버 안 대기열(async) | 14.8초 |

- 두 작업의 영상이 달라 경로에 따른 분석 속도 차이는 이 자료로 판단할 수 없다. 후속 문서에 원본 로그를 재검증했다.

### 공유 → 분석 시작 대기 (`trova_queue_wait{path}`, #250)

| 환경 | 경로 | 대기 | 조건 |
|---|---|---|---|
| 로컬 Docker Kafka + 임시 서버 8091 | kafka | 252ms | 작업 89 |
| 로컬, 브로커 끈 뒤 | async(넘김) | 5,074ms | 보내기 대기 5초가 더해짐. 1분 건너뛰기 동안의 다음 공유는 이 5초를 겪지 않음 |
| 운영 Aiven | kafka | 3,867ms | 작업 91, 재시작 뒤 첫 공유(연결을 새로 엶) |
| 운영 Aiven | kafka | 1,192ms | 작업 92, 연결이 열린 뒤. 프로듀서 요청 지연(서버 → Aiven) 79ms |

- 추정(실측 아님): 운영 1.2초의 나머지는 DB 왕복·소비자 가져오기 간격으로 보이나 나눠 재지 않았다. 기존 async 경로의 대기는 지표가 없던 때라 재지 않았다(스레드 풀 바로 실행이라 수십 ms 추정).

### 자원 (2026-10-30, 로컬, -Xmx384m, 각 2회)

| | 기준 main | async(기본) | kafka |
|---|---|---|---|
| non-heap | 138 / 139MB | 138 / 137MB | 152 / 152MB |
| RSS | 386 / 414MB | 412 / 391MB | 408 / 410MB |
| 불러온 클래스 | 약 21,820 | 약 22,170 | 약 24,220 |
| JAR | 71.2MB | — | 83.9MB(+12.8, zstd·snappy 제외 뒤) |

- 운영 배포 뒤 java RSS 약 375MB, 서버 여유 221MB. 브로커는 운영 서버(956MB)에 두지 않고 Aiven 무료를 쓴다.
- 브로커가 꺼졌을 때 공유 응답: 기본 `max.block.ms` 60초 → 5초로 줄여 503까지 61초 → 6초(로컬).

## 남은 측정
- Spring AI: 운영 호출이 쌓이면 `gen_ai_client_operation_seconds`로 중앙값·실패율을 기록(지금은 1회).
- Kafka: 운영 공유가 쌓이면 경로별 대기 중앙값과 1초 안 시작 비율(Grafana 패널 #252).
