## 알게 된 것

1. **Python 자체는 작다.** CPU 164~295ms, 메모리 21~26MiB, 시작·종료 51~128ms, 요청 준비는 최대 58ms였다. Python을 Rust나 Java로 바꿔도 줄일 수 있는 건 많아야 분석 1건(10~41초)에서 약 0.3초다. → **언어를 바꿀 근거가 없다.**
2. **인스타는 프레임 뽑기(ffmpeg)가 가장 크다.** 19.6~19.7초로 분석 시간의 절반이고, 자식 CPU가 37~38초다(CPU가 약한 서버에서 영상 전체를 디코딩한다). Gemini는 6~8초다. ffmpeg는 이미 C 프로그램이라 Rust로 바꿀 대상이 아니고, **뽑는 방식(옵션)을 바꾸는 것**이 후보다.
3. **생각(thinking) 토큰은 0이다.** 10회 모두 값이 오지 않았고, 지난 14일 기록도 전체 = 입력 + 출력이었다. → thinking 설정은 줄일 여지가 없다.
4. **유튜브 입력의 93%가 영상 토큰이다**(5,354 중 5,000). collect와 filter가 같은 영상을 매번 처리한다. 캐시는 4번 중 1번만(3,524토큰) 잡혔다. → 영상 해상도 낮추기 또는 두 호출 합치기가 후보다(정확도 평가 필요).
5. **같은 유튜브 영상도 Gemini 시간이 크게 흔들린다**(collect 8.9초 vs 2.8초). 1~2건으로 개선 효과를 판단하면 안 된다.
