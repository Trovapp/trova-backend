# AI 대화: 장소 찾기 도구 호출률과 응답 대기 (#69)

## 문제 (운영 서버, 2026-09-30 21:33)
- 테스트 계정으로 대화 5번: 2번은 정확히 5초에 `Read timed out`으로 끊겨 "지금 답변을 가져오지 못했어요", 3번은 "카드로 보여드릴게요"라고 답했지만 후보 0개.
- 같은 시각 `api_call_logs`에 `google-places` 호출 0건 → Gemini가 `find_alternatives` 도구를 부르지 않고 말만 했다.
- 운영 기록: 9/15~9/18에는 대화 20턴 중 도구 호출 8번, 9/30에는 5턴 중 0번. 그 사이 대화 코드 변경은 #54(기호 금지 규칙 추가) 하나.
- 로컬(Mac) 서버도 같은 시간대에 5번 중 4번 5초 시간 초과. 몇 분 뒤 다시 잰 6번은 모두 약 1초로 정상 → Gemini가 일시적으로 느렸던 시간대.

## 측정 방법 (로컬 Mac에서 Gemini 직접 호출)
- 스크립트: `docs/benchmarks/scripts/chat_tool_call_bench.py`. 서버와 같은 요청 형태(지시문 + 도구 선언, 호출 모드 AUTO, 세션 첫 메시지). 지시문은 Java 소스에서 그대로 읽는다.
- 메시지 18개 × 3회 = 지시문당 54회. 장소 세션 찾기 8개, 빈 시간 세션 찾기 4개, 일반 대화 6개("고마워", "몇 시에 문 열어?" 등).
- 판정: 찾기 요청은 그 세션의 찾기 도구를 불러야 통과. 일반 대화는 찾기 도구를 부르지 않고, 도구 없이 "카드/화면/찾아드렸/찾아보았" 같은 이미 찾았다는 표현을 쓰지 않아야 통과("찾아드릴까요" 같은 제안은 허용).
- 가짜 카드: 도구를 부르지 않았는데 이미 찾았다는 표현을 쓴 답(사용자에게 빈 카드 약속).
- 원본 결과: `docs/benchmarks/results/2026-09-30-chat-tool-calling/*.json`

|---|---|---|---|---|---|
| #54 이전 (9/18까지 운영) | 11/24 (46%) | 12/12 | 18/18 | 12 | 1.05초 / 9.95초 |
| #54 이후 = 수정 전 (9/30 운영) | **5/24 (21%)** | 11/12 | 18/18 | **19** | 1.04초 / 1.29초 |
| **수정 후 (#69)** | **24/24 (100%)** | **12/12** | **18/18** | **0** | 1.01초 / 40.93초 |

- #54의 기호 금지 규칙 추가 뒤 장소 찾기 도구 호출률이 46% → 21%로 떨어졌다. 다만 #54 이전도 절반 이하라, 근본 원인은 "도구 없이 카드 이야기를 해도 된다"고 읽히는 지시문이었다.
- 수정 후 지시문: 찾기 요청이면 도구를 먼저 호출, 카드는 이번에 호출한 도구 결과로만 생긴다, 도구를 안 불렀으면 카드/찾아드렸다 표현 금지, 장소 정보(이름, 영업시간, 평점) 지어내기 금지.
- 수정 전에는 "여기 몇 시에 문 열어?"에 영업시간을 지어낸 답(오전 열 시부터 오후 아홉 시)도 있었다(사전 측정). 수정 후에는 "확인되지 않습니다"로 답한다.

## 응답 대기 시간 (같은 측정 162회)
- 대부분 약 1초. 수정 후 측정 1회차에 4.5~5.6초가 5번(그중 2번은 예전 5초 대기였다면 끊김), 3회차에 40.9초가 1번.
- 대화 호출 대기를 5초 → 20초로 늘렸다(1단계). 40.9초 같은 경우는 20초로도 끊긴다 — 앱 대기 60초 안에서 Gemini 2회(20초씩) + 도구(약 11초)를 맞추느라 더 늘리지 않았다.

## 확인하지 않은 것
- 여러 턴 대화(두 번째 메시지 이후)와 note_preference 호출은 측정하지 않았다(세션 첫 메시지만).
- AUTO 모드는 확률적이다. 54회 표본에서 100%이지 항상 100%라는 뜻은 아니다.
