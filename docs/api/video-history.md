# 영상 분석 이력 API

앱은 기존처럼 `GET /api/places`로 영상 기록을 연다. 같은 영상에서는 장소가 남은 가장 큰 작업 번호가 대표 결과다. 재분석할 때 새 작업에 장소를 저장하므로 이전 결과, 북마크, 여행 일정의 ID가 유지된다. 이력에는 현재 남아 있는 장소가 표시된다. 사용자가 직접 삭제·수정한 장소의 원본을 복구하는 기능은 없다.

## 분석 회차 선택

로그인한 사용자가 `GET /api/places/videos/{jobId}/history`를 호출한다. 기준 작업과 정규화한 영상 URL이 같은 본인 결과만 반환한다. 유튜브 shorts·watch·live·embed·youtu.be와 인스타그램 reel·p 등은 플랫폼과 영상 ID가 같으면 같은 영상으로 묶는다. 작업 번호 내림차순이며 첫 항목이 대표 결과다. `createdAt`은 작업 생성 시각, `placeCount`는 남은 장소 수다. 장소가 없는 회차는 제외한다.

```json
[
  {"jobId": 32, "createdAt": "2026-11-21T12:00:00", "placeCount": 5},
  {"jobId": 21, "createdAt": "2026-11-20T12:00:00", "placeCount": 10}
]
```

`GET /api/places/videos/{jobId}/history/{resultId}`에서 목록의 작업 번호를 `resultId`로 전달한다. 응답은 기존 `GET /api/places`와 같은 장소 배열이며 선택한 회차만 포함한다. 기준 작업이 없거나 타인 소유이면 두 API 모두 404다. 상세는 다른 영상·타인의 결과 또는 장소가 모두 삭제된 회차에도 404를 반환한다.

## 장소를 저장할 때 표시할 주소

주소와 지도 핀은 항상 같은 응답에서 읽는다. 영상 시트와 이력에서는 분석 결과의 `roadAddress`를 우선하고 비어 있으면 `address`를 사용한다. `addressSource`는 `ANALYSIS_RESULT`다. 사용자가 위치를 바로잡으면 수정한 결과가 표시된다. 북마크 생성·목록에서는 연결된 카탈로그 장소의 `address`와 좌표를 사용하고 `addressSource`는 `PLACE_CATALOG`다. 주소가 없으면 출처는 null이다.

`POST /api/bookmarks/saved-place`는 영업시간 조회에서 저장한 Google ID의 후보도 이름과 거리로 확인한다. 기존 후보가 부적합하면 지역·장소명으로 검색한다. 좌표가 양쪽에 있고 직선거리 300m 이내이며 공백·기호·괄호 속 한자 병기를 제거한 이름이 일치하는 후보를 허용한다. 지점 이름은 지역 접두어나 생략한 상호를 고려한다. 예를 들어 ‘이삭토스트 서울명동성당점’과 ‘이삭토스트 명동성당점’은 같은 지점 후보이며, 다른 상호나 다른 지점명은 제외한다. ‘롯데백화점’과 ‘나이키 롯데백화점’처럼 시설과 입점 매장의 이름만 겹치는 경우도 제외한다. 일치하는 후보가 없으면 422이며 북마크를 생성하지 않는다. 기존 카탈로그 핀에 좌표가 빠져 있으면 같은 Google ID와 이름을 확인한 검색 결과로 좌표를 복구한다. 상세 조회는 기존 Google ID를 우선하며 검색이 필요할 때는 기존 3km 기준을 사용한다.

### 여러 카탈로그 핀이 일치할 때

기존 Google ID가 검증을 통과하면 그 핀을 유지한다. 검색이 필요할 때는 조건을 만족하는 후보 중 분석 좌표와 가장 가까운 핀을 선택한다. 거리가 같으면 카탈로그 행 ID가 작은 핀을 선택한다. 서로 다른 Google ID의 행은 별도로 유지하므로 기존 북마크와 일정의 참조도 유지된다.

경포호 QA 건의 분석 핀(운정동 984)에는 Google ID가 없었다. 운영 읽기 전용 대조에서 같은 호수의 카탈로그 핀 두 개가 확인됐다. 저동 94의 ‘경포호(鏡浦湖)’는 분석 핀에서 약 130m, ‘강릉시 경포호’의 ‘경포호’는 약 143m 떨어져 있었다. 두 후보가 함께 검색되면 저동 94의 핀을 저장한다. 영상 시트와 저장 목록의 주소 차이는 각 출처가 호수의 대표 지점을 다르게 기록한 결과다.
