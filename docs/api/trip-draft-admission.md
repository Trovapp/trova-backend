# 일정 초안 접수와 다시 짜기

인증된 사용자가 `POST /api/trip-drafts`에 영상 목록과 조건을 보내면 서버가 비동기 생성 작업을 접수한다. 기존 초안에서 다시 짜기를 시작할 때는 `replacesDraftId`에 원본 초안 번호를 넣는다.

```http
POST /api/trip-drafts
Content-Type: application/json
Idempotency-Key: 93242a57-f1b4-40bc-9f28-514f1ae595c6

{"jobIds":[17],"message":"당일치기 오전 위주","replacesDraftId":41}
```

앱은 사용자가 새 작업을 시작할 때 UUID 하나를 발급한다. 응답 유실이나 앱 재실행으로 같은 요청을 복구할 때는 그 키를 다시 보낸다. 401 후 같은 계정으로 다시 로그인해도 미확정 요청에는 같은 키를 보낸다. 키는 선택 사항이며 UUID 형식이 잘못되면 400이다.

| 상황 | HTTP | 응답과 앱 동작 |
|---|---|---|
| 새 작업 접수 | 202 | `{"draftId":42,"status":"PENDING"}` |
| 같은 사용자가 최초 접수 후 24시간 안에 같은 키를 재전송 | 202 | 본문 조건·원본·작업의 현재 상태와 관계없이 최초 접수 응답을 재생한다. `GET /api/trip-drafts/42`에서 현재 상태를 확인한다. |
| 원본 없는 수동 생성에서 같은 사용자가 24시간 미만에 같은 본문을 다시 전송(키 생략·변경 포함) | 202 | 폐기되지 않은 PENDING·PROCESSING·NEEDS_INPUT·READY 초안의 최초 ID와 `PENDING`을 돌려준다. 승인·폐기·실패 직후 또는 최초 접수부터 24시간이 지나면 새 키나 헤더 없는 요청으로 새 초안을 만들 수 있다. |
| 원본이 있는 다시 짜기에서 같은 사용자가 10분 미만에 같은 본문을 다시 전송(키 생략·변경 포함) | 202 | 완료·질문 대기를 포함해 최초 작업 ID와 `PENDING`을 재생한다. |
| 같은 원본에 PENDING·PROCESSING 작업이 있고 본문이 다르거나 10분이 지난 경우(기존 키 재생 제외) | 409 | `activeDraftId`로 기존 초안을 조회한다. 최초 접수 후 24시간 미만이고 정규화한 본문이 같으면 이 요청의 키도 기존 작업에 연결한다. 409 본문을 읽지 못하면 같은 키를 보관해 다시 보낸다. 다른 본문의 키는 연결하지 않는다. |
| 같은 원본의 대체 초안이 NEEDS_INPUT이고 키·본문 재생 조건에 해당하지 않는 유효한 요청 | 202 | 이전 질문을 종료하고 새 초안을 접수한다. 이전 질문에 뒤늦게 답하면 답변 API가 409를 반환한다. |
| 배포 전 원본 번호를 기록하지 않은 진행 작업이 이 사용자의 비노출 원본에서 시작됐을 가능성이 있는 경우 | 503 | `DRAFT_LEGACY_JOB_IN_PROGRESS`와 `Retry-After: 30`을 반환한다. 30초 뒤 같은 요청을 재시도할 수 있다. |
| 원본의 작업이 READY·APPROVED·FAILED이고 키·본문 재생 조건에 해당하지 않는 요청 | 202 | 새 초안을 접수한다. 완료 후에도 24시간 내 기존 키로는 최초 응답을 받는다. |

본문을 비교할 때 영상 번호 목록은 순서와 중복을 무시한다. 날짜와 조건은 `message`에 담기며, 메시지의 앞뒤 공백과 연속 공백 차이는 무시한다. `replacesDraftId`가 다르면 별도 요청이다. 서버는 접수된 키를 먼저 조회한다. 본문으로 재생할 때 받은 새 키도 최초 접수의 24시간 만료 시각까지 같은 작업을 가리킨다. 재생으로 본문이나 키의 만료 시각이 연장되지 않는다. 원본이 있는 다시 짜기에서 재생할 키가 없고 최초 접수 후 10분 이상 지났으면 기존 원본의 상태에 따라 새로 접수하거나 409를 반환한다. 같은 원본에서 다른 조건으로 이미 처리 중이면 그 작업의 409가 과거 본문 재생보다 우선한다. 본문 재생은 해시 저장을 시작한 버전에서 접수한 작업부터 적용한다.

상세 조회 `GET /api/trip-drafts/{draftId}`는 폐기 여부를 불리언 `dismissed`에 담는다. 닫힌 초안은 `true`, 나머지는 `false`다. 앱은 구버전 서버와 호환되도록 필드를 선택적으로 읽는다. 다른 기기에서 폐기했거나 상태가 APPROVED·FAILED가 됐다면, 같은 입력으로 새 수동 생성을 시작할 때 새 키를 사용한다.

배포 전에는 비노출 원본과 다시 짠 초안의 관계를 저장하지 않았다. 같은 사용자가 원본보다 나중에 만든 미추적 수동 초안 중 두 원본 번호가 모두 비어 있는 행이 후보가 된다. 영상 선택은 다시 짤 때 바꿀 수 있어 영상 목록만으로 원본을 확정할 수 없다.

후보에 PENDING·PROCESSING 작업이나 마지막 갱신 후 24시간이 지나지 않은 NEEDS_INPUT 질문이 하나라도 있으면 503을 반환한다. 키는 소비하지 않고 질문은 그대로 두므로 사용자가 답할 수 있다. 후보가 모두 마지막 갱신 후 24시간 이상 지난 질문이면 유효한 새 요청을 202로 접수하면서 그 질문들을 만료 처리한다. 만료된 질문에 뒤늦게 답하면 409다.

409 응답 예시

```json
{
  "code": "DRAFT_REPLACEMENT_IN_PROGRESS",
  "message": "이 일정을 이미 다시 짜고 있어요.",
  "status": 409,
  "traceId": "d41ffc4d-3767-4c19-bcfa-f082c9de8821",
  "activeDraftId": 42
}
```

`activeDraftId`는 진행 중인 대체 초안의 숫자 ID다. `traceId`는 응답 헤더 `X-Trace-Id`와 같다.
