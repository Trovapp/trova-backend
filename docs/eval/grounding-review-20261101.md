# 장소 추출 정확도 보완 (#293)

프롬프트 후보는 채택하지 않았다. 사람 정답과 같은 채점 코드를 사용한 신규10영상 전후 비교에서 strict 재현율(정답을 빠뜨리지 않은 비율)은74.95→64.37%, 정밀도(내놓은 이름 중 맞은 비율)는73.95→64.92%였다. 기존 느슨한 채점은 재현율78.86→78.27%, 정밀도78.18→80.33%였다. 유리한 정밀도 하나만 골라 개선으로 부르지 않는다. 정답 없는 사례의 오탐도0→1로 늘어 미리 정한 채택 기준을 통과하지 못했다.

모델의측정시점변동이있으므로이값과과거66.4/64.2%를연결해코드개선률로쓰지않는다. 새실험은캐시없음·영상별전후순서교대·같은모델/temperature/사람정답·원본해시·기존scoring.cjs를사용했다. 최종20개유효실행과별개로RemoteDisconnected1건은기록에보존하고0점으로숨기지않았다. 같은입력해시를확인하고오류사례부터재개했다. 실제Gemini요청은before22/after20=42, 단계별30·전체60상한내다. 429/예산초과는재개대상이아니다.

## 채택한 좁은 수정

기존프롬프트가이미제외하는서울/부산/제주도와명시적영문표기, SRT기차안같이고정지도지점이아닌표기를정확일치로검사한다. 부산역/서울숲/Busan Museum 등부분문자열이겹치는장소는유지한다. 같은이름의실제식당/카페/숙소/상점이나구체주소가있으면보존한다. 전세계지명이나정답별칭을추측해삭제하지않는다. 프롬프트후보/새AI호출단계는production에추가하지않았다(ADR0031).

## 운영 서버에서의 부분 확인

사용자 요청 후 같은배포Python과키를쓰는운영서버에서공개영상2개를실행했다. 운영JAR/스크립트를교체하거나사용자공유job을만들지않았고, 임시파일로새순수점검함수만적용한재생이다. 따라서앱전체/Kafka성능시험은아니다.

- 영상5: 원래결과 `Busan`1개가점검후빈목록이됐다. 사람정답도빈목록이다.
- 영상6: 원래구체장소10개는그대로유지했다. 다른이름철자/누락이남아전체정확도가완성됐다는뜻은아니다.
- 실제운영Gemini4요청,기존배포소스해시/수정후보해시/API기록과전체places를원본에보관했다. 이새점검을검증하려고같은모델을다시호출하지는않았다. 임시후보파일삭제·운영서비스파일/DB변경없음.
