# Trova 화면 녹화 릴스 시나리오

## 공통 촬영 원칙

- 각 영상은 15초예요. 세로 화면으로 녹화하고, 자막이 장소명과 앱의 경고를 가리지 않게 배치해요.
- 직접 만든 여행 영상이나 홍보용 사용 허락을 받은 릴스·쇼츠를 써요. 장소명과 방문 맥락이 분명한 영상을 골라요. 출처 표기만으로 사용 허락을 대신하지 않아요.
- 실제 사용자 이름·사용자 데이터가 없는 홍보용 테스트 계정을 써요. 로그인 상태를 확인하고 알림을 꺼요. 공유 단축어 키와 계정 정보는 녹화하지 않아요.
- 아이폰은 홈 화면 PWA와 공유 단축어 연결을, 안드로이드는 비공개 테스트 앱 설치와 공유 목록의 Trova 표시를 미리 확인해요. 한 편에서는 같은 기기로 흐름을 이어 가요.
- 최근 7일 공유 한도 10개 중 촬영·실패 재현·재촬영에 쓸 여유를 확인해요. AI 일일 한도도 확인해요. 같은 영상의 기존 결과를 연 것을 새 분석처럼 연출하지 않아요.
- 15초는 편집본 길이예요. 분석 대기를 줄인 구간에는 “분석 대기 구간 편집”을 표시해요. 미리 준비한 결과를 쓰면 “미리 분석한 결과”라고 표시해요. 핀이나 메모를 합성하지 않아요.
- 장소 추출 실패, 위치 미확인, AI 일일 한도 초과는 서로 다른 상태예요. 앱에서 확인한 실제 화면만 쓰고, 실패 안내 문구를 임의로 만들지 않아요.
- 공통 주의 자막 “AI가 장소를 잘못 찾을 수 있어요”를 결과 장면에 읽을 수 있게 넣어요. 일정은 늘 “초안”이라고 불러요.
- 아래 자막은 편집용 문구예요. 앱 자체가 보여 주는 오류 문구로 소개하지 않아요. 끝 문구는 모두 “링크는 프로필에”예요.

## 시나리오 1. 공유하면 지도에 장소가 담겨요

**훅 · 첫 1초 자막:** “이 릴스 속 장소 어디?”

| 시간 | 장면 순서 | 자막 문구 |
|---|---|---|
| 0–1초 | 여행 릴스에서 방문 장소가 보이는 순간을 보여 줘요. | 이 릴스 속 장소 어디? |
| 1–4초 | 영상의 공유 버튼을 누르고 Trova로 보내요. 아이폰에서는 ‘Trova에 저장’을 선택해요. | 여행 영상을 Trova로 공유해요 |
| 4–6초 | 실제 분석 중 화면을 보여 준 뒤 Trova의 결과 화면으로 이어 가요. | AI가 장소를 찾는 중이에요 / 분석 대기 구간 편집 |
| 6–11초 | 지도에 담긴 핀을 보여 주고, 핀을 눌러 영상 속 장소명과 대조해요. | 찾은 장소가 지도에 담겼어요 / AI가 장소를 잘못 찾을 수 있어요 |
| 11–13초 | 장소 카드와 지도를 함께 보여 줘요. | 방문 전 위치·영업정보를 확인해 주세요 |
| 13–15초 | 지도 결과를 배경으로 끝 문구를 보여 줘요. | 링크는 프로필에 |

**녹화 때 준비할 것**

- 사용할 영상: 같은 지역의 방문 장소명이 화면이나 음성으로 분명히 나오는 여행 릴스 또는 쇼츠. 원본과 실제 추출 결과를 대조해요.
- 로그인 상태: 테스트 계정에 로그인하고, 첫 공유 연결·알림 허용 안내를 미리 확인해요.
- 공유 한도 여유: 새 영상 공유와 재촬영에 쓸 여유를 남겨요. AI 일일 한도에 걸려 촬영이 멈추지 않는지도 확인해요.
- 결과 상태: 좌표가 확인된 장소로 지도 흐름을 보여 줘요. 위치 미확인 표시가 있으면 이를 가리거나 확인된 핀처럼 설명하지 않아요.

**실패하면 보이는 장면을 넣나요?** 이번 편에는 넣지 않아요. 공유에서 지도까지의 동작을 읽을 시간을 확보하기 위해서예요. 성공한 촬영 사례임을 설명란에 적고, 화면에는 AI 오류 가능성을 남겨요. 장소를 못 찾으면 실제 실패 화면을 별도로 보관해 시나리오 2의 실패 장면에 활용해요. 성공 결과로 바꿔 이어 붙이지 않아요.

## 시나리오 2. 영상 속 팁이 장소 메모에 남아요

**훅 · 첫 1초 자막:** “장소는 찾았는데, 팁은?”

| 시간 | 장면 순서 | 자막 문구 |
|---|---|---|
| 0–1초 | 원본 영상에서 방문 팁을 말하는 순간을 보여 줘요. | 장소는 찾았는데, 팁은? |
| 1–4초 | 원본에서 “방파제에서 사진 촬영 가능”이라는 팁을 확인해요. | 영상에서 들은 팁도 |
| 4–6초 | Trova의 해당 장소 카드를 열어요. | 미리 분석한 결과 |
| 6–10초 | 장소 메모를 확대해 실제로 남은 같은 팁을 보여 줘요. | 장소 메모에 함께 남아요 / AI가 장소를 잘못 찾을 수 있어요 |
| 10–13초 | 별도 실패 사례로 전환해 장소를 못 찾은 실제 앱 화면을 보여 줘요. | 다른 영상의 실패 사례 · 장소를 못 찾기도 해요 |
| 13–15초 | Trova 소개 화면으로 전환해 끝 문구를 보여 줘요. | 링크는 프로필에 |

**녹화 때 준비할 것**

- 사용할 영상: 위 팁을 실제로 말하는 직접 제작 또는 사용 허락을 받은 여행 영상. 다른 팁을 쓰면 원본 발언과 메모를 확인한 뒤 자막도 맞춰 바꿔요. 없는 팁을 메모에 넣지 않아요.
- 로그인 상태: 테스트 계정으로 로그인하고, 해당 장소의 메모를 바로 열 수 있도록 준비해요. 이 편은 이미 분석한 결과를 보여 줘요.
- 공유 한도 여유: 메모 촬영용 영상과 별도 실패 사례를 준비할 여유를 확인해요. 추가 촬영 전에 남은 공유 가능 여부와 AI 일일 한도를 다시 확인해요.
- 실패 화면: AI가 실제로 장소를 찾지 못한 테스트 영상의 화면을 준비해요. 일일 한도 오류나 위치 미확인을 장소 추출 실패로 대신 쓰지 않아요.

**실패하면 보이는 장면을 넣나요?** 넣어요. 팁을 함께 보관하는 장점을 보여 주면서도, AI가 장소를 찾지 못하면 기대한 메모까지 얻지 못할 수 있음을 전해요. 별도 영상의 사례라는 자막을 붙여 성공 장면과 구분해요. 실제 실패 화면이 확보되기 전에는 이 편을 게시하지 않아요.

## 시나리오 3. 영상 3개를 하루 일정 초안으로

**훅 · 첫 1초 자막:** “저장한 영상 3개, 하루로?”

| 시간 | 장면 순서 | 자막 문구 |
|---|---|---|
| 0–1초 | 촬영용 여행 영상 3개의 썸네일을 나란히 보여 줘요. | 저장한 영상 3개, 하루로? |
| 1–5초 | 각 영상에서 Trova로 공유하는 실제 동작을 짧게 이어 붙여요. | 같은 지역의 영상을 차례로 공유해요 / 공유·분석 대기 구간 편집 |
| 5–8초 | 영상들에서 추출된 장소가 모인 지도를 보여 줘요. | 영상 속 장소를 모았어요 / AI가 장소를 잘못 찾을 수 있어요 |
| 8–11초 | 실제 앱의 선택·일정 구성 동작을 거쳐, 해당 장소가 들어간 하루 일정 초안을 보여 줘요. | 모인 장소로 하루 일정 초안을 만들어요 |
| 11–13초 | 초안의 장소 순서를 훑고, 휴무일·영업시간 미확인 경고를 보여 줘요. | 초안이에요. 운영 정보는 확인해 주세요 |
| 13–15초 | 일정 초안을 배경으로 끝 문구를 보여 줘요. | 링크는 프로필에 |

**녹화 때 준비할 것**

- 사용할 영상: 같은 지역에서 하루에 방문을 검토할 만한 장소를 다루는 여행 영상 3개. 서로 멀리 떨어진 도시를 섞지 않고, 중복 장소가 적은 영상으로 골라요. 영상 사용 허락도 각각 확인해요.
- 로그인 상태: 같은 테스트 계정에서 공유부터 초안까지 이어 가요. 무관한 저장 장소가 결과에 섞이지 않도록 촬영용 계정을 준비해요.
- 공유 한도 여유: 영상 3개의 새 공유와 재촬영에 필요한 여유를 확인해요. AI 일일 한도에 걸리면 실제 대기·오류 상태를 확인하고 촬영을 멈춰요.
- 일정 구성: 실제 앱에서 여러 영상의 장소를 하루 초안으로 모으는 조작을 미리 확인해요. 선택이나 구성 동작이 필요하면 화면에 남겨요. 공유만으로 영상 3개가 자동 병합된다고 단정하지 않아요.
- 결과 확인: 초안의 장소가 해당 영상에서 왔는지 대조해요. 미확인 경고가 실제로 있는 결과를 사용하고, 없는 경고를 합성하지 않아요. 초안을 확정된 여행처럼 소개하지 않아요.

**실패하면 보이는 장면을 넣나요?** 이번 편에는 넣지 않아요. 여러 영상의 공유와 초안 확인을 보여 주는 데 시간을 써요. 대신 설명란에 “장소를 못 찾은 영상은 초안에 담기지 않을 수 있어요”를 적어요. 촬영 중 추출에 실패하면 그 상태를 기록하고, 빠진 장소를 수동으로 채운 결과를 자동 생성처럼 보여 주지 않아요.
