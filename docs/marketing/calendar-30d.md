# Trova SNS 운영 캘린더

## 운영 기준

D1은 운영을 시작하는 날이에요. 인스타는 주마다 릴스와 캐러셀을 합쳐 세 번, 스레드는 매일 글을 올려요. D1~D7을 첫 주로 삼아요. 마지막 주는 D29~D30만 포함하므로 인스타는 D29에 올리고, 나머지 주간 편성은 다음 달력에 이어 가요.

같은 날의 인스타와 스레드는 같은 테스트 자료를 써요. 하루 한 시간 안에서 자료 확인과 촬영에 절반, 편집에 나머지 대부분을 쓰고, 게시 전 점검과 내 게시물 댓글 확인 시간을 남겨요. 글만 올리는 날에는 짧게 작성하고 다음 촬영 자료를 준비해요. 새 분석을 매일 돌리거나 새 개발 작업을 게시 조건으로 삼지 않아요. 확인한 개선이 없으면 이미 확인한 판단과 남은 한계를 이야기해요. 표의 제목과 훅은 실제 화면에 맞을 때만 써요.

원본은 직접 만든 영상이나 홍보용 사용 허락을 받은 영상만 써요. 출처 표기로 허락을 대신하지 않아요. 홍보용 테스트 계정으로만 촬영해요. 숫자로 이용 규모나 성과를 말하지 않아요. 내 게시물에 달린 질문에 답하고, 남의 게시물에 댓글로 홍보하지 않아요.

### 릴스 순환과 변형 메모

- 시나리오 1은 D1 → D12 → D22에 써요. 원본을 릴스에서 쇼츠로 바꾸거나 장소를 찾는 첫 장면만 바꿔요. 공유 → 실제 분석 중 화면 → 지도 → 원본과 핀 대조의 흐름을 유지해요. 성공한 촬영 사례임을 설명란에 적어요. 실패한 결과를 성공 장면으로 이어 붙이지 않아요.
- 시나리오 2는 D5 → D15 → D26에 써요. 다른 실제 방문 팁으로 바꾸거나 보관한 원본과 메모를 다시 비교해요. 원본 발언과 같은 팁만 보여 줘요. ‘미리 분석한 결과’와 ‘다른 영상의 실패 사례’를 표시해요. 실제 장소 추출 실패 화면이 없으면 게시를 미루고, 점검한 지도·초안의 캐러셀로 해당 슬롯을 바꿔요. 다른 오류를 실패 화면 대신 쓰지 않아요.
- 시나리오 3은 D8 → D19 → D29에 써요. 원안의 같은 지역 영상 묶음을 다른 지역 묶음으로 바꾸거나 보관본의 도입 자막만 바꿔요. 실제 공유와 선택·일정 구성 동작을 남겨요. 공유만 하면 여러 영상이 자동 병합된다고 설명하지 않아요. 미확인 경고를 가리지 않아요. 설명란에는 ‘장소를 못 찾은 영상은 초안에 담기지 않을 수 있어요’를 넣어요.
- 세 시나리오 모두 원안의 짧은 세로 편집 구조를 써요. 분석 대기를 줄이면 ‘분석 대기 구간 편집’을 표시해요. 공유 동작도 줄인 편은 ‘공유·분석 대기 구간 편집’을 써요. 보관본을 새 분석으로 소개하지 않아요. 핀·메모·경고를 합성하지 않아요.
- 결과 장면에는 ‘AI가 장소를 잘못 찾을 수 있어요’를 읽을 수 있게 넣어요. 방문 전 위치와 운영 정보를 확인하도록 안내해요. 끝 문구는 ‘링크는 프로필에’로 통일해요. 초안이라는 표현을 유지해요. 준비나 점검이 길어지면 새 촬영을 멈추고, 점검을 마친 보관본으로 재편집해요. 사용할 자료가 없으면 게시를 미뤄요.

- [ ] 일정이 확정됐다고 받아들이면 ‘초안’과 미확인 경고를 먼저 보여 줘요. 공유만으로 모든 일정 구성이 끝난다고 오해하면 실제 선택·구성 동작을 남겨요.
- [ ] 실패 화면을 같은 영상의 전후로 오해하면 ‘다른 영상의 실패 사례’ 표시를 더 읽기 쉽게 바꿔요. 분석이 즉시 끝난다고 오해하면 대기 편집 표시를 점검해요.
- [ ] 영상 속 팁이 어디에 남는지 묻는 댓글이 이어지면 준비된 메모 화면을 다음 캐러셀에 넣어요. 직접 수정 방법을 물으면 실제 가능 범위를 확인한 뒤 안내해요.
- [ ] 자신의 저장 목록을 정리해 봤다는 반응이 오면 막힌 단계와 초안에서 확인한 부분을 물어요. 사용자 이름·화면·원본 데이터는 게시물에 옮기지 않아요.
- [ ] 개인정보 질문이 반복되면 시작 안내에서 방침을 찾는 경로를 점검해요. 처리 방식은 방침을 확인한 내용만 답해요.
- [ ] 별다른 질문이 없으면 내 게시물에 ‘저장한 영상을 정리할 때 어디서 막히나요?’라고 물어요. 단순 반응만으로 성과나 개선을 단정하지 않아요. 촬영이 버거우면 보관본 재편집과 짧은 글로 다음 주 분량을 조정해요.
