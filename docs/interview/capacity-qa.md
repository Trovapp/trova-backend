# 면접 노트 — 부하 테스트·병목 해결 (질문-답)

근거 문서와 숫자는 각 답 끝에. 숫자에는 항상 환경(운영/격리)과 조건을 붙여 말한다.

## Q. 성능 병목을 찾아서 개선한 경험이 있나요?
격리 환경에서 운영 사양을 흉내 내 장소 목록 API에 동시 사용자를 늘려 보니, 40명에서 p95가 2~3초로 늘고 DB CPU가 97%였습니다.
실행 계획을 보니 사용자별 조회가 테이블 전체를 훑고 있어서 `(user_id, created_at, id)` 인덱스를 추가했고,
같은 JVM·데이터에서 인덱스만 빼고 넣는 순서(ABBA)로 반복 측정해 p95 49~64ms, DB CPU 16%를 확인했습니다.
운영에 반영한 뒤에는 같은 방식으로 운영에서도 전후를 쟀는데, 운영 테이블이 277행이라 차이가 없었습니다.
그래서 “데이터가 늘었을 때를 위한 선제 조치”로 정리했고, 운영 응답 시간은 DB 밖에 있다는 걸 분해해서 확인했습니다.
(격리: `docs/monitoring/2026-11-02-index-abba.md`, 운영: `docs/monitoring/2026-11-04-prod-index.md`)

## Q. 왜 운영에서 바로 극한 부하 테스트를 하지 않았나요?
운영 서버가 메모리 1GB짜리 무료 인스턴스라 실제 사용자 장애 위험이 있고, DB가 Supabase 무료 티어라 서버 한계보다 DB 한도에 먼저 걸려
“서비스 한계”가 아니라 “무료 티어 한계”를 재게 됩니다. 그래서 극한은 운영 사양을 흉내 낸 복제 환경에서, 운영에는 분당 150건 정도의 약한 고정 부하만 걸고
응답 1건 2초·오류 1%·서버 메모리 기준을 넘으면 자동으로 멈추게 했습니다.

## Q. 운영에서 개선 효과가 없었다면, 그 작업은 의미가 없었던 건가요?
쿼리 시간이 0.26ms라 응답 270ms 중 비중이 거의 0이었습니다. 응답 시간을 분해해 보니 앱 내부 약 165ms, 서버→DB 왕복 31ms, 클라이언트→서버 왕복 40ms였습니다.
인덱스는 데이터가 늘면 격리 실험처럼 효과가 커지는 선제 조치이고, 이 분해 덕분에 다음에 고칠 곳(앱 내부 처리, DB 왕복 횟수)이 분명해졌습니다.
효과가 없다는 결과도 같은 조건에서 인덱스를 지웠다 다시 만들어 확인했습니다.

## Q. 처음 보는 장애나 멈춤을 겪은 적이 있나요?
운영 약한 부하 측정 중 평소 p95 400ms 정도인 API에서 요청 1건이 3초 시간 초과가 났습니다.
같은 시각 Prometheus를 보니 `jvm_gc_pause_seconds_max`의 major GC가 4.97초였고, DB 연결 5개가 모두 묶여 있었습니다.
JVM 옵션을 확인하니 GC를 지정하지 않아 작은 메모리 서버에서 Serial GC가 자동 선택돼 있었고, Full GC 동안 앱 전체가 멈춘(Stop-the-world) 것이었습니다.
힙 사용량은 90MiB뿐이라 CPU 한도(1/8 OCPU)나 스왑이 청소를 느리게 했다고 보고, GC 로그로 빈도를 확인한 뒤 Serial과 G1을 같은 부하로 비교할 계획입니다.
(진행 후 결과 추가)

## Q. 그럼 GC 없는 언어(예: Rust)로 바꾸면 되지 않나요?
GC 멈춤만 보면 맞지만, 백엔드 전체 재작성 비용이 크고 원인이 “GC 종류를 안 정한 설정”이라 JVM 설정으로 먼저 해결하는 게 비용 대비 맞다고 판단했습니다.
실제로 미디어 처리 일부를 Rust로 비교했을 때도 단독은 빨랐지만 Python에 붙이면 통신 비용으로 오히려 느려져(0.477→1.711ms) 기존 언어를 유지했습니다.

## Q. p95를 왜 보나요? 평균이면 안 되나요?
평균은 느린 요청 몇 개가 묻힙니다. 실제로 GC 멈춤이 있던 측정에서 평균은 291ms로 멀쩡했지만 최대는 3초였습니다.
p95는 “요청 100개 중 95개가 이 시간 안에 끝난다”는 뜻이라 대부분의 사용자가 겪는 최악을 보여 줍니다.

## Q. 측정 결과를 어떻게 믿을 수 있게 만들었나요?
- 같은 조건(같은 JAR·계정·부하·시간대)에서 한 가지만 바꿈. 운영에서는 배포 전에 인덱스만 바꿔 측정.
- 전/후를 번갈아 반복(ABBA, 있음→없음).
- 원본(k6 JSON, Prometheus 5초 간격 JSON, EXPLAIN)과 재현 스크립트를 커밋.
- 측정이 조기 중단되면 사유를 기록하고, 감시 기준을 고친 뒤 3분 완주로 다시 측정.
