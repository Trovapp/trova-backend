# 빈 시간에 자동 추천할 장소의 범위 · 2026-11-22

아파트·병원·관공서처럼 거주자나 용무가 있는 사람이 찾는 시설은 기본 추천에서 빼는 편이 좋다. 현재 비식사 시간에는 주변 업종을 제한하지 않고, 주거·의료 시설은 서버 제외 목록에도 없다. 주차장·주유소·학교·숙소는 이미 일부 걸러지므로 새 규칙의 효과와 구분해야 한다.

## 후보가 화면 응답에 들어가는 과정

1. 같은 일차의 연속 장소에서 앞 장소 종료와 뒤 장소 시작 사이가 **30분 초과**이고 양쪽 좌표가 있으면 산술 중점을 쓴다. 마지막 장소 뒤에도 종료부터 21시까지 30분을 넘기면 마지막 좌표로 검색한다.
2. Google Nearby Search (New)에 중심 반경 1,500m, 최대 20개, 한국어·KR을 요청한다. 11–14시 또는 17–20시와 조금이라도 겹치면 includedTypes에 restaurant 하나를 보낸다. 다른 시간대에는 type 제한이 없다. 검색 키워드, Text Search, 카카오 검색, 실패 후 대체 검색은 이 경로에 없다.
3. 검색 결과를 모두 공용 places에 upsert하고 임베딩을 준비한 뒤 앞뒤 장소와 Google ID가 같은 항목을 뺀다. 마지막 공백은 마지막 장소만 비교한다. 최초 저장 때 types 배열의 첫 값만 category에 남긴다. 기존 행은 누락 좌표를 보완하지만 새 분류로 갱신하지 않는다. primaryType 필드는 요청하지 않는다.
4. 저장 category가 아래 목록과 정확히 같으면 제외한다. null, 다른 세부 유형, 제외 유형이 배열 두 번째 이후에만 있는 신규 장소는 이 검사에서 살아남는다. 이름 검사도 없다.

   - 숙박: lodging, hotel, motel, hostel, guest_house, resort_hotel, extended_stay_hotel
   - 교통: subway_station, train_station, transit_station, bus_station, light_rail_station, airport
   - 교육·차량: university, school, primary_school, secondary_school, parking, gas_station

5. 평점·리뷰 수 하한은 없다. max(평점 × ln(리뷰 수 + 1), 1)에 개인화 계수 (1 + 0.6 × 개인화 점수)를 곱해 내림차순으로 정렬하고 비유한 점수를 뒤로 보낸다. 남은 후보 전체를 반환한다. 반경 외에 도보 시간, 우회 거리, 영업 여부로 거르는 단계는 없다.

근거는 [빈 시간 서비스](../../src/main/java/com/trova/backend/recommendation/GapRecommendationService.java), [검색 요청](../../src/main/java/com/trova/backend/recommendation/GooglePlacesApiClientImpl.java), [카탈로그](../../src/main/java/com/trova/backend/recommendation/PlaceCatalogService.java), [기본 점수](../../src/main/java/com/trova/backend/recommendation/PlaceScoring.java)에서 확인했다.

## 근거와 건수

운영 DB 환경 변수 PROD_DB_ENV_FILE이 없어 운영 집계는 미실행이다. Google·카카오 장소 API 호출도 없었다. 서버는 필터 전 원본 후보를 장소 단위로 공용 카탈로그에 저장하고, 빈 시간 요청별 후보 목록·최종 순위는 응답으로만 만든다. 다른 추천·장소 검색도 같은 카탈로그를 사용하며 호출 로그의 nearby-search-alternative 키까지 대체 장소 검색과 공유한다. 따라서 아래 표의 모든 분류에서 실제 노출 건수는 미상이다.

[기존 테스트](../../src/test/java/com/trova/backend/recommendation/GapRecommendationServiceTest.java)에는 동일 ID 카페와 다른 ID 카페, 평점 null 및 평점 1·리뷰 0인 카페 후보가 있다. 필터식을 대입하면 이웃과 다른 ID의 hospital, apartment_complex, null은 통과하고 parking, hotel은 탈락한다. 신규 후보의 types가 [point_of_interest, school] 순이면 통과한다. 이 예측과 아래 가상 상호는 실측 사례가 아니다.

## 적용 제안

- 빈 시간 검색에 한정해 primaryType을 함께 받아 명확한 주 용도를 먼저 판단한다. 신규 제외 후보는 apartment_building, apartment_complex, condominium_complex, housing_complex, hospital, doctor, dental_clinic, dentist, pharmacy, drugstore, local_government_office, city_hall, bank, atm, real_estate_agency, corporate_office, funeral_home이다. 기존 제외 유형과 합쳐 Nearby의 excludedPrimaryTypes에 지원되는 Table A 값만 보내면 원래 20자리 중 부적합 후보가 차지하는 몫도 줄일 수 있다. 종교시설·복합시설은 응답에서 판단해 관광 예외를 살린다. [Google 유형 표](https://developers.google.com/maps/documentation/places/web-service/place-types)
- 서버에서도 이번 응답의 primaryType과 전체 types를 사용해 기존 캐시의 오래된 category를 보완한다. 박물관·관광명소·카페처럼 방문 용도가 명확하면 부가 태그나 상호 속 단어 하나로 탈락시키지 않는다. point_of_interest, establishment만으로는 방문 적합성을 알 수 없다. 명확한 주거·의료 주 용도에 일반 태그가 붙어도 제외한다.
- 카카오는 현재 빈 시간 후보에 관여하지 않는다. 나중에 기존 카카오 결과를 재사용할 때만 원본 그룹 HP8·PM9(의료), PO3(공공), SC4·AC5(교육), BK9(은행), PK6·OL7(주차·주유), AG2(중개)를 제외 후보로 사용한다. CS2·AD5는 편의점·숙박 정책을 따르고 AT4·CT1은 관광·문화 예외 판단에 쓴다. 주거·물류 등은 category_name의 세부 경로로 판단한다. 현재 KakaoCategory는 카페·음식점·숙박·관광·쇼핑 등을 단순화하고 미인식 값은 추출 분류로 대체하므로 원본을 잃기 전에 판단해야 한다. [카카오 로컬 문서](https://developers.kakao.com/docs/ko/local/dev-guide) · [분류 변환](../../src/main/java/com/trova/backend/geocoding/KakaoCategory.java)
- 이름은 분류 누락 시 보조 신호로 쓴다. 공백 정규화 후 ‘아파트 관리사무소’, ‘행정복지센터’, ‘장례식장’처럼 구체적 접미어를 먼저 보고 ‘빌라’, ‘의원’, ‘공장’, ‘병원’ 단독 부분 일치는 보류한다. 주소에는 적용하지 않는다. 예를 들어 ‘옛병원 카페’(cafe), ‘호텔 1층 베이커리’(bakery), ‘옛성당’(관광명소)은 보존하고, ‘봄의원’(doctor)과 ‘솔빛아파트’(apartment_complex)는 제외하는 고정 사례로 검증한다.

## 매니저용 읽기 전용 집계

2026-10-24~11-22의 저장 시각 기준 공용 카탈로그 장소 수다. 기존 장소를 재검색할 때마다 last_synced_at을 갱신하지 않으므로 최근 조회 빈도도 측정하지 못한다. 결과에는 저장 분류, 이름 끝에서 매칭된 고정 단어, 건수만 나온다.

```sql
SELECT coalesce(category,'(없음)') AS stored_type,
       coalesce(substring(name from '(아파트|빌라|오피스텔|병원|의원|약국|보건소|주민센터|행정복지센터|학교|학원|은행|ATM|주차장|주유소|공인중개사|사무소|본사|교회|성당|장례식장|물류센터|공장|편의점|호텔|모텔)$'), '(기타)') AS name_suffix,
       count(*) AS catalog_places
FROM places
WHERE last_synced_at >= timestamp '2026-10-24' AND last_synced_at < timestamp '2026-11-23'
GROUP BY 1,2 ORDER BY 3 DESC,1,2;
```
