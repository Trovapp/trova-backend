# 0045. 장소 추출 정답에 Gemini·GPT 교차 일치분과 사람 확인분을 넣는다 (0022의 "AI 출력을 정답으로 넣지 않는다"를 바꿈)

- 상태: 확정 · 날짜: 2026-11-16 · 근거: 이슈 #437(사용자 작성, "일치하면 정답으로 넣고 불일치만 사람이 본다"), 사용자 지시 2026-11-16("answers.csv 반영 — 일치분과 Y 행 추가")
- 관련: [0022](0022-pipeline-regression-eval-evalflow.md)(정답은 answers.csv 한 곳, AI 출력을 정답으로 넣지 않음), 기록 `docs/eval/cross-check-20261116.md`

## 배경
`eval/extraction/answers.csv`는 사람이 영상을 보고 직접 적은 127행(영상 24개)이었다. 0022와 `eval/README.md` Part A는
"영상을 보고 직접, AI 결과를 보지 않고" 적도록 했다. 300행 이상으로 늘리려면 영상 200개를 사람이 다 보기 어렵다.

## 결정
- 같은 입력(제목·설명·한국어 자막·프레임 8장)을 Gemini(파이프라인)와 GPT(Codex)에 따로 넣어 **둘이 같은 장소를 내면 정답 후보**로 본다.
  하나만 낸 장소는 사람이 판정한 것(Y)만 넣는다. 판정 기준은 기존 정답과 같다: **영상이 소개한 장소만**
  (주변·해시태그·목록에 언급만, 다른 장소 안 시설, 번화가·상권·체인 지점 불명은 정답 아님).
- 새 행은 `note`에 출처를 남긴다: `#437 <샘플> 교차 일치(Gemini=…, GPT=…)` 또는 `#437 <샘플> 사람 확인 Y(…)`.
  사람이 직접 적은 기존 행(note 비었거나 다른 내용)과 구분된다.
- 새 영상 번호는 1000 + 샘플 번호(c007 → 1007)로 기존 1~35와 섞이지 않게 한다. `videos.csv`에는 `selected`를 비워 넣는다.
  Part A·evalflow 측정 범위(`selected=Y`)에 넣을지는 따로 정한다.
- 0022의 나머지(정답은 answers.csv 한 곳, evalflow 기대값은 `build_config.py`가 생성)는 그대로다.

## 결과와 한계
- 교차 일치분의 정확도는 사람이 전부 보지 않았다. GPT를 사람 정답과 비교한 정밀도가 79.8%였고, 둘이 같이 틀릴 수 있다.
  측정에서 이상한 오답이 나오면 `note`로 교차 일치 행인지 먼저 본다.
- 표기는 교차 판정에서 확인한 것만 고쳤다(기록 7절·8절). 나머지는 Gemini 표기 그대로다.
