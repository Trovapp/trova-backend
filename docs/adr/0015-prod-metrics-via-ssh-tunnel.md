# 0015 운영 서버 지표는 서버 안에서만 열고, Mac의 Prometheus가 SSH 터널로 가져간다
- 상태: 확정 · 날짜: 2026-10-13 · 근거: 이슈 #171, 사용자 결정("Prometheus로 한 번 봐보고싶은데", "운영서버로 해야하는거 아니야? 나 핸드폰으로 앱 사용해볼건데", 방법을 듣고 "진행")

## 결정
- 운영 서버 `.env`에 `ACTUATOR_EXPOSE=health,prometheus`를 둔다. 백엔드는 원래 `127.0.0.1:8080`에서만 받으므로 지표 주소도 서버 안에서만 열린다.
- 외부 입구(Caddy)에서 `/actuator`·`/actuator/*` 중 `health`를 뺀 나머지는 404로 막는다. #27(지표가 로그인 없이 공개되던 문제)을 코드 설정이 아니라 입구에서도 한 번 더 막는 셈이다.
- Prometheus·Grafana는 운영 서버가 아니라 Mac(`docker-compose.monitoring.yml`)에서 돌린다. Mac에서 SSH 터널(`127.0.0.1:18080` → 서버 `127.0.0.1:8080`)을 열어 둔 동안만 `job=trova-prod`로 15초마다 수집한다.
- 운영 지표가 Mac에 쌓이므로 Prometheus(9090)·Grafana(3300)는 `127.0.0.1`에만 연다. 대시보드 "Trova 서버 한눈에"는 레포에 두고 Grafana가 시작할 때 자동으로 불러온다(`monitoring/grafana/provisioning/dashboards/`).

## 이유
- 앱을 휴대폰으로 직접 쓰는 동안 운영 서버의 요청·응답 시간·오류를 실시간으로 보고 싶다. 관리자 대시보드는 5분 간격이라 한 번의 사용 흐름을 따라가기 어렵다.
- 서버에 새로 띄운 것이 없다. 설정 한 줄과 Caddy 규칙만 바뀌었다(둘 다 바꾸기 전 백업: `.env.bak-20261013-031153-metrics`, `Caddyfile.bak-20261013-031153-metrics`).
- Mac이 꺼져 있거나 터널이 닫혀 있으면 그동안의 지표는 없다. 항상 볼 기록은 계속 관리자 대시보드의 5분 스냅샷(ADR 0012)이 맡는다.
- 되돌리기: `.env`의 `ACTUATOR_EXPOSE` 줄을 지우고 재시작하면 된다. Caddy 규칙은 남겨 둬도 해가 없다.

## 비교한 대안
1. 운영 서버에 Prometheus·Grafana — 남은 메모리 약 300MB(E2.1.Micro 1GB)라 ADR 0012에서 이미 뺐다.
2. Grafana Cloud 무료 + 서버에 수집기(Alloy) — 상시 수집은 되지만 서버 메모리를 더 쓰고 외부 서비스가 늘어난다. 무료 한도도 다시 확인해야 한다.
3. 지표 주소를 외부에 열고 토큰으로 막기 — 앱 코드에 인증을 더해야 하고, 실수하면 #27이 다시 생긴다.

## 다시 볼 조건
- 운영 서버를 A1처럼 큰 서버로 옮기면 상시 수집(대안 1·2)을 다시 본다.
- 관리자가 여러 명이 되거나, Mac이 꺼져 있는 동안의 지표가 필요해지면.
