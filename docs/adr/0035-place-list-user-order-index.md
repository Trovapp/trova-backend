# 0035. 장소 목록의 사용자·정렬 복합 인덱스

- 날짜: 2026-11-02
- 상태: 확정 (격리 환경 검증, 운영 미적용)
- 관련: #307, ADR 0034

## 배경

장소 목록 DTO 쿼리는 `user_id`로 조회하고 `created_at desc, id desc`로 정렬한다.
격리 환경 16만 장소에서 순차 스캔과 DB CPU 포화가 관측됐다.

## 결정

`saved_places(user_id, created_at, id)` B-tree 인덱스를 추가한다.
user_id 동등 조건 뒤의 정렬은 역방향 인덱스 스캔으로 처리할 수 있다.
전체 엔티티 열을 인덱스에 복제하는 covering index는 만들지 않는다.
응답 형태와 순서, 페이지네이션 정책은 변경하지 않는다.

## 검증

같은 JAR/합성 데이터/CPU 제한에서 인덱스 없는 A와 있는 B를 ABBA 순서로 비교한다.
각 블록은 같은 20/40 VU 부하이고, 40개 계정의 응답 본문 SHA-256이 일치해야 한다.
실행 계획과 Prometheus 시계열, k6 지연/오류/처리량을 보존한다.
측정 결과는 후속 보고서에 기록하며 운영 성능으로 일반화하지 않는다.

## 적용과 비용

새 DB의 JPA 스키마 생성에는 `@Index`를 사용한다.
기존 운영 DB는 JPA 자동 update로 큰 테이블 인덱스를 생성하기 전에,
검토된 운영 절차로 CONCURRENTLY 인덱스를 생성하고 유효성을 확인해야 한다.
이번 작업은 운영 DB에 적용하지 않는다. 인덱스 저장 공간과 쓰기 비용이 추가된다.

실측: [ABBA 결과](../monitoring/2026-11-02-index-abba.md). 40 VU p95 평균 2793→57ms, DB CPU 97→16%, 연결 대기 최대 21→0.
