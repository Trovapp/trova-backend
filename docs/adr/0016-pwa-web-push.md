# 0016 PWA에 표준 웹 푸시(VAPID)로 일정 초안 준비·여행 날 비 소식을 알린다
- 상태: 확정 · 날짜: 2026-10-14 · 근거: 이슈 #185, 설계 [2026-10-14-web-push-design.md](../superpowers/specs/2026-10-14-web-push-design.md), 사용자 결정("단축어로 링크 보내고 다 됐을때 알림은 원래 안뜨는건가?", 이벤트·플랫폼·권한 시점·방식 선택 후 "응 ADR 바꾸고 진행해줘")
- 바꾸는 결정: [0013](0013-pwa-before-app-store.md)의 "웹 푸시 알림은 이번에 하지 않는다"

## 결정
- 앱스토어 출시 전에도 PWA(홈 화면에 설치한 웹앱)에 푸시 알림을 보낸다. 보내는 일은 두 가지뿐이다: 자동 일정 초안이 준비됐을 때, 여행 날 비 소식이 새로 생겼을 때.
- 중간 서비스(FCM·OneSignal 등) 없이 표준 웹 푸시(VAPID)로 서버가 직접 브라우저 푸시 서버(애플·구글·모질라)에 보낸다. 구독은 우리 DB(`push_subscriptions`)에 둔다.
- Java 라이브러리는 의존성이 없는 `com.zerodeplibs:zerodep-web-push-java`(2.1.5)를 쓰고, 발송은 `PushNotificationService` 하나로 감싸 바꿀 수 있게 둔다.
- 권한은 브라우저 창을 바로 띄우지 않고, 앱 안 카드의 [알림 받기]를 눌렀을 때만 묻는다(첫 영상을 보낸 직후, 단축어 사용자는 다음에 앱을 열 때).
- 네이티브 앱의 Expo 푸시(#137)는 앱스토어 출시 때 한다. 보낼 내용과 보내는 방법을 나눠 두어 그때 방법만 더한다.

## 이유
- 아이폰 사용자는 단축어로 영상을 보내므로 앱을 열지 않는다. 분석(약 45초)과 초안(약 3초)이 끝나도 알 방법이 없어 결과를 놓친다(2026-10-13 운영 사용 기록).
- 아이폰 PWA는 iOS 16.4부터 홈 화면에 설치한 경우 웹 푸시를 받을 수 있다. 애플 개발자 계정(연 $99) 없이 되는 유일한 알림 경로다.
- 표준 웹 푸시는 비용이 없고 가입할 외부 서비스가 없다([0002](0002-cost-zero-free-tiers.md)). 운영 서버 메모리가 1GB라 의존성이 없는 라이브러리를 고른다.

## 검토한 다른 방법
1. FCM(Firebase) 웹 푸시 — 무료지만 Firebase 프로젝트·SDK가 늘고, 아이폰도 결국 애플 푸시 서버로 간다. 얻는 게 적다.
2. OneSignal 같은 알림 서비스 — 무료 플랜이 있지만 사용자 구독 정보가 외부 서비스에 쌓이고 개인정보 위탁이 하나 더 는다.
3. 앱스토어 출시까지 기다리기(0013 그대로) — 그동안의 PWA 사용자는 결과를 놓친다.

## 결과
- 개인정보처리방침에 수집 항목(푸시 구독 정보, 알림 허용 시)과 4항 위탁(애플·구글·모질라 푸시 서버)을 기능 배포 전에 더한다.
- 운영 `.env`에 `VAPID_PUBLIC_KEY`·`VAPID_PRIVATE_KEY`·`VAPID_SUBJECT`가 필요하다. 키가 없으면 알림만 꺼지고 앱은 그대로 돈다.
- 날씨 확인은 "서버를 켠 때부터 4시간마다"에서 매일 8·12·16·20시(한국 시간)로 바뀐다. 알림이 밤에 가지 않게 하려는 것이다.
- 설치하지 않은 아이폰 Safari, iOS 16.4 미만, 알림을 거절한 사용자는 받지 못한다. 앱 안 알림은 그대로 있다.
