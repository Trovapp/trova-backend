# 0058 요청 안에서 임베딩 HTTP 대기와 독립 작업을 겹친다
- 상태: 확정 · 날짜: 2026-11-26 · 근거: #543, PR #544 리뷰

## 결정

`PlaceEmbeddingService.ensureEmbeddingsWithWork`는 Gemini 임베딩 HTTP 호출을 가상 스레드로 보내고 요청 스레드에서 독립 작업을 수행한다. 대안 찾기에서는 거리·이동시간 필터를 통과한 알려진 지역의 혼잡도 조회만 독립 작업으로 넘긴다.

- DB 조회·저장·사용량 기록과 엔티티 접근은 요청 스레드에만 둔다. 작업 스레드에는 엔티티 대신 미리 만든 불변 텍스트 목록만 넘기고 HTTP 결과만 돌려받는다. 트랜잭션이나 추가 DB 연결을 작업 스레드로 옮기지 않는다.
- executor는 요청 범위의 try-with-resources로 닫는다. 예외가 발생해도 종료를 기다려 응답 뒤에 작업을 남기지 않는다.
- Gemini 묶음은 요청당 동시에 하나만 보낸다. 첫 묶음 결과를 기다리는 동안 독립 작업을 정확히 한 번 실행하고, 결과 저장·사용량 기록 뒤 다음 묶음을 보낸다. 100개 단위 분할과 무료 한도 계산을 유지한다.
- 독립 작업 예외는 경고 로그만 남긴다. 이미 실행한 Gemini 결과의 저장과 사용량 기록은 계속한다. 이 작업의 실패가 임베딩 처리를 중단해서는 안 된다.
- 독립 작업이 없으면 기존처럼 요청 스레드에서 호출한다.

## 이유

대안 찾기의 임베딩 HTTP 대기와 혼잡도 조회는 서로 결과를 필요로 하지 않는다. 두 대기를 겹치면 Gemini 동시 호출 수와 DB 연결 수를 늘리지 않고 요청 시간을 줄일 수 있다. 독립 조회 실패로 생성한 벡터와 api_call_log가 사라지면 다음 요청에서 불필요한 재생성과 사용량 누락이 생긴다.

## 비교한 대안

- 순차 실행: 구조는 단순하지만 독립된 HTTP 대기 시간이 누적된다.
- 여러 Gemini 묶음 동시 실행: 무료 티어 요청 제한과 부하를 늘리므로 채택하지 않는다.
- 전역 executor로 넘기고 즉시 반환: 응답 뒤 작업이 남고 요청 수명과 오류 처리가 분리되므로 채택하지 않는다.

## 다시 볼 조건

다른 호출처에 적용하려면 해당 작업이 임베딩 결과에 의존하지 않고 요청 스레드에서 실행해도 안전한지 먼저 확인한다. 엔티티·DB·트랜잭션을 작업 스레드로 넘기지 않으며, executor 종료 대기·요청당 Gemini 동시 1개·독립 작업 1회·실패 시 저장과 기록 유지 조건을 지킨다. CI에서 latch를 이용해 실제 호출처의 HTTP 대기 중 실행, 여러 묶음, 실패 처리를 검증한 뒤 확장한다. 요청 수 증가로 전체 Gemini 동시 호출 제한이 필요해지면 요청 간 제한을 별도 결정한다.
