# 0012 관리자 운영 대시보드는 웹으로, 조치는 감사 기록과 함께, AI는 무료 한도와 로컬 플러그인으로
- 상태: 확정 · 날짜: 2026-10-11 · 근거: 이슈 #157, 사용자 결정("운영용", "이용자가 많으면 앱에서 보면 안좋지 않아?", "계정삭제도 넣어도 되는거 아닌가?")

## 결정
- 관리자 대시보드는 웹(Trovapp/trova-frontend `/admin`)에 만들고 Cloudflare Pages(무료)에 배포한다. 앱에는 넣지 않는다.
- 웹 로그인은 1회용 교환 코드(60초, 1회)로 JWT를 받는다. 돌아갈 웹 주소와 CORS는 설정 한 곳만 허용한다.
- 서버 상태는 서버가 5분마다 `server_metric_snapshots`에 남기고 30일 지나면 지운다. 운영 서버에 Prometheus·Grafana를 띄우지 않는다.
- 관리자 조치(여행 삭제, 계정 삭제, 재실행, 멈춘 작업 정리, 초안 숨기기)는 미리보기 → 사유·재확인 → 실행 순서로만 하고 `admin_action_logs`에 남긴다. 감사 기록에는 개인정보를 남기지 않는다.
- AI 보조는 서버에서는 Gemini 무료 한도 안에서(관리자 몫 하루 상한), 코드 조사·수정은 로컬 Claude Code 플러그인(opsflow)으로 한다.

## 이유
- 이용자가 늘면 표로 찾아 들어가는 작업이 많아지고, 관리자 화면을 고칠 때마다 앱을 다시 배포해야 하는 부담이 크다 — 웹이 낫다(사용자 판단).
- 웹 로그인이 지금 동작하지 않는다(백엔드가 JWT로 바뀐 뒤 로그인 성공 시 앱 주소로만 토큰을 줌). 토큰을 주소에 그대로 넣으면 브라우저 기록·로그에 남으므로 교환 코드를 쓴다.
- Vercel 무료(Hobby) 플랜은 개인·비상업 용도만 허용([Vercel 문서](https://vercel.com/docs/plans/hobby), 2026-10-11 확인) — 여행 패스 수익 모델([0007](0007-travel-pass-bm.md))과 부딪힌다. Cloudflare Pages 무료는 빌드 월 500회([공식 한도](https://developers.cloudflare.com/pages/platform/limits/)), 상업적 사용을 막는 조항은 찾지 못함 — 배포 전에 약관을 다시 확인한다.
- E2.1.Micro 남은 메모리 약 300MB([0005](0005-deploy-e2-micro-systemd.md)) — 모니터링 스택을 같이 띄우면 서비스가 죽을 수 있다.
- 사용자 요청 처리를 DB 직접 수정으로 하면 실수와 기록 누락이 생긴다. 탈퇴는 개인정보처리방침상 "지체 없이 파기"라 관리자가 대신 처리할 수 있어야 하고, 같은 `UserAccountService.withdraw`를 재사용한다.
- 비용 0원([0002](0002-cost-zero-free-tiers.md)): 서버에 유료 AI API를 넣지 않는다. Gemini 한도는 서비스와 함께 쓰므로 관리자 몫에 상한을 둔다.

## 비교한 대안
1. 앱 안의 관리자 탭 — 로그인·호스팅이 필요 없지만, 이용자가 늘면 화면이 좁고 고칠 때마다 앱 배포가 필요하다.
2. Mac 로컬 HTML(devflow) — 가장 빠르지만 이 Mac에서만 보이고, 실행할 때마다 운영 DB를 직접 읽는다.
3. 운영 서버에 Grafana — 그래프는 강력하지만 메모리 부족 위험.
4. 백엔드가 관리자 페이지를 직접 제공 — 프론트엔드 코드는 이 레포에 두지 않는다는 규칙(CLAUDE.md)과 부딪힌다.
5. 웹 로그인에 토큰을 주소 조각(#)으로 전달 — 구현은 쉽지만 토큰이 기록·화면 공유에 노출될 수 있다.

## 다시 볼 조건
- 운영 서버가 Ampere A1 등 메모리가 넉넉한 서버로 옮기면 Prometheus·Grafana를 다시 검토한다.
- 관리자가 2명 이상이 되면 역할 체계(Role)와 조치별 권한을 검토한다.
- 관리자 AI가 하루 상한에 자주 닿으면 규칙 분류를 늘리거나 상한을 다시 정한다(유료 전환은 사용자에게 먼저 묻는다).
