# 0055 대화 카드를 먼저 스트리밍하고 세션 처리를 직렬화한다

2026-11-25 · 확정 · 관련 ADR 0009, 0054 · PR #539

대안 검색 도구가 반환한 카드를 두 번째 Gemini 답장 생성 전에 SSE로 보낸다. 기존 POST 응답 계약은 유지한다. 빈 후보 목록은 `cards`의 빈 배열로 보내고, 후보가 없는 선호 저장은 `reply`, `done`만 보낸다. 스트림에 이벤트 재생과 자동 재전송은 없다. 재시도는 새 턴을 만들므로 클라이언트가 명시적으로 요청한다.

동시 처리 상한은 기본 사용자당 3개, 전체 256개이며 단일 JVM에서만 보장한다. 상한을 넘으면 스트림을 시작하기 전에 일반 JSON 오류와 X-Trace-Id를 포함한 HTTP 429를 반환한다. 여러 JVM으로 확장할 때는 공유 상한과 세션 저장·라우팅을 다시 정해야 한다.

HTTP 연결 수명과 수락한 턴의 처리 수명을 분리한다. 연결이 끊기거나 60초 emitter 제한에 도달해도 시작한 작업은 히스토리 저장까지 진행하며, 완료할 때까지 슬롯을 점유한다. MVC 초기화 실패로 아직 시작하지 않은 작업은 실행하지 않고 슬롯을 한 번 반환한다. 정상 완료와 실패도 finally에서 슬롯을 반환한다.

기존 POST와 SSE가 같은 세션의 공정 ReentrantLock을 공유해 Gemini 호출·도구 실행·히스토리 갱신을 한 턴씩 실행한다. 잠금 대기는 최대 30초이며 초과 시 429, 중단 시 인터럽트를 복원하고 503으로 끝낸다. 잠금은 finally에서 해제한다. JDK 21 가상 스레드가 HTTP·JDBC 대기 중 캐리어를 고정하지 않도록 외부 호출을 synchronized 블록에 넣지 않는다. 상한 관리에만 짧은 모니터를 사용하고 그 안에서는 외부 I/O를 하지 않는다.

기존 POST의 표시 후보는 성공 응답의 candidates를 기준으로 기록한다. 두 번째 Gemini 생성이 실패해 폴백 응답에 후보가 없으면 표시 후보 ID와 요약도 기록하지 않는다. SSE는 전송 계층이 cards 전송 성공을 반환한 경우에만 표시 후보로 기록하며, 이후 폴백이어도 이미 전송한 후보는 유지한다. 전송 성공은 서버 emitter의 수락을 뜻하고 클라이언트의 실제 수신 확인을 뜻하지 않는다.
