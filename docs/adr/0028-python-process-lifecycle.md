# 0028 보조 Python도 소유 프로세스 종료 확인 뒤 출력과 파일을 처리한다

- 상태: 확정 · 날짜: 2026-11-01 · 관련: #284, 기존 #264 프로세스 정리 원칙 확장

## 결정
리뷰 요약·태깅·선택·검증·일정 생성은 공통 JSON Python 실행기를 사용한다. stdout reader 스레드 대신 파일을 사용하고, 정상·실패·인터럽트·시간초과 시 부모/관찰 자식의 종료를 확인한 뒤 출력 수집 및 소유 작업 폴더를 정리한다. 종료 미확인 시 입력/출력을 보존한다.

기존 PipelineRunner와 부모/관찰 자식 종료 helper를 공유한다. 종료 대기 예산은 기존 5초, 보조 실행 제한은 기존 2분, 주 파이프라인은 기존 5분이다. 외부 API 호출/재시도/입력 payload와 결과 형식은 바꾸지 않는다.

작업 폴더는 새로 생성한 요청만 소유하며 이미 존재하는 폴더는 덮거나 지우지 않는다. 호출자는 기존처럼 요청 식별자를 고유하게 부여한다. 미확인 종료의 파일을 후속 재시도로 훼손하지 않기 위한 선택이다.

## 한계
관찰 전 분리/재부모화와 새 fork, JVM SIGKILL, OS가 신호를 거부하는 경우까지 원자적으로 제어하는 프로세스 그룹 보장은 아니다. 종료 미확인 파일은 자동 삭제하지 않으므로 원인 확인 뒤 별도 정리가 필요하다. 새 외부 서비스/의존성/스키마를 도입하지 않는다.
