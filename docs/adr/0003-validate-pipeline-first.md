# 0003 파이프라인 검증 먼저, 그다음 API·배포
- 상태: 확정 · 날짜: 2026-08 · 근거: CLAUDE.md "개발 순서", `pipeline-test/`

## 결정
1. URL → 오디오·자막 → STT → 장소 추출이 실제로 쓸 만한지 로컬 스크립트로 20~30개 샘플을 먼저 검증한다.
2. 검증되면 Spring Boot API로 옮긴다.
3. 배포는 API가 로컬에서 안정적으로 동작한 뒤에 한다.

## 이유
- 검증되지 않은 파이프라인 위에 서버 구조부터 짜면, 정확도가 안 나올 때 구조째 버리게 된다.

## 다시 볼 조건
- 새 AI 단계(예: 예약 에이전트)를 붙일 때도 같은 순서를 따른다.
