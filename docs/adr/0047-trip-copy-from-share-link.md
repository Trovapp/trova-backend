# 0047. 공유 링크에서 내 여행으로 복사

- 상태: 확정 · 날짜: 2026-11-17 · 근거: 이슈 #446, 사용자 결정
- 관련: [0046](0046-trip-share-link.md), [복사 설계](../superpowers/specs/2026-11-17-trip-copy-design.md)

## 결정

링크 받은 사람은 로그인 후 자기 소유의 **사본**을 가진다. 공동 편집이나 실시간 동기화는 제공하지 않는다. 이후 원본 수정·삭제·링크 해제는 이미 만든 사본에 영향을 주지 않는다. 자기 여행도 복사할 수 있다.

사본은 공개 응답 범위인 제목·날짜·일차·장소·순서·시간·이동수단만 보존한다. memo·savedPlaceId·googlePlaceId·space는 복사하지 않고 장소 출처는 MANUAL로 저장한다. 켜진 링크와 정지되지 않은 소유자를 기존 findPublic으로 확인한다.

사용자당 한국 시간 하루 복사 한도는 기본 20회(감으로 정함)이며 장소 호출 한도와 별도로 센다. 공개 조회와 IP당 분당 한도를 공유한다. 현재 한도는 단일 JVM 메모리 기준으로 서버 재시작 시 초기화된다.

## 이유

사용자가 정한 구조는 "받은 사람이 Trova 열면 내 여행에 담기는 구조"다. 읽기 전용 링크 위에 가장 작은 추가로 이를 제공할 수 있다. 공동 편집 권한 모델을 새로 만들 필요가 없고, 받은 사람이 사본을 고쳐도 원본 소유자의 일정과 개인 정보가 보호된다.

## 비교한 대안

- 공동 편집 초대: 여러 사람이 원본을 고칠 수 있으나 초대·역할·권한 철회·동시 수정 처리가 필요하다. 현재 결정인 내 여행 사본보다 범위가 크다.
- 구독형 보기(원본 바뀌면 따라감): 원본의 최신 상태를 계속 볼 수 있지만 받은 사람의 수정과 원본 변경을 어떻게 합칠지 정해야 한다. 독립적인 내 여행 요구에 맞지 않는다.

## 다시 볼 조건

함께 편집해 달라는 요청이 쌓이면 공동 편집 초대와 권한 모델을 다시 검토한다. 서버가 여러 대가 되면 메모리 한도를 공유 저장소로 옮기는 것도 검토한다.
