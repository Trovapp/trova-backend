# 0062. 사용자별 목록 응답을 단일 JVM에서 20초간 재사용한다

2026-11-28 · 확정 · #563

## 조회

장소·북마크·여행 GET은 인증과 사용자 존재 확인 후 사용자 ID와 목록 종류로 응답 DTO를 찾는다. 목록별 보관 한도는 512행이며 빈 배열도 한 행으로 계산한다. 성공한 결과는 20초간 재사용한다.

같은 키의 첫 요청이 Caffeine 맵에 future를 등록하고, 맵 잠금을 놓은 뒤 요청 스레드에서 DB를 읽는다. 같은 키의 후속 요청은 그 결과나 예외를 공유한다. 대기자 수로 조회를 거절하지 않는다. 실패한 조회는 다음 요청에서 재시도한다. 읽기 트랜잭션을 이미 연 호출자는 자기 트랜잭션에서 직접 읽는다.

## 쓰기와 공유 권한

Hibernate 변경 콜백에서 영향 범위를 같은 Spring 쓰기 트랜잭션에 모은다. 성공 커밋 시 우선순위가 높은 `TransactionSynchronization.afterCommit`에서 캐시 항목을 제거한다. 여행 변경 SSE를 발행하는 `@TransactionalEventListener`는 이 뒤에 실행된다. 롤백은 캐시를 유지한다. 쓰기 전에 시작한 조회는 제거된 future만 완료하므로 새 항목을 덮어쓰지 않는다.

- 저장 장소와 북마크의 추가·수정·삭제는 해당 소유자의 해당 목록을 무효화한다. 분석 단계 업데이트와 새 카탈로그 장소 삽입은 영향을 주지 않는다.
- 기존 카탈로그의 북마크 표시 필드가 바뀌면 그 장소를 포함한 북마크 목록을 무효화한다. 아직 결과가 없는 진행 중 북마크 조회도 다시 읽을 수 있게 한다. 좌표 복구와 공간 태그 벌크 UPDATE는 실제 갱신된 장소 ID를 트랜잭션 안에서 알린다.
- 여행·일차·여행 장소 변경은 확인된 멤버들의 여행 목록을 무효화한다. 멤버를 로딩하지 않은 쓰기, 멤버 제거·변경, 공유 프로필 변경에서는 여행 목록 전체를 무효화한다. 이때 장소·북마크 목록은 유지한다.

즉시 반영은 단일 JVM의 Spring 관리 쓰기 트랜잭션에 적용된다. 목록에 영향을 주는 벌크 SQL을 추가할 때 변경 알림도 연결한다. 다중 인스턴스나 외부 쓰기를 도입할 때는 인스턴스 간 무효화가 필요하다.

## 운영

필수 운영 설정 변경은 없다. 읽기 전용·쓰기 혼합 부하를 각각 측정하고, GET 지연·처리량·CPU와 함께 429·5xx·클라이언트 타임아웃을 확인한다.
