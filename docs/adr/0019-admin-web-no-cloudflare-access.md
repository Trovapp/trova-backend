# 0019 관리자 웹 앞의 Cloudflare Access는 붙이지 않는다 (0012 일부 변경)
- 상태: 확정 · 날짜: 2026-10-20 · 근거: 이슈 #224, 사용자 결정("꼭 연결해야하나?", 이유를 듣고 "응 그렇게 정리하고 진행해줘")

## 결정
- ADR 0012와 설계(`docs/superpowers/specs/2026-10-11-admin-dashboard-design.md` 보안 표)의 "관리자 웹 앞에 Cloudflare Access(이메일 1회용 코드)"는 하지 않는다.
- 관리자 데이터·조치는 지금처럼 백엔드 `/api/admin/**`가 지킨다: 관리자 명단(`ADMIN_USERS`), 관리자 웹 전용 토큰(1시간·`aud=admin-web`), 위험 조치는 로그인 후 10분 안, 요청 횟수 제한, 감사 기록, 전수 권한 테스트.
- 대신 관리자 카카오 계정에 2단계 인증을 켠다(계정 설정, 코드 변경 없음).

## 이유
- Access는 관리자 웹(`admin.trovapp.workers.dev`)의 정적 파일만 막는다. 그 파일에는 비밀값도 데이터도 없다.
- 백엔드(Oracle 서버, Caddy가 직접 받음)는 Access를 거치지 않는다. 관리자 카카오 계정을 빼앗긴 경우 공격자는 백엔드 로그인 흐름으로 1회용 코드를 받아 백엔드에 바로 교환할 수 있어, 웹 앞의 Access로는 막히지 않는다. 설계에서 말한 "두 겹"이 실제로는 한 겹이다.
- 진짜 두 겹이 되려면 백엔드가 Access 토큰까지 검사해야 하고, 그러려면 운영 서버를 Cloudflare 뒤(터널·프록시)로 옮겨야 한다 — 관리자 1명인 지금 규모에 비해 일이 크다.
- 2026-10-20 설정을 시도했을 때 Workers의 Access는 Zero Trust 가입(플랜 선택)부터 필요했다. 무료 플랜($0, 50명)이 있지만 계정에 새 서비스가 하나 늘어난다.

## 비교한 대안
1. 웹 앞에만 Access — 위 이유로 막아 주는 것이 거의 없다.
2. 운영 서버를 Cloudflare Tunnel 뒤로 옮기고 백엔드가 Access 토큰 검사 — 실제 두 겹이지만 배포 구조(ADR 0005)와 앱·PWA 요청 경로까지 바뀐다.
3. 백엔드에 관리자 전용 2단계 인증(TOTP 등) — 코드와 시험이 늘어난다. 관리자가 늘면 다시 본다.

## 다시 볼 조건
- 관리자가 2명 이상이 되거나, 외부 사람(외주·운영 인력)이 관리자 웹을 쓰게 되면.
- 운영 서버가 Cloudflare 뒤로 옮겨지면(그때는 대안 2가 싸진다).
