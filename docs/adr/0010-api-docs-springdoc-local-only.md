# 0010 API 문서는 springdoc으로 자동 생성, 운영 서버에서는 끈다
- 상태: 확정 · 날짜: 2026-10-08 · 근거: 이슈 #149, SDD 검토 ③, #27(actuator 공개 범위)

## 결정
- 엔드포인트 문서는 손으로 쓰지 않고 springdoc-openapi가 컨트롤러에서 만든다(`/v3/api-docs`, `/swagger-ui.html`).
- 기본은 꺼져 있고 `API_DOCS_ENABLED=true`일 때만 켜진다. 로컬에서만 켜고, 운영 서버는 꺼 둔다.
- 켜졌을 때 문서 경로만 로그인 없이 열고, 다른 API는 그대로 로그인이 필요하다. 문서에는 `/api/**`만 담는다.
- Swagger UI에서는 앱 로그인 토큰(JWT, `Authorization: Bearer`)으로 호출해 본다.

## 이유
- 엔드포인트 목록은 코드가 기준이라 따로 적지 않기로 했다(CLAUDE.md). 손으로 쓴 목록은 코드와 달라졌었다(#143에서 확인) — 코드에서 바로 만들면 어긋나지 않는다.
- springdoc은 오픈소스라 비용이 없다([0002](0002-cost-zero-free-tiers.md)). Spring Boot 4.1에 맞는 3.1.1을 쓴다.
- 운영 서버에서 API 구조가 로그인 없이 공개되면 공격 표면이 넓어진다. #27에서 prometheus가 기본 공개됐던 것과 같은 실수를 막으려고 같은 방식(환경 변수로 켜기)을 따른다.

## 비교한 대안
1. 운영에서도 공개 — 앱·웹 개발자가 한 명이라 공개할 이득이 없다.
2. 운영에서 켜고 관리자만 보기 — 관리자 확인을 문서 경로에 붙이는 코드가 늘어난다. 지금은 로컬에서 보면 충분하다.
3. 로컬에서만 켜기(선택).

## 다시 볼 조건
- 외부 개발자(협업자·제휴)에게 API를 보여줘야 할 때 — 그때 운영 공개 범위를 다시 정한다.
