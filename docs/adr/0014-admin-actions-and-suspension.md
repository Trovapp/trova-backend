# 0014. 관리자 조치 범위: 사용자 상세(가린 값)·계정 정지 추가, 조회도 기록, 멈춘 작업 정리는 빼기

- 상태: 확정
- 날짜: 2026-10-12
- 관련: #167, 설계 [2026-10-11-admin-dashboard-design.md](../superpowers/specs/2026-10-11-admin-dashboard-design.md) 2단계, [0012](0012-admin-dashboard-web.md)

## 결정
- 2단계 관리자 조치는 여행 삭제, 계정 삭제(탈퇴 대신), 실패한 분석 다시 실행, 자동 초안 숨기기에 **계정 정지/정지 풀기**를 더한다.
  정지하면 그 계정의 앱·웹 토큰과 단축어 키가 바로 막히고(키는 지운다) 다시 로그인할 수 없다. 관리자 계정은 정지·삭제할 수 없다.
- **사용자 찾기·상세**는 읽기 전용으로 가입 경로·가입일·최근 활동·건수·조치 이력을 보이고, 닉네임은 첫 글자만 남기고 가린다.
  로그인 ID(제공자 고유번호)·프로필 사진은 보이지 않는다. 개인정보를 파일로 내려받는 기능은 만들지 않는다.
- 사용자 찾기·상세 열람도 감사 기록(`admin_action_logs`)에 남긴다(검색어는 남기지 않고 결과 건수만). 감사 기록은 앱에서 지우는 경로를 만들지 않고 최소 1년 보관한다.
- 실행(쓰기) 조치는 관리자 웹 토큰을 받은 지 10분 안일 때만 된다. 지나면 다시 로그인한다.
- 설계에 있던 "멈춘 작업 정리" 조치는 뺀다 — 서버가 5분마다 15분 넘게 멈춘 작업을 자동으로 실패 처리한다(`OrphanedJobRecoveryService`).

## 이유
- 사용자 요청(2026-10-12): "사용자에 대한 설정을 할 수 있는 게 없네" → 다른 서비스 관리자 페이지 조사. 흔한 사용자 관리 기능은 목록·상세·정지/차단·역할·대신 보기·조치 기록이었다(MakerKit·Forest Admin·Stripe 문서).
  1인 운영이라 역할(RBAC)·대신 보기는 실익이 없고, Gemini 무료 한도를 마구 쓰는 사용자를 바로 막을 수단(정지)이 없다.
- 개인정보의 안전성 확보조치 기준(2023-9 개정): 개인정보취급자 접속기록 1년 이상 보관·월 1회 점검(제8조), 일정 시간 뒤 접속 차단(제6조). 사용자 상세부터 개인정보를 보게 되므로 열람을 기록하고 화면에서 가린다. 규모 면제가 없는 조항이다.
- 정지 확인은 요청마다 DB를 읽지 않고 서버 메모리의 정지 목록으로 한다 — 운영 서버가 1대(E2.1.Micro)라 충분하다.

## 비교한 대안
1. 정지 대신 계정 삭제만 — 되돌릴 수 없고 사용자 데이터가 사라진다. 오판 위험이 커서 고르지 않았다.
2. 정지를 토큰 블랙리스트로 — 토큰이 여러 개(앱 90일·웹·단축어 키)라 사용자 단위로 막는 편이 단순하다.
3. 관리자 화면 앞에 Cloudflare Access(이메일 1회용 코드) — 이번 범위에서는 하지 않는다. 관리자 계정(카카오) 2단계 인증과 10분 재로그인으로 대신하고, 관리자가 늘면 다시 본다.

## 다시 볼 조건
- 관리자가 2명 이상이 되면 역할(조회만/조치 가능)과 권한 변경 기록(3년 보관)을 넣는다.
- 서버가 2대 이상이 되면 정지 목록을 메모리 대신 DB·공유 캐시로 확인한다.
- 정보주체가 5만 명을 넘으면 접속기록 보관을 2년으로.
