# 0017 안드로이드는 네이티브 앱(같은 Expo 코드), 아이폰은 PWA
- 상태: 확정 · 날짜: 2026-10-14 · 근거: 이슈 #190, 설계 [2026-10-14-android-app-design.md](../superpowers/specs/2026-10-14-android-app-design.md), 사용자 결정("ios는 pwa로 가고 안드로이드는 따로 또 만들어서 앱 출시까지 가고 싶은데", 빌드·설치까지 먼저 / EAS 무료 빌드 / 맥 에뮬레이터 / 앱 알림 이번에 넣기, "진행해줘")
- 바꾸는 결정: [0013](0013-pwa-before-app-store.md)의 "사용자가 늘면 앱스토어 출시로 넘어간다" — 안드로이드는 지금 앱으로 간다. 아이폰은 그대로 PWA.

## 결정
- 안드로이드는 지금 앱(Expo) 코드를 그대로 네이티브 앱으로 빌드해 구글 플레이 출시까지 간다. 아이폰은 PWA(+ 단축어)를 유지한다.
- 빌드는 EAS 무료 플랜(월 15번, 대기열 느림)으로 한다. `preview`(APK, 설치 확인용)·`production`(AAB, 플레이용) 두 가지.
- 확인은 맥의 안드로이드 에뮬레이터(구글 플레이 이미지)로 한다. 안드로이드 폰이 없다.
- 앱 알림은 Expo 푸시(무료)로 보낸다. 웹 푸시(0016)와 같은 알림·같은 이동 규칙을 쓰고, 서버 발송 서비스가 웹 구독과 Expo 토큰 양쪽으로 보낸다.
- 이번 범위는 빌드·설치·동작 확인까지다. 플레이 개발자 등록(1회 약 $25)과 개인 계정의 비공개 테스트(테스터 12명·14일)는 준비되면 따로 한다.

## 이유
- 안드로이드는 앱을 설치하면 공유 목록에 Trova가 바로 뜬다(앱 설정 `androidIntentFilters: text/*`). 아이폰처럼 단축어가 필요 없어 "공유 한 번"에 가장 가깝다.
- 앱 코드는 이미 안드로이드 설정(패키지 `com.trovapp.trova`, 아이콘, 공유 받기)을 갖고 있어 새로 만들 부분이 빌드·알림 정도다.
- EAS 무료 빌드는 맥에 안드로이드 빌드 도구를 갖추지 않아도 된다. Expo 푸시는 무료이고 FCM 연결(Firebase, 무료)만 있으면 된다.

## 검토한 다른 방법
1. 안드로이드도 PWA만 — 설치·공유 받기는 되지만 플레이 스토어에 없어 찾기 어렵고, 사용자가 원하는 "앱 출시"가 아니다.
2. 맥에서 직접 빌드(Android SDK·Gradle) — 횟수 제한은 없지만 도구 설치·유지가 크다. 에뮬레이터만 설치한다.
3. FCM을 서버에서 직접 호출 — Expo 푸시를 거치지 않아 위탁이 하나 줄지만, 서버에 구글 서비스 계정 키를 두고 OAuth 토큰을 관리해야 한다.

## 결과
- 구글 플레이 출시에는 개발자 등록비(1회)가 든다 — 비용 0원 원칙([0002](0002-cost-zero-free-tiers.md))의 예외라 사용자가 결제할 때 진행한다.
- 개인정보처리방침 4항에 Expo(미국, 알림 전달)를 더한다.
- Firebase 프로젝트·서비스 계정 키는 사용자가 콘솔에서 만들고 Expo에 올린다. 키는 레포·서버에 두지 않는다.
