# 0032 로컬 모니터링 기록을 보존하고 수집 중단을 업무 지표 0과 구분한다

- 상태: 확정 · 날짜: 2026-11-01 · 근거: #305, 사용자 요청(모니터링 실습과 이력서에 설명할 수 있는 검증)

## 결정

- ADR 0015의 Mac Prometheus/Grafana + SSH 터널을 유지한다. 운영 서버에 수집기를 추가하지 않는다.
- Compose 프로젝트와 데이터 볼륨 이름을 고정하고, 기존 데이터를 정지 상태에서 이관한다.
- Prometheus는 30일/1GB 보관 제한을 두며 WAL 등 추가 디스크 사용은 별도다.
- 기존 대시보드와 별도로 운영 전용 학습 대시보드를 제공한다. 수집 중단 구간을 업무 지표 0으로 채우지 않는다.
- 운영 대상 수집 실패/누락 1분 경보를 Prometheus에서 평가하고 모의 시계열로 발생/복구를 검증한다.
- 외부 알림 전송과 상시 수집은 이번 범위 밖이다. 연결되지 않은 기능을 완료한 것으로 기록하지 않는다.

## 이유와 한계

실제 컨테이너가 다른 워크트리의 설정을 마운트하고 있었고 운영 SSH 터널이 끊겨 있었다.
Prometheus는 이미지의 익명 볼륨을 사용했고 Grafana에는 데이터 볼륨이 없었다.
고정 볼륨은 재생성 시 데이터 유실을 줄이지만 백업이나 24시간 감시를 대신하지 않는다.
기존 영상 단계 지표는 성공적으로 반환된 Python 결과에 한정되며 전체 작업의 성공률/p95를 입증하지 않는다.
운영 부하 테스트는 한도·진행 작업·자원을 확인한 후 제한된 관찰부터 진행한다. 이번 작업에서는 실행하지 않는다.

## 검증

`monitoring/alerts.test.yml`, Compose/Prometheus 설정 검사, 신규 패널 12개 PromQL 실행,
이관 전 과거 시계열 조회와 기존 패널 보존, 운영 대상 UP 확인.
실제 확인 결과: `docs/monitoring/2026-11-01-monitoring-validation.json`.
