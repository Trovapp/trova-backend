# 0046. 메모리 압박 경보의 짧은 계산 공백을 마지막 유효값으로 잇는다

- 날짜: 2026-11-18 · 상태: **초안, 사용자 승인·Cloud 반영 대기** · 관련: #428, PR #433, ADR 0041·0042
- 본 작업 요청에 따라 레포 규칙 후보를 작성했다. 운영 정책 확정이나 운영 반영을 의미하지 않는다.

## 문제와 제안

r28의 PSI는 첫 Pending(15:49:10) 이후 두 번 공백으로 리셋돼 15:57:10에야 발화했다. 외부 Synthetic은 이미 15:40:50에 발화했다. 이를 누락된 다운 감지로 해석하지 않고 PSI 경보의 연속성 문제로 다룬다.

`HighMemoryPressure`의 PSI instant 계산값이 없을 때만 `last_over_time((원래 PSI 계산식)[5m:1m])`으로 보완한다. 현재 정상값이 있으면 항상 그것을 택한다. 과거 최대값을 유지하는 방식은 짧은 정상 부하까지 2분 조건을 채우게 하므로 쓰지 않는다. 20%·2분·평가 1분, NoData→OK·오류 KeepLast는 유지하고 스왑 보조 B는 제거한다. 수집·앱 코드·유료 서비스는 추가하지 않는다.

배포·재시작은 중지 전부터 UP 및 지표 재수신 확인 뒤 최소 5분까지 종료 시각 있는 PSI 사일런스를 건다. 부하 측정에도 포함한다. 사일런스는 자동화가 아니며 지표 정상화·규칙 Normal 확인 후 끝낸다. 승인 뒤 ADR 0041의 메모리 경보만 이 공백 보완을 예외로 연결하고, 다른 경보의 NoData 정책은 바꾸지 않는다. ADR 0042의 앱 내부 수집 방식도 유지한다.

## 근거·대안·한계

[검토 보고서](../monitoring/2026-11-18-memory-pressure-alert-review.md)에 실제 전이 전체, 원시 전송 공백을 확정할 수 없는 범위, 세 대안, 예상 6분 단축, 무료 비용, 승인할 변경과 롤백을 기록했다.

오래된 압박은 원래 rate 창과 보완 창을 합쳐 약 10분 남을 수 있다. 처음부터 지표가 없거나 장기 공백이면 이 경보는 정상이라 별도 끊김 경보·Synthetic이 필요하다. 짧은 실제 압박 뒤 전송만 끊겨도 발화할 수 있어 계획 재시작 사일런스가 필수다. Cloud 실행 엔진·Slack 동작과 실제 r28 원시 표본 재생은 검증하지 않았다.

## 다시 검토할 조건

공백 보완 때문에 정상 배포/회복 뒤 오탐이 생기거나, 첫 PSI 임계값 도달 전 장애가 반복되거나, 여러 서버로 늘어날 때. 승인 전에는 Cloud가 기존 규칙을 계속 사용한다.
