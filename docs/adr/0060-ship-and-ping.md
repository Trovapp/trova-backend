# 0060 서버 요청의 쉽앤핑 전송

- 날짜 2026-11-26
- 상태 확정
- 이슈 #549

운영자는 서버에 SHIP_AND_PING_KEY를 설정해 요청 관측을 활성화한다. 클라이언트에 키를 배포하지 않는다. Spring의 API 요청 필터에서 메서드, 경로 템플릿, 상태, 경과 시간과 완료 시각을 수집한다. 매핑 전 실패는 기능 지도의 메서드와 경로에 대조한다. 일치하는 항목이 없으면 고정 경로 /api/:id를 사용한다. 두 SSE 연결은 제외한다. 오류 종류는 HTTP 상태 코드 이름이며 실제 예외가 있으면 클래스 이름만 추가한다.

API 스레드는 최대 1,000건 큐에 기록을 넣는다. 별도 작업자가 50건 또는 30초에 전송하며 실제 JSON 바이트가 64KiB를 넘으면 나눈다. 한 묶음은 최대 100건이다. 과부하와 수집 장애 때 기록을 버리고 종료 시 최대 5초간 잔여 기록 전송을 시도한다. 요청 본문, 인증 정보, 계정 정보, 응답 본문, 쿼리와 실제 경로를 전송하지 않는다.

배포 식별자는 Gradle build-info의 빌드 시각이다. 관리자는 운영 환경 변수를 설정한 셸에서 `python scripts/send_shipandping_feature_map.py`를 한 번 실행하고 HTTP 202를 확인한다. 기능 지도는 서버 시작과 분리한다.

## 확인 방법

ShipAndPingTest는 루프백 수집 서버에서 요청 스키마, 제외 경로, 오류 및 비동기 전송 경계를 검사한다.
