# 0026 관리자 DB 변경과 실행 감사는 함께 커밋하고 큐 전달은 커밋 뒤에 한다

- 상태: 확정 · 날짜: 2026-10-31 · 관련: #271, ADR 0014의 감사 의무 보강

## 결정
- 조치 서비스의 입력/확인 토큰 검증 뒤 별도 트랜잭션 서비스가 핸들러 DB 변경과 감사 저장을 함께 수행한다. 어느 쪽이 실패하면 둘 다 롤백한다. 사용한 확인 토큰은 되살리지 않는다.
- 조회/로그인용 독립 감사(REQUIRES_NEW)는 유지한다. 실행 감사는 기존 조치 트랜잭션에 참여하도록 MANDATORY 메서드를 사용한다.
- 재실행은 새 작업과 생성 감사를 먼저 커밋하고 afterCommit에서 ShareJobQueue.enqueue를 호출한다. 커밋 전이나 감사 롤백 시 큐를 부르지 않는다.
- 큐 거절 시 별도 새 트랜잭션으로 새 작업 삭제와 거절 감사를 함께 남긴다. 생성과 거절 기록이 모두 남으며 요청은 기존 409다. 정지 목록 추가/제거는 커밋 뒤에 반영한다.

## 한계
DB와 브로커 사이의 분산 트랜잭션이나 outbox를 도입하지 않는다. 생성 커밋 직후 프로세스가 죽으면 enqueue를 못 할 수 있고 기존 멈춘 작업 복구 정책이 적용된다. 큐 거절 뒤 DB까지 실패하면 새 작업/생성 감사가 남고 오류를 전파한다. 현재 감사 의무의 로컬 트랜잭션 누락을 고치는 범위이며 exactly-once 전달 보장은 아니다.
