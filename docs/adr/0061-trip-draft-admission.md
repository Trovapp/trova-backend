# 0061. 일정 초안 접수를 DB 사용자 행 잠금으로 직렬화한다

확정일 2026-11-27 · 관련 이슈 #551, QA PR #552

## 결정

같은 사용자의 같은 원본 초안에서 진행 중인 다시 짜기는 하나만 허용한다. 대기·처리·질문 대기 상태에서 다른 요청을 받으면 조건이 같아도 409와 기존 작업 ID를 반환한다. 성공과 실패 모두 새 요청을 허용한다. 앱이 응답 유실로 같은 작업을 재시도할 수 있도록 선택 UUID 키를 지원한다. [API 계약](../api/trip-draft-admission.md)

접수 트랜잭션의 첫 조회가 사용자 행을 쓰기 잠금으로 읽는다. 잠금을 획득한 뒤 사용자·키로 최근 24시간의 최초 접수를 찾고, 그다음 사용자·원본으로 진행 작업을 찾는다. 키는 사용자 단위여서 원본이 달라도 같은 키가 동시에 새 초안 두 개를 만들 수 없다. 잠금은 입력 검증과 초안 INSERT까지 유지한다. 큐 전달과 외부 모델 호출은 잠금을 놓은 뒤에 한다. 새 접수만 큐로 보내며, 저장 직후 프로세스가 내려간 경우는 기존 대기열 복구 절차를 따른다. [ADR 0043](0043-job-handoff-outbox-or-sweeper.md)

작업 ID와 키는 초안 한 행에 함께 저장한다. 최초 접수 시각으로 만료를 판정하고 한 시간마다 만료된 키 값을 지운다. 초안의 나머지 내용과 작업 ID는 그대로 보존한다. 예전 버전이 만든 진행 초안도 기존 교체 원본 번호로 찾는다. 홈에 노출하지 않는 직접 생성 초안은 원본 번호를 별도로 기록해 홈 노출 규칙을 유지한다. 이미 여러 건이 진행 중인 이전 데이터에서는 가장 먼저 만든 진행 작업 ID를 안내한다.

## 적용 범위

이 API의 중복 접수는 여러 서버가 같은 DB를 쓰는 경우에도 직렬화해야 한다. 접수 중 같은 사용자의 다른 원본 요청도 잠깐 기다릴 수 있다. 원본이 다르면 각 작업의 생성과 처리는 독립적으로 진행한다. 승인된 여행의 장소 재구성과 장소 상세 생성은 각각 기존 정책을 따른다. [ADR 0025](0025-replan-admission-quota.md) · [ADR 0027](0027-place-details-single-flight.md)
