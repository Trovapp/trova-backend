# 0061. 일정 초안 접수를 DB 사용자 행 잠금으로 직렬화한다

확정일 2026-11-27 · 관련 이슈 #551, QA PR #552·#553

## 결정

같은 사용자의 같은 원본 초안에서 진행 중인 다시 짜기는 하나만 허용한다. 대기·처리 중인 원본에 다른 본문이 들어오면 409와 기존 작업 ID를 반환한다. 질문 대기 중에는 새 요청이 유효할 때 이전 질문을 종료한다. 질문 답변과 새 접수는 같은 초안 행을 잠가 한쪽만 재개하게 한다. 성공과 실패 뒤에는 본문 재생 시간이 지나면 같은 내용도 새로 접수한다. 앱이 응답 유실로 같은 작업을 재시도할 수 있도록 선택 UUID 키를 지원한다. [API 계약](../api/trip-draft-admission.md)

접수 트랜잭션의 첫 조회가 사용자 행을 쓰기 잠금으로 읽는다. 잠금을 획득한 뒤 사용자·키로 최근 24시간의 최초 접수를 찾고, 그다음 사용자·원본으로 진행 작업을 잠그고 사용자·본문 해시로 최근 접수를 찾는다. 키는 사용자 단위여서 원본이 달라도 같은 키가 동시에 새 초안 두 개를 만들 수 없다. 잠금은 입력 검증과 초안 INSERT까지 유지한다. 큐 전달과 외부 모델 호출은 잠금을 놓은 뒤에 한다. 새 접수만 큐로 보내며, 저장 직후 프로세스가 내려간 경우는 기존 대기열 복구 절차를 따른다. [ADR 0043](0043-job-handoff-outbox-or-sweeper.md)

앱 재설치나 응답 유실로 UUID가 달라지거나 사라져도, 최초 접수부터 10분 미만이면 같은 본문의 작업 ID를 202로 재생한다. 원본 없는 직접 생성에도 적용한다. 요청 시점의 영상 ID 집합(중복 제거 후 숫자순), 원본 번호(생략은 null), 날짜와 조건이 들어 있는 메시지(연속 공백을 한 칸으로 합치고 양끝 공백 제거)를 UTF-8로 인코딩해 SHA-256 해시를 저장한다. 답변으로 영상 목록이 달라져도 해시는 바뀌지 않는다. 배포 전에 접수한 행은 최초 영상 목록을 복원할 수 없어 해시를 소급하지 않는다.

READY·FAILED·APPROVED와 질문 대기에도 같은 10분 창을 적용한다. 빠르게 끝난 작업도 응답을 잃은 앱이 복구할 수 있고, 10분부터는 완료한 작업과 동일한 내용을 의도적으로 다시 만들 수 있다. 재생은 만료 시각을 연장하지 않는다. 창이 끝났어도 대기·처리 중인 동일 원본은 409다. 같은 원본에서 다른 조건으로 이미 진행 중인 작업이 있으면 이전 완료 작업의 본문과 일치해도 그 진행 작업의 충돌 정책이 우선한다.

작업 ID와 최초 키는 초안 한 행에 함께 저장한다. 본문 재생 시 처음 받은 UUID도 별도 키 테이블에서 그 작업 ID에 연결해, 이후 24시간 키 복구 계약을 최초 접수 시각 기준으로 유지한다. 최초 접수 시각으로 만료를 판정하고 한 시간마다 만료된 키 값을 지운다. 초안의 나머지 내용과 작업 ID는 그대로 보존한다. 예전 버전이 만든 진행 초안도 기존 교체 원본 번호로 찾는다. 홈에 노출하지 않는 직접 생성 초안은 원본 번호를 별도로 기록해 홈 노출 규칙을 유지한다. 이미 여러 건이 진행 중인 이전 데이터에서는 가장 먼저 만든 진행 작업 ID를 안내한다.

구버전은 비노출 원본 번호를 저장하지 않았다. 신버전이 만든 행은 `source_tracked`로 구분한다. 비노출 원본보다 나중에 같은 사용자가 직접 만든 구버전 초안 중 두 원본 번호가 모두 비어 있는 후보를 답변 API와 같은 쓰기 잠금으로 읽는다. 영상과 조건을 바꿔 다시 짤 수 있으므로 입력만으로는 원본 관계를 확정할 수 없다. 후보에 대기·처리 중인 작업이나 마지막 갱신 후 24시간 미만인 질문이 있으면 질문을 보존하고 503과 재시도 시간을 반환한다. 답변이 먼저 접수된 작업은 완료 후 새로 접수할 수 있다. 사용자가 질문을 다시 열 수 없어도 새 접수가 무기한 막히지 않도록, 남은 후보가 모두 24시간 이상 응답이 없는 질문이면 유효한 새 접수와 함께 만료시킨다. 만료 기준에는 접수 시각 대신 질문의 마지막 갱신 시각을 쓴다. 이 전환 기간에는 다른 일정의 구버전 질문도 접수를 지연시킬 수 있고, 답변 없이 만료 시간이 지나면 함께 종료될 수 있다.

작업자는 PENDING에서 처리를 시작할 때 행 잠금 아래 처리 회차를 올린다. PROCESSING 재전달은 같은 회차를 이어서 실행한다. 구버전 행은 처음 처리할 때 1회차로 초기화한다. 외부 호출 후 상태가 PROCESSING이고 회차가 일치해야 결과를 기록한다. READY 기록과 원본 닫기는 한 트랜잭션에서 수행하고, 정리기는 현재 상태와 마지막 갱신 시각을 조건으로 실패 처리한다.

## 적용 범위

이 API의 중복 접수는 여러 서버가 같은 DB를 쓰는 경우에도 직렬화해야 한다. 접수 중 같은 사용자의 다른 원본 요청도 잠깐 기다릴 수 있다. 원본이 다르면 각 작업의 생성과 처리는 독립적으로 진행한다. 승인된 여행의 장소 재구성과 장소 상세 생성은 각각 기존 정책을 따른다. [ADR 0025](0025-replan-admission-quota.md) · [ADR 0027](0027-place-details-single-flight.md)
