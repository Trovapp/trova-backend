# 0054 여행 변경을 SSE로 알리고 Kafka로 서버 간 전달한다

2026-11-21 · 채택 · 관련 ADR 0021, 0053

앱의 쓰기는 기존 HTTP API를 사용한다. 열린 상세 화면에는 서버가 변경 사실과 커밋된 여행 버전을 SSE로 보낸다. 변경 기록을 저장한 트랜잭션이 커밋된 뒤에만 이벤트를 발행한다. 브라우저 EventSource는 인증 헤더를 지정할 수 없어, 로그인 상태에서 사용자·여행·원래 인증 만료 시각에 묶인 60초 일회용 표를 발급한다.

메모리 모드에서는 현재 프로세스의 구독자에게 전달한다. Kafka 모드에서도 로컬 구독자에게 즉시 보내고, 같은 이벤트를 tripId 키로 발행한다. 각 서버는 호스트 이름으로 정한 고정 그룹에서 구독하고 자기 발행분은 건너뛴다. 호스트 이름을 공유하는 인스턴스에는 각각 고유한 고정 이름을 APP_SERVER_NAME으로 지정한다. 그룹이 저장한 오프셋이 있어도 파티션을 할당받으면 끝에서 수신을 시작한다. 브로커 오류나 확인 시간 초과 뒤에는 1분간 로컬 전달만 수행한다. 클라이언트는 재연결 시 최신 상세를 조회하므로 토픽의 과거 기록을 재생하지 않는다.

각 연결은 전용 송신 실행기에서 한 번에 하나씩 쓴다. 대기열 8칸이 차거나 전송이 25초 이상 걸리는 것을 감지하면 해당 연결을 종료한다. 커밋 이벤트 작업 큐가 포화되면 여행별 최신 버전을 최대 1,000개 여행까지 보관하고 빈 자리가 생길 때 재시도한다. 새 버전이 들어온 지 60초가 지난 항목은 만료된다. 상한에 도달하면 갱신 시각이 가장 오래된 여행을 뺀다. 각 서버는 25초 heartbeat 때 멤버 목록과 커밋 버전을 함께 읽는다. 직전 heartbeat에서 관측한 버전까지 여전히 전달하지 못한 연결은 닫으며, 해당 클라이언트가 재접속하면서 최신 일정을 조회한다. 로컬 구독자 조회 오류가 발생해도 Kafka 발행은 진행한다. 편집 푸시는 날씨·초안 푸시와 별도 큐에서 처리한다. 큐가 가득 차면 새 편집 알림의 누락을 경고와 trova.trip-push.discarded에 기록한다. 삭제 알림은 이때 호출 스레드에서 발송한다. 수신자의 모든 기기에서 발송이 실패하면 다음 편집에서 즉시 다시 시도할 수 있다.

현재 단일 서버 배포에서 열린 상세 화면과 푸시 억제 기간은 메모리로 관리한다. Expo는 기존 등록 토큰에만 발송하며 수신을 끄고 등록을 해제한 기기는 대상에서 빠진다. 푸시는 변경을 커밋한 서버에서만 발송한다. 여러 서버로 확장할 때는 표 발급과 사용을 같은 서버로 라우팅하고, 다른 서버에서 접속 중인 사용자까지 푸시를 억제하려면 접속 상태와 5분 창을 공유해야 한다. 브로커 단절 중에는 다른 서버가 받은 변경을 재접속 조회로 복구한다.
