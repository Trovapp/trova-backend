# 0046. 여행 읽기 전용 공유 링크

- 상태: 확정 · 날짜: 2026-11-17 · 근거: 이슈 #444, 사용자 제공 설계
- 관련: [0013](0013-pwa-before-app-store.md), `docs/superpowers/specs/2026-11-17-trip-share-link-design.md`

## 배경

여행 소유자가 다른 사람에게 로그인 없이 일정을 보여줄 링크가 필요하다. 편집 권한과 개인 메모는 공유하지 않는다.

## 결정

- 소유자만 공유 링크를 조회·생성·해제한다. 다른 사람의 여행과 없는 여행은 모두 404다.
- 링크는 읽기 전용이다. 공개 API는 인증 객체나 CurrentUserService를 사용하지 않는다.
- SecureRandom 32바이트를 Base64url 패딩 없이 인코딩한 43자 토큰을 사용한다.
- 토큰 원문을 DB에 저장한다. ShareKey는 발급 때만 원문을 보여주고 해시를 저장하지만, 여행 공유 링크는 사용자가 나중에도 같은 링크를 다시 봐야 한다. 유출 시 가능한 작업은 해당 여행의 읽기 전용 보기뿐이다.
- 여행당 켜진 링크는 하나다. 반복 생성은 기존 링크를 돌려준다. 해제는 revokedAt을 기록하고, 다시 켜면 새 토큰을 발급한다.
- 공개 응답은 여행 제목·날짜, 일차, 지정된 장소 정보만 포함한다. id·memo·source·googlePlaceId·사용자 정보는 제외한다.
- PWA 경로는 `/t/{token}`이다. `app.web-app-url` 끝의 슬래시를 제거해 붙이며, 설정이 비면 상대 경로를 돌려준다.
- 공개 조회는 기존 RequestRateLimiter로 IP당 분당 60회 제한한다. `APP_SHARE_LINK_PUBLIC_PER_MINUTE`로 조정하며 초과하면 429와 `Retry-After: 60`을 돌려준다.
- 여행 삭제 시 켜진 링크와 해제된 링크를 모두 먼저 삭제한다. 테이블 생성은 기존 ddl-auto에 맡긴다.

## 결과와 한계

링크를 아는 사람은 로그인 없이 공개 정보를 볼 수 있다. 소유자는 링크를 해제해 이후 조회를 막을 수 있다. 요청 제한은 기존 구현과 같은 단일 JVM 메모리의 1분 고정 창이다.
