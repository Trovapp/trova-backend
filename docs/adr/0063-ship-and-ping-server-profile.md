# 0063 쉽앤핑 앱 프로필과 서버 자원·요청 시간

- 날짜 2026-11-29
- 상태 확정
- 이슈 #567

[ADR 0060](0060-ship-and-ping.md)의 서버 요청 배치와 기능 지도를 보완한다. 앱의 구성과 분당 자원 사용량을 요청 지연과 함께 볼 수 있도록 기존 수집 주소와 서버 키를 재사용한다.

## 프로필 등록

서버가 준비되면 같은 수집 주소의 `POST /v1/profile`에 전체 프로필을 보낸다. 프로필에는 코드나 운영 문서에서 확인한 표시값만 넣는다. 호스팅·요금제·할당 사양처럼 확인할 수 없는 값은 생략한다. 수집 주소, 인증 정보, 사용자 식별자는 프로필에 포함하지 않는다.

전송 워커는 프로필 JSON과 수집 주소를 기존 서버 키로 HMAC 처리한다. 2xx 응답을 받은 뒤에만 서비스 계정의 `~/.trova/shipandping-profile`에 지문을 원자적으로 저장한다. 같은 지문으로 재시작하면 등록을 생략하고, 프로필이 바뀌면 전체를 다시 전송한다. 실패한 등록은 다음 분에 재시도한다. 홈에 쓸 수 없는 환경에서는 성공한 지문을 해당 프로세스에서만 기억한다.

## 유휴 분의 자원 기록

서버 시계가 1분마다 기존 전송 워커를 깨운다. 워커는 `sp-1` 배치 최상위의 `resources`에 JVM·Micrometer에서 읽은 CPU, 메모리, 구간 GC 정지 시간, Tomcat 스레드 수, Hikari 연결 수를 숫자로 보낸다. CPU steal 비율은 같은 구간의 steal 시간 증가분을 전체 CPU 시간 증가분으로 나눈 값이다. 요청이 없는 분에도 `records: []`를 보내고, 측정할 값이 없으면 `resources: {}`를 보낸다. 64KiB를 넘어 배치를 나누면 자원 표본은 한 묶음에만 싣는다.

## 요청 시간과 종료

`queue_ms`는 수신부터 MVC 핸들러 진입까지, `duration_ms`는 같은 수신부터 종료 관측까지다. 기본 수신 시각은 Tomcat Coyote의 요청 시작 시각이다. `SHIP_AND_PING_TRUST_LOOPBACK_PROXY`는 기본으로 꺼져 있다. 켜려면 **Tomcat으로 전달하는 모든 경로에서 Caddy가 외부 입력의 `X-Request-Start`를 수신 시각으로 덮어써야 한다.** 실제 소켓 피어가 루프백일 때만 헤더를 검사한다. 형식이 잘못됐거나 미래 또는 10분을 초과한 시각이면 Tomcat 시각을 쓴다. 수신 시각이 없으면 대기를 생략하고 핸들러 시간만 기록한다.

응답 설정을 알 수 없으면 `timeout_ms`의 기본값은 10000이다. SSE는 ADR 0060에 따라 최초 디스패치가 반환될 때 연결 수립 결과를 한 번 기록하고 스트림 수명에는 요청 기한을 적용하지 않는다. 수립 중 일반 요청의 기본 기한이 지나도 디스패치 반환 시점의 상태와 시간을 기록한다. 이후 스트림 유지 시간, emitter 기한, 끊김은 이 요청의 결과를 바꾸지 않는다. 단일 비동기 응답은 실제 `AsyncContext` 기한을 적용하며, 명시적으로 기한이 없으면 0으로 기록한다. 완료·끊김·기한 중 먼저 관측한 결과 한 건을 보내고 기한을 지난 완료는 timeout으로 분류한다. 응답이 커밋되기 전 끊김·기한 초과의 상태는 0이다. 관측용 시계는 사용자 연결을 종료하지 않는다.

요청에 귀속할 수 있는 Hibernate·직접 JDBC 실행과 외부 호출은 `db_ms`와 `external_ms`에 각각 누적한다. 단위는 정수 밀리초이며 상한은 600000이다. Google Places는 실제 호출에서 한 번 재고 같은 호출 로그와 내부 작업 로그는 제외한다. 관측값이 없으면 필드를 생략하며 대상·주소·쿼리·본문을 보내지 않는다.
