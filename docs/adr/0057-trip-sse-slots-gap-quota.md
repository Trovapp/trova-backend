# 0057 여행 변경 SSE는 오래된 연결을 교체하고 빈 시간 추천은 검색별로 차감한다

2026-11-25 · 확정 · 이슈 #545 · 관련 ADR 0036, 0054, 0056

화면을 빠르게 다시 열 때 사용자당 연결 3개 제한이 새 연결을 거절했다. 같은 사용자가 상한에 도달하면 단일 JVM의 등록 순서상 가장 오래된 연결을 제거하고 새 연결을 받는다. 전체 256개 제한은 유지하되 사용자 슬롯의 교체는 전체 수를 늘리지 않으므로 허용한다. 다른 사용자 연결은 밀어내지 않는다. 권한·인증 확인은 교체 전에 수행한다.

완료·오류·타임아웃 callback과 송신기의 IOException·정상 종료에서 close가 슬롯을 정확히 한 번 즉시 반환한다. servlet 송신이나 emitter 완료가 지연되어도 반환은 기다리지 않는다. TCP 연결 단절이 서버에 아직 알려지지 않은 경우에는 다음 쓰기/heartbeat에서 감지하므로 물리적 단절 즉시 감지를 보장하지 않는다. 재접속 교체 정책으로 그 사이의 사용자 슬롯 거절을 막는다. 활성 슬롯은 `trova.trip-events.active` gauge, 교체는 `trova.trip-events.replaced` counter로 기록하며 사용자·여행 ID 라벨을 넣지 않는다.

등록·슬롯 제거의 짧은 모니터 안에는 JDBC·servlet 송신·emitter 완료 같은 블로킹 I/O를 넣지 않는다. 교체 대상의 종료 요청도 등록 모니터 밖에서 수행한다. ADR 0056의 대화 스트림은 처리 수명까지 점유하는 별도 정책이며 여기서는 바꾸지 않는다.

빈 시간 추천은 컨트롤러 요청당 차감 대신 `GapRecommendationService`의 Google Places 검색 직전에 사용자 일일 장소 한도를 한 번 차감한다. 검색하지 않는 빈 일정·시간/좌표 누락·없는 일차는 차감하지 않는다. 빈 시간이 여러 개면 검색마다 차감하며, 실패한 외부 검색 시도도 차감한다. 한도 초과 예외는 검색 실패 폴백 바깥에서 발생시켜 기존 429 메시지를 유지한다. ADR 0036의 사용자 ID 조회 최적화는 유지하며 차감 위치 설명만 이 결정으로 대체한다.

짧은 TTL 결과 캐시는 이번 변경에 추가하지 않는다. 추천은 여행 버전 외에도 장소 카탈로그·개인화·사용자의 저장 장소 분류에 영향을 받으므로, 결과 동일성을 보장하는 별도 무효화 설계가 필요하다.
