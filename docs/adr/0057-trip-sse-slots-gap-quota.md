# 0057 여행 변경 SSE는 오래된 연결을 교체하고 빈 시간 추천은 검색별로 차감한다

2026-11-25 · 확정 · 이슈 #545 · 관련 ADR 0036, 0054, 0056

화면을 빠르게 다시 열 때 사용자당 연결 3개 제한이 새 연결을 거절했다. 같은 사용자가 상한에 도달하면 단일 JVM의 등록 순서상 가장 오래된 종료 중이 아닌 연결을 제거하고 새 연결을 받는다. 교체 대상은 원자적으로 예약해 종료 이벤트를 기다리거나 close가 시작된 연결을 다시 교체하지 않는다. 교체된 연결에는 기존 FIFO writer로 `event: replaced`, `data: {"reason":"connection_limit"}`를 보낸 뒤 닫는다. 앱은 이 이벤트를 받으면 자동 재접속을 멈추고 "다른 기기에서 열림" 상태를 표시해야 한다(앱 구현은 별도 작업). 네트워크가 이미 막힌 경우 프레임 수신은 보장하지 않는다. 전체 256개 제한은 유지하되 사용자 슬롯의 교체는 전체 수를 늘리지 않으므로 허용한다. 다른 사용자 연결은 밀어내지 않는다. 권한·인증 확인은 교체 전에 수행한다.

완료·오류·타임아웃 callback과 송신기의 IOException·정상 종료에서 close가 슬롯을 정확히 한 번 즉시 반환한다. servlet 송신이나 emitter 완료가 지연되어도 반환은 기다리지 않는다. TCP 연결 단절이 서버에 아직 알려지지 않은 경우에는 다음 쓰기/heartbeat에서 감지하므로 물리적 단절 즉시 감지를 보장하지 않는다. 재접속 교체 정책으로 그 사이의 사용자 슬롯 거절을 막는다. 반환 후에도 남은 writer가 상한 밖에서 무한히 쌓이지 않도록, 등록부터 emitter 완료의 finally까지 모든 writer를 별도로 센다. 활성·종료 중 writer를 합친 상한은 전체 슬롯 한도의 두 배(기본 512개)이며 도달 시 교체 요청도 429로 거절한다. 따라서 전체 256개가 찼어도 정리 여유가 있을 때만 교체할 수 있다. 실행기 거절도 슬롯과 writer 예약을 모두 반환한다. writer 수는 `trova.trip-events.writers` gauge, 활성 슬롯은 `trova.trip-events.active` gauge, 교체는 `trova.trip-events.replaced` counter로 기록하며 사용자·여행 ID 라벨을 넣지 않는다.

등록·슬롯 제거의 짧은 모니터 안에는 JDBC·servlet 송신·emitter 완료 같은 블로킹 I/O를 넣지 않는다. 교체 대상의 종료 요청도 등록 모니터 밖에서 수행한다. ADR 0056의 대화 스트림은 처리 수명까지 점유하는 별도 정책이며 여기서는 바꾸지 않는다.

빈 시간 추천은 컨트롤러 요청당 차감 대신 `GapRecommendationService`의 Google Places 검색 직전에 사용자 일일 장소 한도를 한 번 차감한다. 검색하지 않는 빈 일정·시간/좌표 누락·없는 일차는 차감하지 않는다. 빈 시간이 여러 개면 검색마다 차감하며, 실패한 외부 검색 시도도 차감한다. 한도 초과 예외는 검색 실패 폴백 바깥에서 발생시켜 기존 429 메시지를 유지한다. 빈 시간이 두 개이고 남은 한도가 하나면 첫 검색만 수행하고 두 번째 직전 429로 전체 요청을 끝낸다(부분 응답 없음). 대화 도구는 `findGap`으로 지정한 beforePlaceId의 빈 시간만 검색하며, 한도 소진 메시지를 일반 조회 실패와 구분해 반환한다. 남의 여행·없는 여행/일차의 403/404는 차감하지 않는다. ADR 0036의 사용자 ID 조회 최적화는 유지하며 차감 위치 설명만 이 결정으로 대체한다.

짧은 TTL 결과 캐시는 이번 변경에 추가하지 않는다. 추천은 여행 버전 외에도 장소 카탈로그·개인화·사용자의 저장 장소 분류에 영향을 받으므로, 결과 동일성을 보장하는 별도 무효화 설계가 필요하다.
