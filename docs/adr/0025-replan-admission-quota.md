# 0025 재구성 새 접수는 기존 장소 요청 한도에 포함하고 단일 JVM에서 직렬화한다

- 상태: 확정 · 날짜: 2026-10-31 · 관련: #270, #267 리뷰, 사용자 순차 수정 승인

## 결정
- 재구성의 새 작업 생성 시도에 DailyQuotaService의 기존 사용자별 장소 요청 한도 1회를 적용한다. 활성 작업 ID 재사용·잘못된 조건·다른 사용자 여행 요청에는 차감하지 않는다.
- 한 번의 재구성은 여러 외부 요청을 만들 수 있다. 기존 장소 API와 같은 요청 시도 단위이며 생성/큐 실패도 환급하지 않는다. 외부 API 전체 호출 수나 과금의 엄밀한 상한은 아니다.
- 같은 여행의 조회·생성·비동기 접수를 고정 버킷 잠금으로 직렬화해 동시 요청이 한 작업을 재사용하도록 한다. 한도 초과에는 기존 예외/429 응답을 쓴다.
- DB 저장의 리포지토리 트랜잭션이 끝난 뒤 작업자를 호출하는 기존 순서를 유지한다. 큐 거절 시 유령 작업 삭제도 유지한다.

## 범위
ADR 0024와 같이 단일 JVM/서비스 인스턴스 범위다. 다른 여행의 해시 버킷 충돌은 가능하다. 다중 서버의 원자적 접수나 전체 Gemini/Google 호출 예산은 별도 설계가 필요하며 이번 수정으로 보장하지 않는다.
